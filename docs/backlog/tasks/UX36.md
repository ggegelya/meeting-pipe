# UX36: Summary reading measure: centered column, honest padding, wrapping metadata

Band origin: filed 2026-07-29 (owner exploratory sweep, item 4: "the summary content is cut in width at some level... make size of the text area dynamic to the size of the panel, or make max width of the right panel fixed, or any other options"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

What the owner sees as "cut at some width" is the reading-measure cap, not a clip. `SummaryLayout.readingMeasure = 640` (`SummaryRenderedView.swift:8-10`) is a deliberate typography decision (TECH-DSN8 / UX13: ~70 characters at body size, "reads like paper"), applied to the rendered summary at :91-93:

- `.padding(MPSpace.s5)` (20pt) is applied INSIDE the cap, so the real text column is 640 - 40 = 600pt.
- `.frame(maxWidth: .infinity, alignment: .leading)` then parks the capped block hard left, so on a wide window all remaining width is dead space on the right. The detail column itself has a min of 450 and no max (`LibraryWindow.swift:782`, `LibraryLayout.swift:25-26`), so the asymmetry grows with the window.

The same cap-then-left-park pattern repeats in `SummaryTab.swift:242/:245` and :287/:288 and in `CorrectionEditor.swift:41`. Two stray literals shadow the constant: `.frame(maxWidth: 460, ...)` at `SummaryTab.swift:421` and :435 (the BYO/preview area), which will not track any change to the shared measure.

A real horizontal-space defect hides underneath: `ActionItemRow`'s metadata band is a non-wrapping `HStack` inside the cap (`SummaryRenderedView.swift:325-338`: a 16pt spacer, owner chip, due chip, confidence chip, FEAT10 `EvidenceChips`), with no `ViewThatFits` and no wrap, so a long owner name plus several evidence chips compresses and truncates. The one hard `lineLimit(1)` in the reader is the attendee chip (:432). Prose itself wraps correctly (`.fixedSize(horizontal: false, vertical: true)`, e.g. :197, :323).

## Scope

Decision, taken as delegated: keep a reading measure. Unbounded text width is rejected on readability grounds (70-90 characters per line is the defensible measure; a 1200pt line is objectively worse to read), and a fixed max on the detail panel is rejected because it would punish the Transcript and Audio tabs that use the width. The fix is to make the measure honest and the layout symmetric:

- Apply `.padding` outside the cap (or widen the cap by the padding) so 640 is the true text measure.
- Replace the left-park with a centered placement (`.frame(maxWidth: .infinity, alignment: .top)` centering the measured block), so a wide window frames the column like a page rather than abandoning the right half. Apply the same change at the `SummaryTab` and `CorrectionEditor` sites so reader and editor stay aligned (the stated reason the shared constant exists).
- Fold the two 460 literals into a named constant in `SummaryLayout` (a second, narrower measure for preview panes) so they track future changes.
- Make the action metadata band wrap: `ViewThatFits` with a two-line fallback, or a trailing-truncation policy that keeps evidence chips visible; pick whichever reads better with real data, record the pick.
- Optional, owner-eyeball-gated: nudge the measure from 640 toward ~680 if the centered layout reads too narrow on the owner's screen. Not a spec requirement.

## Explicitly not in scope

A user-facing width setting. Changing the detail column's min/ideal (`LibraryLayout`). Transcript tab layout. The red scroll indicator in the owner's screenshot (stock scroller styling, not a defect).

## Acceptance

The measure constant is applied at every summary surface through `SummaryLayout` with no shadowing literals (grep for `maxWidth: 4` and `maxWidth: 6` literals in the summary surfaces comes back empty).

A layout-level test or presentation seam pins that the metadata band renders all chips at `detailMinWidth` (450pt column) without truncating the evidence chips (if not testable headlessly, the acceptance is the owner eyeball case below plus a code-review assertion that `ViewThatFits`/wrap is in place).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770). Repo dash guard green.

Owner eyeball: open the meeting from the 2026-07-27 screenshot at full-screen width; the summary column sits centered with even margins, nothing is parked against the left edge, and an action row with owner + due + confidence + evidence chips shows all of them at the narrowest detail width.
