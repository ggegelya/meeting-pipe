# T11: Swift tests leak temp directories: one test leaves a 230 MB WAV per run, eleven files never clean up, and the temp-dir helper is copied 32 times

Band origin: filed 2026-10-25 from the 2026-10-25 code-quality audit band ([code-quality audit](../../audits/2026-10-25-code-quality-audit.md) TS1, TS2). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The finder rated TS1 high; the independent skeptic confirmed every number and downgraded it to medium, because the cost is disk on the dev Mac only and CI runners are ephemeral. Filed at P2 on that medium.

**The 230 MB file.** `WaveformPeaksTests.test_compute_renders_60_minute_synth_in_under_two_seconds` calls the file's private `tempDir()` (`"mp-wf-\(UUID().uuidString)"`, no teardown) and `writeStereoWAV(at:sampleRate: 16_000, seconds: 60 * 60)`. That is 57,600,000 frames at 4 bytes, so `dataSize` is 230,400,000 and the file is 230,400,044 bytes. `writeStereoWAV` builds the whole file in one `Data` in memory, appending two 2-byte arrays per frame from `sampleFn`, then `data.write(to:)`; the sample function is the constant `{ _, _ in (0.1, 0.1) }`. Nothing ever deletes it.

**Measured on the dev Mac on 2026-10-25** (read-only, `$TMPDIR` is `/var/folders/2t/.../T/`): 3,516 `mp-*` directories totalling 5,645,492 KiB. Of those, 135 are `mp-wf-*` totalling 5,627,000 KiB (5.37 GiB), and 25 of them hold a `long.wav` of 220 MiB, which is essentially the whole footprint. The oldest `mp-*` directory is dated 2026-07-13 and the oldest `mp-wf-*` 2026-08-22, the newest of both 2026-10-24, so nothing on this Mac is purging them. By prefix the largest counts are `mp-meetingstore` 1,168, `mp-tests` 835, `mp-workflows` 610, `mp-corrections` 168 and `mp-migrator` 162.

**Files with no cleanup at all.** Re-counted at filing: 14 test files under `daemon/Tests` reference `NSTemporaryDirectory()` or `FileManager.default.temporaryDirectory` and contain no `removeItem`, `trashItem` or `addTeardownBlock`. Three of them create nothing: `SessionWatchersTests` and `CoordinatorWiringFenceTests` pass the temp root itself as a read-only `directory:`, and `NotionDatabaseListTests.test_refresh_is_blocked_under_regulated_mode` names a cache file that the regulated path never writes. The other 11 create a directory per call and never remove it: `MCPStatusTests`, `CorrectionStoreTests`, `WorkflowMigratorTests`, `CoordinatorMicGateIntegrationTests`, `WorkflowStoreTests`, `ConfigStoreTests`, `MeetingDragItemTests`, `SecretsStoreTests`, `OnboardingWorkflowPresetTests`, `WaveformPeaksTests` and `MeetingSummaryTests`. The three `"mp-tests-"` files (`MCPStatusTests`, `ConfigStoreTests`, `CoordinatorMicGateIntegrationTests`) account for the 835 `mp-tests` dirs.

**A file with some cleanup can still leak.** `MeetingStoreTests` calls `try tempDir()` 41 times and `removeItem` 4 times, which is how `mp-meetingstore` reached 1,168 (1,012 of them dated 2026-10-24 alone). So "files without cleanup" is a lower bound; the real gap is per call site.

**The helper is copied, not shared.** Re-counted at filing: 32 private helper functions create a fresh temp directory, 20 of them under the names `tempDir()`, `makeTempDir()` or `temporaryDirectory()`, the rest URL-returning or scratch-log variants (`makeTempConfigURL`, `makeTempSecretsURL`, `makeTempURL`, `makeTempWav`, `withScratchLogs`, `makeFingerprintDir`, `makePublishDir`, ...). On top of those, 24 `setUpWithError` methods and about 57 test bodies create one inline. Only 9 sites register `addTeardownBlock { try? FileManager.default.removeItem(at: dir) }` (for example `SummaryStalenessTests.tempDir`, `ClarifyTests.makeTempDir`, `RecordingPostProcessorTests.makeTempDir`), which is already the right shape; it just was never shared.

Re-checked at filing: the audit's "copied 25 times" is an undercount (32 helpers plus 24 setUp copies), and of the skeptic's 14 files without cleanup, 11 actually leak.

## Scope

1. **One scratch-dir helper.** `ScratchDir.make(prefix:teardown:)` (name is the pickup session's) in the shared test-support folder `daemon/Tests/TestSupport/` that T13 introduces; whichever of T11 and T13 lands first creates the SwiftPM target and both test targets depend on it. It creates `NSTemporaryDirectory()/<prefix>-<UUID>` and registers its removal through the passed hook, so a call site reads `try ScratchDir.make(prefix: "mp-wf", teardown: addTeardownBlock)`. The hook parameter is deliberate: a plain `swift build` (which `rebuild.sh` and `ci-local.sh daemon` run) compiles every regular target, and Command Line Tools have no XCTest, so the shared target must not `import XCTest`.
2. **Replace every copy.** The 32 helpers, the 24 `setUpWithError` creations (and their matching `tearDown` removals) and the inline test-body sites move to the helper. Prefixes stay as they are so a leftover is still attributable.
3. **The long WAV.** `writeStereoWAV` writes the header and then the data through a `FileHandle` in fixed chunks from one preallocated buffer, instead of building 230 MB in memory one frame at a time. The test keeps its 60-minute length and its budget; only the writer and the cleanup change.
4. **A fence.** A grep step in `scripts/ci-local.sh daemon` fails on `NSTemporaryDirectory()` or `.temporaryDirectory` under `daemon/Tests` outside `TestSupport/`, with an allowlist in the script, one line per entry with a reason, for the read-only uses (the two `directory:` call sites above). The Notion test moves to the helper rather than the allowlist.

## Explicitly not / out of scope

- Deleting the 3,516 directories already leaked. Nothing in the repo deletes outside what it created; the owner can remove `"$TMPDIR"mp-*` by hand, and the commit body says so with the measured size.
- Swift test doubles, `settle()` helpers and `try!` initialisers: T13, which shares the support folder.
- Swift tests appending to the real `pipeline.log` through a Python child: T9, a different leak with a different fix.
- Test seams compiled into release builds: HYG17.
- Python tests: they use pytest's `tmp_path`, which pytest prunes, and are fine.

## Acceptance

- `ls -d "$TMPDIR"mp-* | wc -l` before and after a full `cd daemon && swift test` differs by 0 (both numbers in the commit body), and no `long.wav` remains under any `mp-wf-*`.
- `grep -rnE 'func (make)?[tT]emp(Dir|orary)' daemon/Tests` finds only the support folder.
- The fence fails on a scratch `NSTemporaryDirectory()` added to a test file (tried and reverted, said in the commit body).
- New tests for the helper: the directory exists during the test and is gone after its teardown hook runs, including when the test body throws. 2 new tests.
- `bash scripts/ci-local.sh daemon` and `bash scripts/ci-local.sh fences` green; `swift build -c release` still green with no `import XCTest` under `daemon/Tests/TestSupport/`.
