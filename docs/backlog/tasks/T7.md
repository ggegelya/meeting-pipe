# T7: the END10 wiring fence skips instead of failing when Coordinator.start() moves, skips pass CI silently, and the watchers have no headless seam

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([architecture review](../../audits/2026-10-24-architecture-review.md) D3, [go-live assessment](../../audits/2026-10-21-go-live-assessment.md) QG-4 and SA-8, [harness audit](../../audits/2026-10-24-ai-harness-audit.md) #3). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

[`CoordinatorWiringFenceTests`](../../../daemon/Tests/MeetingPipeTests/CoordinatorWiringFenceTests.swift) is the fence [END10](./END10.md) added after END9 shipped with 28 green tests and a teardown watcher nothing started. Its helper `coordinatorStartBody()` searches `Coordinator.swift` for the literal `"\n    func start() {"` and otherwise does `throw XCTSkip("Coordinator.start() was renamed; this fence needs updating with it")`. A rename, a move into an extension (which changes the indent), or `func start() async` turns all three source assertions into skips.

A skip is a pass everywhere this repo looks. XCTest reports it as passed, `swift test` exits 0, and `scripts/ci-local.sh daemon` runs plain `swift test` with no skip check, so CI goes green with the fence off. It is not the only silent skip: `FailureProcessTests` throws `XCTSkip` when `pipeline/.venv/bin/python3` is missing, and the `daemon` job in `.github/workflows/ci.yml` never syncs the pipeline venv, so that cross-process test has never run in CI. On 2026-10-24 there are 13 `XCTSkip` sites under `daemon/Tests`.

Why it is a source fence at all, from its own doc comment: the real `Coordinator` "builds a status-bar item, four windows and the AX and HAL buses, none of which stands up headless in a unit test" (go-live SA-8). The same reason produced the wider pattern: the review counted 26 daemon test files that assert on Swift source text, and a 2026-10-24 grep for test files reading `Sources/` text finds 28 (for example `PreferencesSurfaceTests` asserting `view.contains("ScrollViewReader { proxy in")`). Some are deliberate fences with no seam behind them (`TutorialFenceTests`: nothing may start the tour from a launch path); others pin how a view is written rather than what it does.

The wiring under test is small. `Coordinator.start()` calls `discoveryWatcher.start()` and `callTeardown.start()` inline among delegate assignments and hotkey registration, and `configRefresh.start()` further down. Those starts are what END10 proved can be forgotten.

## Scope

1. **Now.** In `coordinatorStartBody()`, replace the `XCTSkip` with `XCTFail` plus a thrown error carrying the same message, so a moved `start()` fails the suite.
2. **A skip gate.** `ci-local.sh daemon` captures the `swift test` output and fails when a test reports skipped and its name is not on an allowlist kept in the script, one line per entry with its reason (the `PlaybackChannelModeTests` buffer-allocation guards; the three ffmpeg guards, allowed only when `command -v ffmpeg` fails, which it never does in CI; `FailureProcessTests` while the daemon job has no pipeline venv). `WindowRecognizerFixtureTests`' "fixture not bundled" skip is deliberately not on the list: a missing fixture is a packaging defect, not an environment. Either sync the venv in the daemon job or allowlist `FailureProcessTests` with that reason; say which in the commit.
3. **A headless wiring seam.** Move the long-lived watchers `Coordinator.start()` starts behind one value (working name `SessionWatchers`) holding them as a small `Startable` protocol (`func start()`), with `startAll()`. `Coordinator.start()` calls `watchers.startAll()`. Behaviour tests build `SessionWatchers` from fakes and assert every member started exactly once, and that the production member list contains the call-teardown, discovery and config-refresh watchers. The source fence shrinks to one assertion (`watchers.startAll()` inside `Coordinator.start()`), and its doc says why that one line is still a source fence.
4. **Label what stays.** Each remaining source-text test file gets a one-line doc comment saying which seam is missing and what it fences, so a reader can tell a deliberate fence from implementation pinning. Converting those files is left to whoever next touches them.

## Explicitly not / out of scope

- A headless `Coordinator`. The status item, windows, and AX and HAL buses stay where they are; the seam is the watcher set only.
- Converting the 28 source-text files. Item 4 labels them; conversion happens on touch.
- Visual or rendered UI tests ([T2](./T2.md)).
- The `/tech-task` wiring rule (a test that fails if production never calls a new component): HYG14. T7 gives that rule a seam to point at for watchers.
- Moving watcher ownership into `MeetingSessionController` or shrinking `SessionHost`: ARCH7.
- The END replay harness: T8.

## Acceptance

- A scratch rename of `func start()` makes `CoordinatorWiringFenceTests` fail, not skip (tried and reverted; say so in the commit body).
- New tests: `SessionWatchers.startAll()` starts each fake once; a second `startAll()` behaves as the shipped watchers do on a second `start()` (state which); the production member list contains the three watchers named above.
- A temporary test that throws `XCTSkip` with an unlisted name makes `bash scripts/ci-local.sh daemon` exit non-zero (tried and reverted); every allowlist entry carries a reason.
- `cd daemon && swift build` and `swift test` green, with the number of new tests in the commit body; `bash scripts/ci-local.sh daemon` green.
