# AI12: Ask context-size control: let a question buy a wider pack, honestly

Band origin: filed 2026-07-31 at the owner's request, during the AI11 owner walkthrough and immediately after watching a 100K-token pack answer well: "also it may be useful to have a toggle or something picker, that will allow to ask with bigger context window (with all necessary wornings). you seen it works fine when we tried." Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

`mp ask` packs its retrieved context to `DEFAULT_CONTEXT_TOKENS` (4000) unless `--context-tokens` overrides it (`ask.py`, `answer_question`). The daemon never passes that flag, so in the app the budget is a constant and there is no way to ask a question that deserves a wider read.

The width genuinely changes the answer, and this is measured rather than assumed. Both runs below are the owner's, on 2026-07-31, from `~/Library/Logs/MeetingPipe/pipeline_events.jsonl`:

- default: `ask_answered  context_tokens: 4000  packed_tokens: 3845  packed_chars: 15380  retrieved_stems: 26`
- wide: `ask_answered  context_tokens: 100000  packed_tokens: 99942  packed_chars: 398729  retrieved_stems: 117`

The wide run read 117 meetings against 26 and returned a visibly fuller answer (seven cited meetings against four, and it surfaced budget discussions the narrow run missed entirely). So the value is real and the path already works end to end. **This is not an AI11 re-open.** AI11 built the budget, the script-aware sizing, and the clamp; what is missing is only the dial and the two sentences that make turning it honest.

## The two constraints, which are the whole difficulty

**On a local backend the tier ceiling is a hard cap, not a default.** `clamp_context_tokens` holds the request at `resource_guard.tier_for(ram).context_token_ceiling` for `local` / `apple_intelligence` / `auto` (8000 on a 32 GB Mac, 4000 at 16 GB, 2000 at 8 GB), and that ceiling exists because exceeding it took this Mac down: the 2026-07-29 `mp ask` incident ended in a hard reboot, and AI2 measured the 14B OOM-crashing and swap-storming at 16K. The control must not offer a value above the ceiling on a local backend, and must not present the clamp as something the user can override. A wider pack is a thing cloud can sell and local cannot.

**On a cloud backend there is no memory risk and a real money one.** Nothing clamps cloud (`test_a_cloud_answer_is_not_clamped_by_this_macs_ram` pins that deliberately), so the honest warning here is about spend, not safety, and it should say the multiple rather than a token count: the wide run above sent roughly 26x the input of the default one. "With all necessary warnings" was the owner's own framing and the warning is the deliverable as much as the picker is.

## Scope

A preset control on the Ask surface, next to the input `AskPane` already owns (UX38), plus the launcher argument behind it.

- **Presets, not a token field.** The owner does not read code and "100000 tokens" names nothing. Three positions in plain language, of the shape `SpeakerSeparation` uses for DIAR3 (a pure position table mapping a named position to a value, with a shared clamp), so the same idiom covers this. Suggested values, the implementer's call to refine: a default that is today's 4000, a middle position, and a wide one that only a cloud backend can reach.
- **The pure decision is what to unit-test:** given a backend and a machine's RAM tier, which positions are offered, which is selected, and what the sublabel says. That belongs on its own type next to `resource_guard`'s Swift mirror `LocalModelTier`, not inline in the view.
- **The seam to the engine already exists.** `PipelineLauncher.ask` composes the `mp ask` invocation; it grows one argument. `AskModel` (root-owned, UX37) holds the selection so a rail switch cannot lose it, exactly as it holds the question.
- **A position above the local ceiling is not offered, and says why** rather than being silently rounded down or greyed with no reason (the UX30 rule: a disabled row states its cause). The `LOCAL16` refusal copy is the register to match.
- **The cost line is shown before the ask, not after it.** A warning that arrives with the bill is not a warning.

## Explicitly not / out of scope

**Do not loosen `clamp_context_tokens`.** It is the guard, and this task consumes it rather than negotiating with it. If a position would exceed the ceiling on local, the position is not offered; the clamp stays the last line of defence and keeps its warning.

**Not a per-question token meter or a spend tracker.** The honest multiple in the sublabel is the scope; counting cumulative spend is a different task nobody has asked for.

**Not retrieval tuning.** `k`, the chunker, and the script-aware rate are AI11's and are not in question here; this task only moves the budget those already respect.

**Not durable Ask history.** Raised by the owner in the same conversation on 2026-07-31 and withdrawn in it ("okay for ux38, no history then for now"). UX38's "Decided at pickup" section already records history as session-only with the durable store one `SavedSearchStore` away if it is ever wanted; leave it there.

**Not a Preferences setting.** The width is a property of the question being asked, not of the app, so it belongs beside the input where the question is written.

## Acceptance

Pipeline: no change is expected in `ask.py`, and `test_ask.py`'s existing clamp coverage must stay green untouched. If the implementation finds it needs a change there, that is a signal to re-read the constraints above before making it.

Swift: `AskContextWidth` tests (new) pin the pure table: on a cloud backend every position is offered; on a local backend positions above the machine's tier ceiling are absent with a stated reason rather than silently clamped; the ceiling used matches `LocalModelTier` for 8, 16 and 32 GB so the Swift and Python tiers cannot drift; the default position is today's 4000 so an owner who never touches the control sees no change. `PipelineLauncher` tests pin that the selected width reaches the `mp ask` argv, and that the default position passes what the CLI would have defaulted to anyway.

`cd daemon && swift build` and `swift test` green. `cd pipeline && uv run --extra dev ruff check src tests`, `pyright`, and `pytest -q` green. `python3 scripts/truth_fences.py both` green. No em-dashes in changed lines.

An `ask_answered` event for a widened question records the chosen `context_tokens`, so the log can answer afterwards which width a given answer was bought with (the field already exists; this is a check that the plumbing reaches it, not a new field).

## Decided at pickup (2026-08-04)

The calls this spec left to the implementer, recorded here so the walkthrough below is read against what actually shipped. `ask.py` is untouched, as the spec predicted; the whole task is Swift.

- **The three positions are Normal 4000, Wider 8000, Widest 100000.** The middle is the 32 GB tier ceiling *exactly*, not a round number: it is the widest a local answer on this Mac is allowed to be, so switching to a local backend leaves the owner a real second position rather than a control with nothing in it, and the tier rule is something the walkthrough can see rather than a claim in a comment. The widest is above every tier in the table (16000 at 48 GB is the highest there is), so "only a cloud backend can reach it" holds by construction instead of by a rule somebody has to keep true.
- **The resting position is always offered, including where the tier ceiling is below it.** At 8 GB the ceiling is 2000 and at 16 GB it is 4000, so a strict reading would withhold even Normal and leave an empty control. It stays, because it is the floor of the control and exactly what `mp ask` passes with no flag at all: those machines are clamped today and still are. Only the *wider* positions are withheld, which is what the constraint is actually about.
- **Regulated mode caps a cloud backend too.** Not in the spec, and load-bearing: `config.effective_backend` forces the local path whenever zero-egress holds, so keying on `summarization.backend` alone would have offered the widest position to a machine about to answer locally, then let the clamp round it down where nobody sees it. That is precisely the shape this task exists to remove. Its refusal names regulated mode and offers no escape hatch, since under it every backend is clamped and "switch to a cloud backend" would point at a door that opens onto a wall (`ReSummarizeMenu.offersWorkflowChange`, same rule).
- **A backend id this build cannot resolve is capped.** Python errs the other way (an unknown backend is uncapped there), which is right for its job: it must not refuse to answer. Here the cost of guessing wrong is a wide local pack, so the guess goes the safe way.
- **`--context-tokens` is passed on every run, including at Normal**, where it is exactly `DEFAULT_CONTEXT_TOKENS`. One code path rather than two, and the `ask_answered` event then records the width *every* answer was bought with rather than only the widened ones. The daemon's own `ask_requested` carries it too.
- **The control is drawn only when there is more than one position to choose.** On a Mac whose ceiling leaves one, the reason line is the whole truth and a one-segment picker would be a control that does nothing (UX43's rule). It is `SettingsSegmented`, the shared primitive, in DIAR3's named-position idiom, rather than a parallel one-off.
- **The selection is re-resolved when the Ask surface appears, not observed live.** `LibraryWindowModel` does not republish on a config change, so changing the backend in Preferences while the Ask rail is open does not repaint it; returning to Ask rebuilds the view (the rail switch that made `AskModel` necessary in the first place) and that is where a width the machine can no longer take falls back to Normal. Step 4 below already tells the owner to return to Ask. `clamp_context_tokens` covers the window in between, which is the one thing it must keep doing.
- **`LocalModelTier.gb` went from private to internal** so the refusal quotes this Mac's memory in exactly the spelling the Preferences preset annotations use. Two formatters for one number is drift a reader would report as a bug.
