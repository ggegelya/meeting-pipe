# UX106: Every recording start shows nothing until the recorder is up, because there is no Starting state, and a press that meets a start in flight or a stop is dropped silently

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source findings: P001, P004, P013, P007, P008 and P051 in the [responsiveness audit](../../audits/2026-11-13-responsiveness-audit.md) (ranked fixes 2 and 6, and "The Record click" section), plus D077 in the [recording reliability audit](../../audits/2026-11-13-recording-reliability-audit.md) (evidence: [D077](../../audits/2026-11-13-recording-reliability-evidence.md)). This is the owner's own complaint of 2026-11-13: the Record click takes about a second to show anything. Re-verified in code at HEAD `3a2da4fc` on 2026-11-13.

**Field numbers** (work laptop pack, 74 recordings, 2026-09-29 to 2026-11-13). No event marks the click itself, so every figure starts at the recorder.log `start:` line and understates the wait. The 8 click-timed `record_attached` starts took 102 to 383 ms to `recording_started`; the 12 explicit idle starts (hotkey, menu, Start late, generic manual) show nothing on screen for 90 to 606 ms; the recorder alone took more than 0.5 s in 9 of 74 starts and more than 1 s in 6. In the newest build (since 2026-11-12, n=6) `start:` to `recording_started` was 104 to 137 ms, and 3,270 ms once (`20261112-163040`, the capture file freeze [PERF28](./PERF28.md) owns). A whole stop (`state_change` recording to stopping, to stopping to idle) has median 3.6 s, p90 12.8 s, max 53.8 s; 12 of 74 stops took over 10 s, among them `20261015-144207` (46.6 s), `20261021-120034` (52.8 s) and `20261022-103101` (53.8 s).

**No visible state between click and recorder.** `MeetingSessionController.beginRecording` checks the in-flight guard, the mic permission, dry run, resolves the workflow and capture mode, then sets `recordingStartInFlight = true` and starts a `Task`. Only after `try await self.coordinator.audioRecorder.start(...)` returns does it call `stateMachine.setRecording`, `statusUI.setRecording` and `hud.present(...)`, and `RecordingHUDWindow.present` then fades in from `panel.alphaValue = 0`. `SessionHost`'s status protocol has `setIdle`, `setPrompting`, `setRecording`, `setStopping` and `setSuppressed`, and no starting setter. From idle (hotkey, menu row, Library toolbar, Start late, URL scheme) there is no prompt to fade, so nothing changes at all until the recorder is up (P004, P013).

**From a prompt, Record looks like Skip (P001, P007).** `MeetingPromptWindow.handleRecord`, `handleSkip`, `handleAlways` and `handleRecordBYO` each call `delegate?.meetingPrompt(...)` first and `dismiss()` second, so the fade waits for the delegate's synchronous work and is the same fade for every answer. PERF15 and PERF24 shortened that synchronous work at HEAD; the order and the identical fade remain.

**A second press is dropped.** During a start: `toggleManual` from `.idle` reaches `startManual`, then `beginRecording`, which returns at `guard !recordingStartInFlight` with only `Log.writeLine("daemon", "beginRecording ignored: a start is already in flight")`. During a stop: `toggleManual`'s `case .stopping:` is a bare `break` with the comment "Mid-flush; a new start would race the await." (P008, P051).

Correction at filing (D077's "Record is ignored without feedback"): `recordAttached` is not silent in the log, since it refuses outside `.idle` with a `record_attached_ignored` event; what it lacks is any on-screen answer. The rest of D077 holds: `.stopping` has no exit but the stop task's own continuation into `resetAfterStop`; `StopStallWatchdog` (`defaultCeilingSeconds = 90`) logs and notifies but changes no state; `AppState.isAcceptingPrompts` is true only in `.idle`, so discovery does not prompt during a stop. D077's larger direction, a background finalizer that returns the session to idle at once, is not this task.

**Why Stop during Starting is the trap.** Per F045 (now [END20](./END20.md), filed in this band), the REC7 latch `endObservedDuringStart` only catches an end seen from `.prompting`; `forceStop` from `.idle` is a no-op; and a start from `.prompting` still commits the recording. A Starting UI with a live Stop button that does nothing would ship a new lie.

Related: [END20](./END20.md) (the correctness half: one in-flight latch for every origin and the first-reading rule; P1), [UX79](./UX79.md) (partial, the Stopping menu and its `setStopping` fence), [OBS5](./OBS5.md), [OBS7](./OBS7.md) (filed in this band, the `ui_action` and `ui_feedback` events), [PERF28](./PERF28.md) (filed in this band, the capture-file freeze), [PERF15](./PERF15.md) (done), [HYG10](./HYG10.md); REC7 is archived in [q6-final.md](../q6-final.md).

## Scope

1. **A Starting state, set synchronously.** In `beginRecording`, at the point where `recordingStartInFlight = true` is set today and before the `Task`, call a new `statusUI.setStarting(source:)` (title and icon, a header row reading Starting, `libraryModel.status` showing Starting) and `hud.presentStarting(source:)`, a HUD with no timer and no level meter that appears without the 180 ms fade-from-zero. Name the app-facing state so it cannot be confused with the lifecycle verdict `.starting` (for example `titleState = .startingRecording`). On success, `setRecording` and `hud.present` promote in place (the HUD keeps its panel); in the existing `catch`, revert with `setIdle` and dismiss the starting HUD before the error notification. The `SessionHost` protocol and `FakeSessionHost` gain the setter.
2. **Stop during Starting is honest.** Either disable the HUD's Stop and the menu's Stop row while starting, or latch a user stop and honour it at the same point REC7 honours `endObservedDuringStart` (stop the fresh recording at once). If [END20](./END20.md) has landed its every-origin latch first, use it; otherwise disable. Never a live Stop that does nothing.
3. **Prompt acknowledgement first.** In the four prompt handlers, give the choice a visible first frame before the delegate call (Record: the button settles into a pressed, labelled Starting look and the panel holds briefly before its fade; Skip and Always: their own fade), then call the delegate. Record's first frame must differ from Skip's.
4. **Answer a press that meets Starting or Stopping.** In `beginRecording`'s in-flight guard and `toggleManual`'s `.stopping` case: log `coordinator`/`record_press_ignored` with `state` and `trigger`, and flash the status item or HUD with a short line ("Already starting", "Still saving the last recording"). A latched pending start that fires when `resetAfterStop` reaches idle is a separate, owner-approved follow-up, since it races the merge, REC23's stem ownership and END13's candidate slot.
5. In the same commit: `docs/GUIDE.md`'s recording recipes name the Starting state; the tutorial's anchors and `TutorialFenceTests` stay green (the tour must not reference a control that changed); UX79's `setStopping` fence stays as is.

## Explicitly not

- Taking capture file creation off main: [PERF28](./PERF28.md).
- Making the in-flight start a real `AppState` case that every switch handles, and the end and first-reading races: [END20](./END20.md).
- A background finalizer that frees the session during a long stop (D077's direction), and a queued start after Stopping: both need their own owner decision.
- Speeding up the recorder start itself.

## Acceptance

- Fence A from the audit, as a `MeetingSessionControllerTests` case: with a fake recorder whose `start` never resolves, `beginRecording` returns and `FakeSessionHost` has already received `setStarting` and the HUD's starting presentation, and no `setRecording`.
- Tests: a start that succeeds promotes Starting to Recording with one HUD panel; a start that throws reverts to idle and dismisses the starting HUD; a Stop pressed during Starting either is disabled or stops the recording as soon as it commits (whichever item 2 shipped), never leaves a running recording; a second `toggleManual` during a start and a `toggleManual` during `.stopping` each emit `record_press_ignored` with the right `state`; prompt Record's first frame differs from Skip's (a pure test over the prompt's choice-to-look mapping).
- `record_press_ignored` documented in `CONVENTIONS.md`'s event table; `python3 scripts/truth_fences.py` clean.
- `cd daemon && swift build` and `swift test` green, with the number of new tests in the commit body; `bash scripts/ci-local.sh` green.
