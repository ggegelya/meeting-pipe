# UX45: Publish-target configuration in-app

Band origin: filed 2026-07-29 (owner exploratory sweep, item 16: capabilities toggleable in-app but configurable only by TOML hand-edits). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task, and [owner-verification.md](../owner-verification.md) carries the gate for shipped work awaiting the owner's confirmation.

## Context

The workflow editor offers Notion, Obsidian, and Filesystem as sink checkboxes (`WorkflowsView.sinksSection`), and Notion alone is configurable in-app (token + the UX22 database picker). The rest of the sink surface, verified 2026-07-29:

- **Obsidian**: six config keys (`obsidian.vault_path`, `.folder`, `.template_path`, `.attach_audio`, `.attachments_subfolder`, `.daily_note_backlink`) have zero Swift references. A workflow can enable the Obsidian sink and it silently cannot run without a hand-edited vault path.
- **Filesystem**: `filesystem.output_dir` has no UI, and this one has teeth: NDA mode force-selects filesystem-only sinks (`Workflow.effectiveSinks`, `flags.ndaMode ? [.filesystem] : sinks`), so the privacy-critical path is the one whose destination cannot be set in-app.
- **LAN** (FEAT1, shipped): `lan.mount_path` / `lan.host` have no UI AND the sink cannot even be selected per-workflow: `WorkflowSink` (in `Workflow.swift`) had exactly three cases as of 2026-07-29, so the pipeline capability is unreachable from the editor entirely. It carries a fourth, `lan`, since this task shipped on 2026-08-03.
- **Notion privacy**: `notion.include_full_transcript` defaults to true (every transcript egresses to Notion wherever that sink runs) and has no switch; the only in-app lever that stops it is regulated mode, a much bigger hammer.
- **OpenAI model**: selecting the OpenAI backend shows an instruction to hand-edit `config.toml` for `summarization.openai_model`, in `PreferencesView+Pipeline.swift` under the `store.summarizationBackend == "openai"` branch, the literal anti-pattern the de-CLI rule names. That branch carries a **Model id** field since this task shipped, and the comment beside it names what it replaced.

## Scope

- **A "Publish targets" group in Preferences, Integrations pane** (it already owns Notion's token and DB): Obsidian (vault path picker + subfolder; `attach_audio` as a toggle; template/backlink stay TOML-only as advanced), Filesystem (output directory picker), LAN (mount path picker + host field, with the reachability caveat FEAT1 already models surfaced as a sublabel). Each target shows a quiet not-configured state that names what is missing, and the workflow editor's sink checkboxes reference it when the sink they enable is unconfigured (an inline caption, the WF9 quiet-cue idiom), so enable-but-broken can no longer be silent.
- **The LAN checkbox in the workflow editor**: add the fourth `WorkflowSink` case end to end. This touches the Swift-to-Python contract: the sink vocabulary rides the workflow into `<stem>.meta.json` and `mp.workflow.apply_overrides` resolves it, so both sides plus `test_workflow_overlay.py` move in the same commit (the sidecar rule in both CLAUDE.md files). Verify at pickup which literal the pipeline's fanout expects for the LAN publisher and match it exactly.
- **`notion.include_full_transcript` toggle** in the Notion group ("Include the full transcript on Notion pages"), sublabel naming the privacy meaning; honest default display (on, matching the config default).
- **OpenAI model field**: a text field shown when the backend picker says OpenAI, bound to `summarization.openai_model`, replacing the hand-edit instruction named in Context.
- All new bindings ride `ConfigStore`'s round-trip (unknown keys preserved; defaults via `ConfigDefaults` where a compile-time default exists).

## Explicitly not in scope

New sinks. Per-workflow overrides of target paths (workflows choose WHICH sinks; global config says WHERE; recorded so pickup does not invent per-workflow paths). Notion property mapping or `notion.default_status` (config-only stays fine; noted). Verifying vault/mount contents beyond existence (the publisher's own reachability handling stands).

## Acceptance

Daemon tests: ConfigStore round-trips each new binding with unknown-key preservation; the workflow editor persists the LAN sink case; the unconfigured-sink caption derivation is pure and table-tested (enabled+unconfigured shows, enabled+configured does not).

Pipeline tests: `test_workflow_overlay.py` covers the LAN sink literal both directions (Swift writes it, `apply_overrides` resolves it); the existing publish fanout tests cover the LAN publisher already (extend only if the vocabulary needed alignment).

`python3 scripts/truth_fences.py config` green (all keys involved are already documented in `config.example.toml`; the fence's Preferences-control direction now finds readers for each). Both suites, ruff, pyright green, with the number of tests this task adds recorded in the same commit. Repo dash guard green.

Owner eyeball: set a Filesystem output directory in Integrations; an NDA workflow's editor no longer shows an unconfigured caption; toggle "Include the full transcript" off and a republished Notion page carries the summary without the transcript body.
