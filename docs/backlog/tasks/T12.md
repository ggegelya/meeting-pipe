# T12: Pipeline suite results depend on the environment: the SIGINT test hangs 60 s and fails when the parent ignores SIGINT, the cluster tests load the real MLX model, and one module-level skip hides the SDK-free MCP tests

Band origin: filed 2026-10-25 from the 2026-10-25 code-quality audit band ([code-quality audit](../../audits/2026-10-25-code-quality-audit.md) TS3, TS4, TS5). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The audit's pipeline run gave 1,427 passed in the foreground and 1 failed plus 1 skipped in a backgrounded run on the same tree. Three tests or files depend on something outside the code under test. All three re-verified on 2026-10-25.

**1. The SIGINT test inherits an ignored SIGINT.** `test_main_dispatch.test_real_sigint_prints_no_traceback` spawns `[sys.executable, "-c", CHILD]`, where `CHILD` replaces `mp.logs_cmd.main` with a `blocking_main` that prints `READY` and runs `time.sleep(60)`, then sends `SIGINT` and waits with `proc.communicate(timeout=60)`. A non-interactive shell starts a background job (`cmd &`) with SIGINT set to `SIG_IGN`, the disposition survives `exec`, and Python does not install `default_int_handler` over an inherited ignore. Reproduced the way the finder did:

- `signal.getsignal(signal.SIGINT)` prints `<built-in function default_int_handler>` in the foreground and `1` (`SIG_IGN`) under `sh -c '<python> -c ... & wait'`, and also `1` in a grandchild spawned from that backgrounded parent, which is exactly the test's child.
- `sh -c 'uv run --extra dev pytest -q tests/test_main_dispatch.py -k real_sigint & wait'` fails with `subprocess.TimeoutExpired` in 60.24 s (wall 60.77 s); the same command in the foreground passes in 0.20 s.

So the test fails, slowly, under any parent that ignores SIGINT: a backgrounded shell, `nohup`, or an agent harness running the suite in the background. `Popen(restore_signals=True)` (the default) does not help: it restores only SIGPIPE, SIGXFZ and SIGXFSZ. A scratch probe on 2026-10-25 with `signal.signal(signal.SIGINT, signal.default_int_handler)` as the child's first statement, run under the same `& wait`, returned code 130 with stderr `["mp logs: interrupted"]` in 0.18 s.

**2. The cluster CLI tests load the real embedding model.** `test_action_clusters.test_cli_out_writes_cluster_ids` and `test_cli_text_collapses_a_cluster_to_one_line` call `mp.actions.main(["--open", "--cluster", ...])`, which reaches `action_clusters.cluster_actions(actions, threshold=...)` with no embedder, and that calls `embed_index.default_embedder()`. `default_embedder` returns `MLXEmbedder` whenever `importlib.util.find_spec("mlx_embeddings")` finds it, else `HashingEmbedder`. On the dev Mac `mlx_embeddings` is importable and `models--mlx-community--multilingual-e5-small-mlx` is in the HF cache, so the two tests took 3.65 s and 1.53 s against 0.01 s for the rest of the file; the Linux CI runner gets `HashingEmbedder` (the module docstring says as much). On a Mac with the package but a cold cache, `MLXEmbedder._ensure_loaded` would fetch the model from the network inside a test, unless the egress guard is armed. If the load fails, `cluster_actions` fails open to singletons and the tests' "same cluster" assertions fail, so the outcome depends on the machine. `test_mcp_serve.py` already pins this correctly with `monkeypatch.setattr(embed_index, "default_embedder", lambda *a, **k: embed_index.HashingEmbedder(dim=256))`.

**3. A module-level skip hides the SDK-free tests.** `test_mcp_serve.py` runs `` sdk = pytest.importorskip("mcp", reason="the optional `mcp` extra is not installed") `` at module level, after the last SDK-free test and before the only two that need the SDK (`test_every_spec_builds_a_real_sdk_tool`, `test_the_sdk_server_registers_the_five_tools_and_no_others`). A module-level skip skips the whole module at collection. The file collects 37 tests with the extra installed; with `sys.modules["mcp"] = None` it reports `1 skipped` (`SKIPPED [1] tests/test_mcp_serve.py:523`), so 35 SDK-free tests, including `test_status_works_without_the_optional_sdk` and `test_a_missing_sdk_names_the_command_that_fixes_it`, never run in exactly the environment they exist for. CI installs `--extra mcp`, so CI does not see it; any venv synced without that extra does.

Re-checked at filing: the hidden count is 35, not about 36, observed with `-rs`, where the audit had inferred it from two runs' totals.

## Scope

1. **SIGINT.** `CHILD` in `test_main_dispatch.py` sets `signal.signal(signal.SIGINT, signal.default_int_handler)` before anything else, and both the child's sleep and the parent's `communicate` timeout drop to 10 s so a regression fails fast. Production `mp.__main__` is not changed: a backgrounded `mp` that ignores Ctrl-C is the shell doing what was asked.
2. **Embedder.** The `library` fixture in `test_action_clusters.py` patches `mp.embed_index.default_embedder` to return a `HashingEmbedder`, the same pin `test_mcp_serve.py` uses. `cluster_actions` imports it inside the function body, so the patch takes effect. The CLI assertions are verbatim restatements, which `HashingEmbedder` groups at `HASHING_THRESHOLD` (`test_hashing_embedder_groups_a_verbatim_restatement` already pins that).
3. **Skip scope.** Remove the module-level `importorskip`; the two SDK tests each call `pytest.importorskip("mcp", ...)` themselves (or share a `skipif(find_spec("mcp") is None)` mark).
