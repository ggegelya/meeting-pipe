# T12: Pipeline suite results depend on the environment: the SIGINT test hangs 60 s and fails when the parent ignores SIGINT, the cluster tests load the real MLX model, and one module-level skip hides the SDK-free MCP tests

Band origin: filed 2026-10-25 from the 2026-10-25 code-quality audit band ([code-quality audit](../../audits/2026-10-25-code-quality-audit.md) TS3, TS4, TS5). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

The audit's pipeline run gave 1,427 passed in the foreground and 1 failed plus 1 skipped in a backgrounded run on the same tree. Three tests or files depend on something outside the code under test. All three re-verified on 2026-10-25.

**1. The SIGINT test inherits an ignored SIGINT.** `test_main_dispatch.test_real_sigint_prints_no_traceback` spawns `[sys.executable, "-c", CHILD]`, where `CHILD` replaces `mp.logs_cmd.main` with a `blocking_main` that prints `READY` and runs `time.sleep(60)`, then sends `SIGINT` and waits with `proc.communicate(timeout=60)`. A non-interactive shell starts a background job (`cmd &`) with SIGINT set to `SIG_IGN`, the disposition survives `exec`, and Python does not install `default_int_handler` over an inherited ignore. Reproduced the way the finder did:

- `signal.getsignal(signal.SIGINT)` prints `<built-in function default_int_handler>` in the foreground and `1` (`SIG_IGN`) under `sh -c '<python> -c ... & wait'`, and also `1` in a grandchild spawned from that backgrounded parent, which is exactly the test's child.
- `sh -c 'uv run --extra dev pytest -q tests/test_main_dispatch.py -k real_sigint & wait'` fails with `subprocess.TimeoutExpired` in 60.24 s (wall 60.77 s); the same command in the foreground passes in 0.20 s.

So the test fails, slowly, under any parent that ignores SIGINT: a backgrounded shell, `nohup`, or an agent harness running the suite in the background. `Popen(restore_signals=True)` (the default) does not help: it restores only SIGPIPE, SIGXFZ and SIGXFSZ. A scratch probe on 2026-10-25 with `signal.signal(signal.SIGINT, signal.default_int_handler)` as the child's first statement, run under the same `& wait`, returned code 130 with stderr `["mp logs: interrupted"]` in 0.18 s.

**2. The cluster CLI tests load the real embedding model.** `test_action_clusters.test_cli_out_writes_cluster_ids` and `test_cli_text_collapses_a_cluster_to_one_line` call `mp.actions.main(["--open", "--cluster", ...])`, which reaches `action_clusters.cluster_actions(actions, threshold=...)` with no embedder, and that calls `embed_index.default_embedder()`. `default_embedder` returns `MLXEmbedder` whenever `importlib.util.find_spec("mlx_embeddings")` finds it, else `HashingEmbedder`. On the dev Mac `mlx_embeddings` is importable and `models--mlx-community--multilingual-e5-small-mlx` is in the HF cache, so the two tests took 3.65 s and 1.53 s against 0.01 s for the rest of the file; the Linux CI runner gets `HashingEmbedder` (the module docstring says as much). On a Mac with the package but a cold cache, `MLXEmbedder._ensure_loaded` would fetch the model from the network inside a test, unless the egress guard is armed. If the load fails, `cluster_actions` fails open to singletons and the tests' "same cluster" assertions fail, so the outcome depends on the machine. `test_mcp_serve.py` already pins this correctly with `monkeypatch.setattr(embed_index, "default_embedder", lambda *a, **k: embed_index.HashingEmbedder(dim=256))`.

**3. A module-level skip hides the SDK-free tests.** `test_mcp_serve.py` runs `` sdk = pytest.importorskip("mcp", reason="the optional `mcp` extra is not installed") `` at module level, after the last SDK-free test and before the only two that need the SDK (`test_every_spec_builds_a_real_sdk_tool`, `test_the_sdk_server_registers_the_five_tools_and_no_others`). A module-level skip skips the whole module at collection. The file collects 37 tests with the extra installed; with `sys.modules["mcp"] = None` it reports `1 skipped` (`SKIPPED [1] tests/test_mcp_serve.py:523`), so 35 SDK-free tests, including `test_status_works_without_the_optional_sdk` and `test_a_missing_sdk_names_the_command_that_fixes_it`, never run in exactly the environment they exist for. CI installs `--extra mcp`, so CI does not see it; any venv synced without that extra does.

Re-checked at filing: the hidden count is 35, not about 36, observed with `-rs`, where the audit had inferred it from two runs' totals.

## Scope

1. **SIGINT.** `CHILD` in `test_main_dispatch.py` sets `signal.signal(signal.SIGINT, signal.default_int_handler)` before anything else, and both the child's sleep and the parent's `communicate` timeout drop to 10 s so a regression fails fast. Production `mp.__main__` is not changed: a backgrounded `mp` that ignores Ctrl-C is the shell doing what was asked.
2. **Embedder.** The `library` fixture in `test_action_clusters.py` patches `mp.embed_index.default_embedder` to return a `HashingEmbedder`, the same pin `test_mcp_serve.py` uses. `cluster_actions` imports it inside the function body, so the patch takes effect. The CLI assertions are verbatim restatements, which `HashingEmbedder` groups at `HASHING_THRESHOLD` (`test_hashing_embedder_groups_a_verbatim_restatement` already pins that).
3. **Skip scope.** Remove the module-level `importorskip`; the two SDK tests each call `pytest.importorskip("mcp", ...)` themselves (or share a `skipif(find_spec("mcp") is None)` mark).

## Explicitly not / out of scope

- The pipeline suite's monkeypatch coupling and the `sys.modules` pytest sniff in `events.py`: T6.
- Python children writing the real `pipeline.log` and the `mlx-server.json` marker: T9.
- The "no network sockets in tests" rule and its exceptions as written in the docs: HYG18 rewords it. This task only removes one path by which the suite could reach the network.
- A conftest-wide SIGINT reset or a suite-wide embedder pin. Only these two places depend on either today; a global fixture would hide the next one instead of failing it.

## Amendment 2026-11-13 (audit band)

Added from the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) findings F152 and F117 (medium, demoted to low on verification) and the unverified lows F195, F196 and F197. All re-verified at HEAD on 2026-11-13. Same class as this task: the pipeline suite's result, or its side effects, depend on the developer's machine.

**Item 2 is still open (F152).** The `library` fixture in `test_action_clusters.py` stubs only `mp.entry.prepare` (`monkeypatch.setattr("mp.entry.prepare", lambda *a, **k: None)`); `cluster_actions` still reaches `emb = embedder if embedder is not None else default_embedder()`, and `default_embedder` returns `MLXEmbedder` whenever `find_spec("mlx_embeddings")` finds it. The audit's socket-recording plugin logged `getaddrinfo('huggingface.co')` and a connect to port 443 from `test_cli_out_writes_cluster_ids`. On the dev Mac the real `~/.cache/huggingface/hub/models--mlx-community--multilingual-e5-small-mlx/refs/main` carries an mtime of 2026-11-12 23:09, consistent with the audit's "rewritten on every run". Item 2's fix stands unchanged; this adds the evidence that the cost is network egress and a write to the real HF cache, not only time.

**The Keychain (F117).** `tests/conftest.py` has no secrets stub. The stub is per test: `monkeypatch.setattr("mp.entry.load_secrets", ...)` appears 2 times in `test_orchestrate.py` and 5 in `test_dogfood.py`. Any other test that reaches `entry.prepare(cfg, ...)` with `secrets=True` (`orchestrate.run_all` and `summarize.summarize` both call it) runs `config.load_secrets`, which, unless the egress guard is armed, calls `_keychain_get` and spawns `/usr/bin/security find-generic-password` for each managed key missing from the environment. `mp.doctor` imports and calls `load_secrets()` directly too. Correction at filing: the tokens do not outlive the test, because the autouse `_reset_egress_guard` snapshots and restores every `MANAGED_SECRET_KEYS` entry after each test; the defect is the Keychain read and the live token in `os.environ` for that test's duration. Correction at filing: stubbing `config._keychain_get` alone does nothing for `load_secrets`, whose default `reader=_keychain_get` is bound at definition time; the stub has to replace that bound default or patch every `from .config import load_secrets` site (`mp.entry`, `mp.doctor`).

**The developer's config.toml (F195).** `actions.main` calls `cfg = entry.prepare(secrets=False)` with no cfg, so `Config.load()` reads `path or CONFIG_PATH`, and `CONFIG_PATH = _expand("~/.config/meeting-pipe/config.toml")` is a module constant nothing in the suite redirects. `test_actions.test_main_json_sorts_dated_first` and `test_main_empty_library` call `main(...)` with no stub, so they parse the real file and then run `arm_for_config(cfg)` on it: a malformed config fails them, and a developer config with `regulated_mode` on arms the egress guard inside them.

**Pytest's own stdout and stderr (F196).** With `os.execvpe` faked, `serve_local_main` still runs `_redirect_output_to_server_log()`, which does `os.dup2(handle.fileno(), 1)` and `os.dup2(handle.fileno(), 2)` onto the pytest process, and nothing restores them; `test_serve_local_execs_server_for_configured_model` and `test_serve_local_strips_cloud_tokens_from_child_under_regulated` both reach it. Correction at filing: the damage is bounded by pytest's capture mode. Under the default fd capture, pytest's suspend re-`dup2`s its saved fds after the test, and `uv run --extra dev pytest -q tests/test_serve_local.py -k "execs_server or help_returns"` printed `2 passed` on 2026-11-13; with `-s` the same command printed nothing at all, because the session's report went into the redirected (pytest temp) `mlx-server.log`. The log itself lands in the pytest-redirected logs dir, not production.

**Real sleeps with sub-second margins (F197).** `test_a_request_longer_than_the_idle_timeout_keeps_the_server` drives a real `threading.Timer` with `idle_timeout_sec=1.0` against a fake server that sleeps 2.0 s, then `time.sleep(0.2)` and a second request that must start before the timer, roughly 0.8 s of margin on a loaded machine. `test_progress_heartbeat.py` runs `_ProgressHeartbeat(interval_s=0.02)` for `time.sleep(0.1)` and `time.sleep(0.08)` and requires at least one beat. Correction at filing: no flake was observed; this is a margin finding, as filed.
