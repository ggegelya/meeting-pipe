# UX72: the local-width refusal is written about this Mac's history rather than for the person reading it

Band origin: filed 2026-08-04 at the owner's request, found while walking AI12 the day it shipped: the wording "feels bounded to the context of current issues we face on the mac (going past that cap has taken this mac down before - exact sign of this boundary, which is not the case for new users..)". Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

`AskContextWidth.swift:213` refuses a width the local backend cannot hold with a sentence containing "has taken this Mac down before."

That is true, and it is why the guard exists: a wide local pack rebooted the owner's Mac on 2026-07-29 (LOCAL16). Writing the incident into the control's copy is a different thing from acting on it. The sentence reports an event in this installation's past, in the second person, to a reader who may have no such past; on a machine that has never been taken down it is not merely irrelevant but unverifiable and slightly alarming.

The rest of the width copy is the model to match, and it is good: "About 25x the text sent to Anthropic, so about 25x the cost of a normal question" and "Needs about 24 GB; this Mac has 16 GB" both state a present fact about *this* machine and *this* request, and neither reaches for history. The refusal should read the same way, saying what will not fit and why, not what happened before.

This is small and it is worth a row rather than a drive-by because the product now has two documents and a possible tutorial in flight (DOC13, FEAT15) whose whole subject is register, and a control that talks about the developer's own incident is the same category of leak as a user-facing guide linking to `../README.md`.

## Scope

Rewrite that one refusal so it states the constraint rather than the anecdote, in the register the neighbouring sublabels already use: what the request needs, what this Mac has, and what to do instead. The existing "Switch to a cloud backend in Preferences" clause is fine and should survive.

Sweep the rest of `AskContextWidth.swift`'s strings for the same shape while there, since the file is small and one pass is cheaper than a second row later.

## Explicitly not / out of scope

**Not the guard itself.** The ceiling is correct, LOCAL16 established why, and the refusal must keep refusing. This is wording only.

**Not the tier table.** Which widths are offered at which memory is AI12's decision and is unchanged.

**Not a general copy sweep.** Other surfaces are DOC12's and DOC13's; this row is `AskContextWidth.swift`.

## Acceptance

`cd daemon && swift build` clean and `swift test` green. Whether this needs a new test is a judgement call: if the copy is already pinned by an existing `AskContextWidthTests` case, updating that case is the whole change.

The string "has taken this Mac down before" appears nowhere in `daemon/Sources`. Worth a source fence given how easy it is to reintroduce from the spec history.

No em-dashes in changed lines. Repo dash guard green.
