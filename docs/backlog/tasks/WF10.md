# WF10: a workflow saved with every destination unchecked writes `workflow_sinks: []`, which Python deliberately ignores and publishes to the global default sinks (Notion on the owner's config) while the Workflows inspector tells the user "No destination set"

Band origin: filed 2026-10-25 from the 2026-10-25 observability audit band ([observability audit](../../audits/2026-10-25-observability-audit.md) row O2, finder FB-2). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The two trees give an empty sink list opposite meanings. Re-read in code on 2026-10-25.

**Swift produces it and says it means nothing is published.** `SinkSelection.toWorkflowSinks` in `WorkflowsView.swift` builds the list straight from the four toggles, and the editor's `save()` validates only the name before `store.update(clone)`. `WorkflowStore` round-trips an empty `sinks` array, and `decode` also yields `[]` for a hand-edited TOML with no `[[sinks]]` table at all (`var sinks: [WorkflowSink] = []; if let arr = doc["sinks"]?.array`). `Workflow.effectiveSinks` is `flags.ndaMode ? [.filesystem] : sinks`, so for any non-NDA workflow the empty list passes through, and `MeetingMetaSidecar.build` writes `dict["workflow_sinks"] = wf.effectiveSinkTypeNames`, which is `[]`. The inspector then renders `guard !sinks.isEmpty else { return Row(label: "Output", value: "No destination set") }` (`WorkflowInspectorPresentation.outputRow`).

**Python ignores it on purpose.** `workflow.apply_overrides`: `if isinstance(sinks, list) and sinks:`, so an empty list is skipped, nothing is added to `changed`, and the overlay log line does not mention it. `test_workflow_overlay.py::test_empty_sinks_list_is_ignored` pins that choice with the comment "must not silently strip publishing. Fall back to the global default." The global default when `config.toml` has no `[output]` table is `OutputCfg.sinks = ["notion"]`, which is the owner's configuration.

So a user who unchecks every destination to keep a workflow's meetings in the Library gets each of them published to Notion, and if `NOTION_TOKEN` is missing, a publish failure (exit 3) for a publish they never asked for. NDA workflows are unaffected: the Swift clamp turns `[]` into `["filesystem"]` and Python's zero-egress clamp re-applies it. Latent on this Mac (all three workflow TOMLs have at least one `[[sinks]]`), reachable in ordinary editor use. The editor does have an explicit "Filesystem (local Markdown only)" toggle, which makes unchecking everything a less likely way to ask for local-only output, but nothing tells the user that unchecking everything means the opposite.

**What "publish nowhere" already does on the Python side.** `publish_router.fanout` with no publishers logs "no publishers configured; returning local-only result" and returns a clean result with `sinks: {}`, and `all_sinks_failed` is false, so the run exits 0. That path is already reached today by a regulated run whose only sink is Notion (`effective_sinks` drops it). But `_write_publish_sidecar` stamps it `state: publish_state(result)`, which is `"none"` for an empty sink map, and the daemon renders `"none"` as the `Unpublished` warning pill with the help text "Every publish target failed for this meeting." (`MeetingRow`), lists it under Needs you (`LibraryScope`), offers an inline Publish, and `AudioRetention.isSettled` treats it as unsettled, so retention never applies. Making `[]` mean "nowhere" without fixing that would trade a privacy surprise for a false failure on every such meeting.

## Scope

One meaning on both sides: **an empty sink list means publish nowhere.** The summary stays in the Library (`<stem>.summary.json` is written before any sink runs). This is the direction that cannot egress by accident, and it is what the inspector already says.

1. **Python honours it.** `apply_overrides` treats a present `workflow_sinks` list as authoritative even when empty: `overlay.output.sinks = []` and `changed.append("sinks=(none)")`. A missing key still keeps the global default (the inherit contract stays as is). `test_empty_sinks_list_is_ignored` is replaced, its comment rewritten to say why.
2. **A distinct publish state for "nothing was meant to run".** `publish_router.fanout` marks a result whose resolved sink list (`effective_sinks(cfg)`) is empty, and `publish_state` returns a new `"local"` for it, and keeps `"none"` for "sinks were configured and every one failed or was skipped by `build_publishers` for missing config", so a half-configured Obsidian sink still surfaces. This also corrects the regulated Notion-only run above. CONVENTIONS.md's publish-result section adds the value, and the CI4 `publish-result-golden.json` fixture is regenerated with `scripts/gen_contract_fixtures.py`.
3. **Swift reads it as settled.** `MeetingRow` renders `"local"` as Ready (with help text "Kept in the Library; this workflow publishes nowhere"), `LibraryScope`'s Needs you predicate and `AudioRetention.isSettled` treat it as settled, and `inlineFix` offers nothing for it.
4. **The editor says what it means.** When no destination toggle is on and NDA is off, the sink section shows a caption in the existing `note(...)` style: "No destinations: summaries stay in the Library and are never published." The inspector's "No destination set" row gains the same second clause.
5. **Pin it across the boundary.** A fifth meta-contract fixture, `workflow-no-sinks.meta.json`, built by `MetaContractFixtureTests` from a non-NDA workflow with `sinks: []`, asserted by `test_workflow_overlay.py` to resolve to `output.sinks == []`.

## Explicitly not

- **Refusing to save a workflow with no destination.** Considered and not chosen: it would still leave a hand-edited TOML with no `[[sinks]]`, and every sidecar already written with `[]`, needing a meaning on the Python side, so it adds a blocked save without removing the decision. If the owner prefers a hard block at pickup, it goes on top of items 1 to 3, not instead of them.
- Changing the global default sink list or what an absent `workflow_sinks` key means.
- Partial-publish and skip wording in the done notification and the menu: UX90. Sink configuration notes and the routing editor's usability: UX45 and UX88.
- A meta sidecar that cannot be read at all: SEC25.

## Acceptance

- `test_workflow_overlay.py`: an empty `workflow_sinks` resolves to `output.sinks == []` and the overlay log names `sinks=(none)`; a missing key keeps the global default; the new fixture resolves to `[]`; an NDA sidecar with `[]` still resolves to `["filesystem"]`.
- `test_publish_router.py`: `publish_state` is `"local"` for an empty resolved sink list and for a regulated run whose only sink was Notion, `"none"` when every configured sink failed, and `"none"` when the only configured sink was skipped for missing config; an `mp run-all` with `[]` sinks exits 0 and writes `publish.json` with `state: "local"`.
- Swift: `MetaContractFixtureTests` builds and verifies the new fixture; `CI4ContractFixtureTests` decodes `"local"`; `AudioRetention.isSettled` is true for it; a `WorkflowInspectorTests` case for the reworded row; a row-presentation test that `"local"` is not in Needs you and renders Ready.
- `cd daemon && swift test` and `cd pipeline && uv run --extra dev pytest -q` green, new test counts in the commit body; `bash scripts/ci-local.sh` green.
- docs/GUIDE.md section 2 (Workflows) says that unchecking every destination keeps summaries in the Library only, in the same commit.
