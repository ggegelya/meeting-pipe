# UX101: Filters, saved folders and Needs you read a scan status that is never .recording and turns .failed after two hours live

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: G039 (medium, confirmed) and G038 (partially confirmed, demoted from medium to a verified low) in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md). Re-verified in code at HEAD `3a2da4fc` on 2026-11-13. The [field evidence pack](../../audits/2026-11-13-field-evidence.md) lists G039 among the UI findings with no log surface, so there is no field count.

**`.recording` is a display-only status.** `Meeting.Status` declares `case recording // currently being written (live)`, but no scan path assigns it. `MeetingStore.buildMeeting` reaches its last branch for a stem with no failure, summary, paste-ready or empty sidecar, and there `if age > Meeting.staleProcessingThresholdSec { status = .failed ... } else { status = .processing }`, with `staleProcessingThresholdSec` at `2 * 60 * 60`. The branch's comment says "The live-recording overlay supersedes this via `LibraryWindowModel.liveRecordingStem`", but that overlay exists in exactly one place: `MeetingRow.effectiveStatus`, `isLiveRecording ? .recording : meeting.status`, which only feeds the row's pill.

**Every other reader sees the raw status.**

- `MeetingFilterEngine.apply` filters with `if let st = filter.status, m.status != st { return false }`, so the filter bar's Status: Recording chip (`FilterBarView`, `Button("Recording") { filter.status = .recording }`) can never match anything, and a saved folder that persisted that chip (`SavedSearchViews` labels `.recording` "Recording") is always empty.
- `LibraryScope.includes` for `.needsYou` returns true for `case .failed, .manualPasteReady, .empty`, and the sidebar's count walk uses the same rule, so a live stem older than two hours raises the amber Needs you count.
- `MeetingRow`'s context menu shows `Button("Reprocess")` under `if meeting.status == .failed`, which reads the raw status, so the meeting being recorded offers Reprocess. The pill itself reads Recording because it uses `effectiveStatus`.

**Scenario** (from the audit): two hours ten minutes into a workshop, the rail shows one meeting needing attention, Status: Failed lists the meeting still being recorded, its menu offers Reprocess, and Status: Recording returns an empty list. The live row is visible because its capture intermediates keep a fresh mtime, so `freshCaptureIntermediate` keeps the row alive for the whole recording.

**The authoritative owner already exists.** `RecordingStemOwnership` (REC23) is the main-confined set of stems "whose capture intermediates the recorder is writing, or may still write", claimed before the first file is created; `LibraryWindowModel.liveRecordingStem` is the UI mirror set after `start()` returns. Either is enough to tell the scan that a stem is live.

**G038, same derivation, folded in.** `MeetingStatusPill.decide` switches on `(status, isNDA)` and its first case is `case (_, true): return MeetingStatusPill(kind: .nda, label: "Kept local", help: "On this Mac by design (NDA workflow).")`. `isNDA` is `meeting.isZeroEgress`, which is `(workflowNDAMode ?? false) || (regulatedMode ?? false) || metaUnreadable`. So a finished zero-egress row reads Kept local whatever its lifecycle: Failed, No speech, Paste pending and Processing are all hidden behind it, and the help text names an NDA workflow even when regulated mode or an unreadable sidecar set the flag. The precedence is deliberate (DSN22 #8, "intent, not failure") and test-pinned, which is why the audit rated it partially confirmed.

Correction at filing: the audit's G038 title includes Recording among the outranked states. That does not happen in practice: `MeetingSessionController.writeMetaSidecar` writes `<stem>.meta.json` at stop, so a live row has no sidecar, `isZeroEgress` is false, and the pill reads Recording. Only finished rows are affected.

## Scope

1. **One live overlay where rows are derived.** Pass the owned stems (from `RecordingStemOwnership`, or `liveRecordingStem` where the Library cannot reach the recorder's set) into row derivation once, so every reader sees `.recording` for a live stem: `MeetingFilterEngine.apply`, `LibraryScope.includes` (through its `Context`), the sidebar counts in `LibrarySidebar`, saved folders, and the row menu's Reprocess gate. The simplest seam is to map statuses in `LibraryListView`'s derivation and the sidebar count walk before filtering; the alternative is a field on `LibraryScope.Context` and an extra parameter to `MeetingFilterEngine.apply`. Pick one and use it everywhere; `MeetingRow.effectiveStatus` then reads the same answer instead of re-deriving it.
2. **Exempt an owned stem from the age rule.** In `MeetingStore.buildMeeting`'s last branch, an owned stem stays `.processing` (or becomes `.recording`) past `staleProcessingThresholdSec`, and is not cacheable while owned, so the first scan after release re-decides it. If [ARCH20](./ARCH20.md) lands first, this is one more input row of its `MeetingStatus.decide` table rather than a branch in the ladder; whichever lands second carries the other's test.
3. **G038: keep the lifecycle visible on a zero-egress row.** Stop letting `isNDA` win the switch in `MeetingStatusPill.decide`: the lifecycle pill keeps its kind and label, and Kept local becomes a second pill beside it, the way `trailingPill` already lays out Mic silent next to the status pill. Its help text comes from whichever flag set it (NDA workflow, regulated mode, or an unreadable sidecar treated as local by default). Update the tests that pin the old precedence. This reverses a deliberate DSN22 #8 choice in part (Kept local still shows, it just stops hiding failures), so the pickup session states that in the commit body.

## Explicitly not

- Restructuring `buildMeeting`'s status ladder as a whole: [ARCH20](./ARCH20.md).
- Changing `staleProcessingThresholdSec` or the age-inferred failure rule for stems nobody owns.
- Trashing, renaming or reprocessing a live stem through other menus or batch actions (a sibling class in this audit band covers trashing a live stem).
- Membership of the NDA only rail after a workflow rename, which is a separate finding in the same audit.

## Acceptance

- Tests:
  - `MeetingFilterEngine` with Status: Recording returns the live stem and nothing else;
  - a live stem whose `startedAt` is older than `staleProcessingThresholdSec` is not in Status: Failed, not in `.needsYou`, does not raise the sidebar's Needs you count, and its row model offers no Reprocess;
  - the same stem, once released from ownership with no sidecar, ages to `.failed` as today;
  - a saved folder holding Status: Recording lists the live stem;
  - `MeetingStatusPill` for a zero-egress row with status `.failed` (and with `.empty`, `.manualPasteReady`) shows the lifecycle pill plus a Kept local pill, and the Kept local help text differs for NDA, regulated and unreadable-sidecar rows.
- Existing `MeetingStore` cacheability tests (PERF22) and the row-pill tests, updated for item 3, stay green.
- `swift test` green with the new tests; `bash scripts/ci-local.sh` green.
- `docs/GUIDE.md`: if a recipe describes the Kept local pill or the Status filter, it is updated in the same commit.
