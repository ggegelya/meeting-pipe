# T10: the default Anthropic summarize request is only ever checked against fakes, so a request-shape change reaches the field first, as the Sonnet 5.5 bump did on 2026-10-01

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([go-live assessment](../../audits/2026-10-21-go-live-assessment.md) QG-8). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Commit `09e7e41` on 2026-10-01, in its own words: "Sonnet 5.5 rejects a non-default temperature and a forced tool_choice with a 400, so a bare summarization.model bump failed every summary." The fix routed the model-dependent kwargs of all three Anthropic call sites (`summarize.AnthropicSummaryClient`, `engine.AnthropicTextClient` for ask and digest, `diarize_cleanup.AnthropicCleanupClient`) through `config.anthropic_sampling`. A regex, `_ANTHROPIC_SAMPLING_MODEL`, decides which ids still get the pinned temperature and forced tool; every other id, including any future one, gets `thinking: {"type": "adaptive"}`, `output_config: {"effort": "low"}` and `tool_choice: {"type": "auto"}`. That is a guess about the API encoded as a regex.

What the suite checks: `test_summarize_backend.py` routes `httpx.Client` through a `MockTransport` (`_anthropic_transport`) and asserts selected fields of the body, for example `test_sonnet_5_5_summarize_request_is_one_the_model_accepts` checks `model`, the absent `temperature`, `tool_choice`, `thinking`, `output_config` and the tool name. That pins what we believe the API accepts. Nothing in the repo ever sends the request to the API: `pyproject.toml`'s `[tool.pytest.ini_options]` holds only `testpaths` and `filterwarnings`, and no test is gated on a live key. The defaults are `Summarization.model = "claude-sonnet-5-5"` and `backend = "anthropic"`, so this is the call every default install makes.

Three things can change that body with no reviewed diff beyond the asserted fields: a default-model bump, an SDK lock refresh (`anthropic` is 0.97.0 in `uv.lock`, capped `<1` by CI8), and an edit to the client (`AnthropicSummaryClient` builds `anthropic.Anthropic(..., timeout=_REQUEST_TIMEOUT, max_retries=0)` and sends `system`, `tools=[SUMMARY_TOOL]` and `messages`).

## Scope

1. **Request snapshots.** For each of the three call sites, a golden JSON of the full request body sent for the default model and a fixed short synthetic transcript, captured through the existing `_anthropic_transport`, stored under `pipeline/tests/goldens/`. A changed body fails the test until the golden is regenerated, which makes every shape change a reviewed diff. Regeneration is one documented command in the test module's docstring; the snapshot excludes volatile values (none are expected, since the transcript is fixed).
2. **An opt-in live contract test.** `pipeline/tests/test_anthropic_live.py`, marked `live` (marker registered in `pyproject.toml`), skipped unless `MP_LIVE_ANTHROPIC=1` and `ANTHROPIC_API_KEY` are both set. It sends a ten-line synthetic transcript through `AnthropicSummaryClient.summarize` with `Summarization().model`, and with `MP_LIVE_MODEL` instead when set, and asserts a validated `MeetingSummary` came back from a tool block. One small call each through `AnthropicTextClient` and `AnthropicCleanupClient`. The transcript is synthetic, never a recording.
3. **When to run it.** The `anthropic_sampling` docstring and the test module say to run the live test before changing the default model, the `anthropic` lock entry, or `anthropic_sampling` itself.

## Explicitly not / out of scope

- A live call in CI. CI holds no key, a live call costs money and flakes on the network, and `ci-local.sh` must stay offline.
- Model-id failures, auto fallback on a refused model, and doctor probing a different model than summarize uses: PIPE28, which can reuse the live test as its probe.
- One shared Anthropic client policy: PIPE24. If it lands first, the snapshot also pins the client's timeout and retry settings.
- The OpenAI and `claude_cli` providers. The `claude_cli` spawn is SEC20.
