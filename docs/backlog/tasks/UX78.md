# UX78: audio keeps playing after leaving the Transcript or Audio tab, with no control on Summary

Band origin: filed 2026-08-10 from the owner's 2026-08-04 testing notes, last item: "when playing transcript, and switching to summary, it would be nice to have the possibility to stop playback, but I have no controls, and playback still running." Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

The playback controller is owned by the detail view, not by either tab that exposes it:

```swift
@StateObject var playback = AudioPlaybackController()   // MeetingDetailView.swift:49
```

It is handed to `TranscriptTab` and `AudioTab` ([:235](../../../daemon/Sources/MeetingPipe/MeetingDetailView.swift#L235), [:243](../../../daemon/Sources/MeetingPipe/MeetingDetailView.swift#L243)) and outlives any switch between them, which is the right ownership: it is what lets the user jump from a summary citation to the transcript and keep their position.

What is missing is a control on the tab that has none. `tabButton` ([:174](../../../daemon/Sources/MeetingPipe/MeetingDetailView.swift#L174)) does exactly one thing on click, `selectedTab = tab.rawValue`, and `tabContent` ([:203](../../../daemon/Sources/MeetingPipe/MeetingDetailView.swift#L203)) switches the subview. Nothing consults `playback`. Since every transport control (`play`, `pause`, `togglePlayPause`, `seek`, the rate and channel pickers) lives inside `AudioTab` and the per-line play affordances inside `TranscriptTab`, selecting **Summary** removes the entire surface while the audio continues.

The two existing `pause()` calls confirm this is an omission rather than a policy. Both are in `TranscriptTab` and both pause for a *local* reason:

- [:440](../../../daemon/Sources/MeetingPipe/TranscriptTab.swift#L440) pauses when an editing or naming sheet opens, because "playback keeps scrolling the list out from under the cursor".
- [:459](../../../daemon/Sources/MeetingPipe/TranscriptTab.swift#L459) pauses on `rightMouseDown` so the context menu can open against a still list.

So the codebase already knows that playback must yield when the user's attention moves, and it handles two narrow cases inside one tab while the tab switch itself, the widest case, is unhandled. There is also no `.onDisappear` pause: `TranscriptTab`'s `onDisappear` removes the right-click monitor and nothing else.

Worth noting for whoever picks this up: with a meeting's audio playing and no visible control, the only exits the owner has are switching back to a tab that has controls, or closing the window. On a shared screen that is worse than merely inconvenient.

## Scope

Two shapes, and they are not equivalent. Pick deliberately; the owner's wording ("it would be nice to have the possibility to stop playback") asks for a control, not for silence.

**A. A persistent mini transport in the detail header, shown whenever `playback.isPlaying`.** Play/pause plus the elapsed position, in the header beside the existing metadata line. Keeps the cross-tab continuity that the shared `@StateObject` exists for, and answers the request literally. Costs a small always-available surface and a decision about where it sits without fighting the header's existing content (`MeetingDetailView+Header.swift` already carries the date, length, language and source, plus the Re-summarize and queued-job rows).

**B. Pause on leaving the audio-bearing tabs.** One `.onChange(of: selectedTab)` that pauses when the new tab is Summary. Two lines, no new chrome, and consistent with the two local pauses above. The cost is that it silently discards an intentional listen-while-reading, and the user gets no control either way, just a stop.

A is the better answer to what was asked and the more useful behaviour; B is what to ship if A's placement cannot be settled. They compose (a header transport plus no auto-pause is coherent; so is A plus B), so say which was chosen and why rather than leaving it implicit.

Constraints:

- **Do not move ownership.** The `@StateObject` on the detail view is load-bearing for the summary-citation-to-transcript jump (`onJumpToTranscript` at [:236](../../../daemon/Sources/MeetingPipe/MeetingDetailView.swift#L236) raises a pending seek and then switches tabs). A per-tab controller would break that.
- **Selecting a different meeting must still stop the previous one's audio.** Not verified on 2026-08-10, so check it before and after: if it already stops, do not regress it; if it does not, that is the same defect one level up and belongs in this task.
- **DSN3 and Dynamic Type** if option A adds chrome: 4.5:1 contrast, no new `.system(size:)` literals on changed lines.
- The controller already publishes everything a header transport needs (`isPlaying`, `currentTime`, `duration`) and already has `togglePlayPause`, so no new state is required.

Read `docs/GUIDE.md` before shipping and update the playback recipe in the same commit if this changes what the guide describes, per the CLAUDE.md rule.

## Explicitly not / out of scope

**Not `AudioPlaybackController` itself.** Its published surface and transport methods are sufficient; this is about where they are reachable from.

**Not the two existing local pauses.** The sheet pause and the right-click pause are correct and stay.

**Not global media-key or Now Playing integration.** A system-level transport would answer this too and is a much larger surface (MPRemoteCommandCenter, artwork, lock-screen metadata) for a single-user local app. If it is ever wanted it is its own row.

**Not the waveform, rate, channel or skip-silence controls.** They belong in `AudioTab` and stay there; a header transport is play/pause and position only.

**Not autoplay behaviour.** Nothing here changes when playback starts.

## Acceptance

- A test asserts the reported case: with playback active, switching `selectedTab` to Summary leaves the user with a reachable transport (option A) or a stopped player (option B). Whichever shape ships, the assertion is that "playing with no way to stop" is unreachable. It must fail against `main`.
- A test asserts the summary-citation jump still works with playback active: a pending seek is honoured and the tab switches, so the shared-controller behaviour is not regressed by the fix.
- A test asserts switching to a different meeting does not leave the previous meeting's audio playing.
- If option A ships, a test asserts the transport is absent when nothing is playing, so the header does not grow permanently.
- `cd daemon && swift build` clean, `swift test` green, with the number of tests this task adds recorded in the ship note. Do not pin an absolute suite total.
- `docs/GUIDE.md` updated in the same commit if its playback recipe changes.
- No em-dashes in changed lines; repo dash guard green.
