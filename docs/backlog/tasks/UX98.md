# UX98: The detail pane's per-meeting state outlives the selection: a finished preview, pasted text or a late transcript reload lands on the next meeting

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Sources: F065 (confirmed) and F070 (partially confirmed) in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md). Re-verified in code at HEAD `3a2da4fc` on 2026-11-14; both hold. Code-derived, not seen in the field.

Correction at filing: the batch summary says a late or cancelled Transcript reload writes another meeting's lines into the pane as a standing state; F070's verifier narrowed that, and it holds at HEAD. After Name a speaker the stale pane usually self-heals at the next debounced rescan, so the wrong-target edit needs to land inside that window; the stale state persists only for Undo naming on a voiceprinted label, a slow load finishing after a faster one, and the Audio tab (detail below).

**The view is reused.** `LibraryWindow` renders `MeetingDetailView(store: model.meetingStore, meeting: only)` with no `.id`, and `MeetingDetailView`'s own stem-change hook says so: "this view has no `.id(meeting.stem)`, so SwiftUI reuses it". Every `@State` in `SummaryTab`, `TranscriptTab` and `AudioTab` is therefore shared between consecutive selections, and only what each tab resets by hand is per meeting. UX78 hit the audio symptom of this and fixed it with a `playback.pause()` in that hook.

**SummaryTab: the reset is incomplete and the preview does not check where it lands (F065).** `.onChange(of: meeting.stem)` resets `isEditing`, `editorModel`, `saveError`, `savedCue`, discards an unkept candidate (`if let s = candidateStem { libraryModel.discardCandidateSummary(stem: s) }`), and clears `candidate`, `candidateStem`, `previewError`, `showReprocess`, `promptDraft`. It does not reset `previewing`, `pasteText`, `pasteSaving` or `pasteError`. `runPreview` awaits `libraryModel.previewSummary(stem: meeting.stem, ...)`, then sets `previewing = false` and on success `candidate = loaded; candidateStem = meeting.stem` with no check that the meeting is still on screen. The `meeting` it reads is the struct copy captured when the task started, so `candidateStem` becomes the old stem while the pane now shows the new meeting. Scenario: Reprocess, Generate candidate on meeting A, select B; when A's run ends, B's Summary tab shows A's candidate in the compare pane beside B's summary, and `keepPreview` and `discardPreview` call `libraryModel.keepCandidateSummary(stem: meeting.stem)` and `discardCandidateSummary(stem: meeting.stem)` with B's stem, while A's candidate sidecar is left on disk. The stem-change reset ran before the candidate arrived, so it cannot catch this. Text typed in the paste editor for one paste-pending meeting pre-fills the next one. A16 (done, see [q3-final.md](../q3-final.md)) discards only a finished candidate on navigation, not an in-flight one.

**Transcript and Audio: the stale-stem guards are tautological (F070).** `TranscriptTab.reload()` starts `let stem = meeting.stem`, awaits a detached `TranscriptLoader.load`, then `guard meeting.stem == stem else { return }`. `meeting` is a `let` of the value type `Meeting` on the view struct, and the async function reads the copy it started with, so the comparison is always true. `AudioTab.reload()` has the same `guard meeting.stem == stem`, and `SummaryTab.reloadSummary()` the same `if meeting.stem == stem`. `.task(id:)` does cancel the old task on a stem change, but `Task.detached(...).value` does not throw on cancellation and nothing checks `Task.isCancelled` after the await, so the cancelled run writes its results into the shared `@State`. The verifier's narrowing, kept: for Name a speaker the stale pane usually self-heals at the next debounced rescan (about 0.5 s plus scan time), so a wrong-target edit needs to land in that window. The stale state persists, with no rescan to repair it, for Undo naming on a voiceprinted label (the overlay is removed before the roster subprocess and the reload runs after it with no further directory event), for a slow load that finishes after a faster one, and on the Audio tab.

**What a stale Transcript pane costs.** Line edits and reassignments are saved against the selected meeting: `TranscriptCorrectionStore.upsert(... stem: meeting.stem ...)` and `libraryModel.reassignSegments(stem: meeting.stem, indices: indices, toLabel:)`. With A's lines on screen while B is selected, the correction goes to B's sidecar carrying A's segment index and original text, and the overlay is applied by index alone (see [ASR12](./ASR12.md) for the index-only apply), so B's transcript is changed at a line the user never saw.

**Two more sites with the same guard, found at filing.** Correction at filing: F070 names Transcript, Audio and Summary only, but the same tautological guard is in `CorrectionsTab.reload()` (`let stem = meeting.stem`, a detached `CorrectionStore.readData(stem: stem)`, then `guard meeting.stem == stem else { return }`, then `record = ...; loadedForStem = stem`) and in `MeetingDetailView.reloadPublishURLs()` (`if meeting.stem == stem { cachedNotionURL = notion ... }`). The Corrections one is the worse of the two: if A's read finishes after B's, the tab holds A's correction record while B is selected, and `CorrectionsTab.performRevert` writes that record's `original_summary` to `meeting.recordingsDir/<B's stem>.summary.json` and deletes B's correction file, so Revert replaces B's summary with A's. The publish one shows A's Notion, Obsidian or local-note links in B's header until the next revision bump.

**Audio tab.** Its work runs under `.task(id: meeting.stem) { await reload(); if let audio = meeting.audioURL { playback.load(url: audio) } }`. A cancelled run for A still finishes `reload()` and then calls `playback.load` with A's URL, so if A's waveform load finishes after B's, the shared player ends up holding the meeting just left. UX53 (done, see [q6-final.md](../q6-final.md)) accepted the stem-only key for a stale waveform, not for the player.

## Scope

Two parts, smallest first:

1. **Reset the subtree per meeting.** Give the detail content `.id(meeting.stem)` at the call site in `LibraryWindow` or inside `MeetingDetailView` around the tabs, so `SummaryTab`, `TranscriptTab` and `AudioTab` get fresh `@State` per selection. Keep `AudioPlaybackController` (a `@StateObject` on `MeetingDetailView`) outside that identity so UX78's header transport and the citation jump keep working; if that is not possible, the pickup states why and takes part 2 for the run state instead. A16's discard of an unkept candidate must still run on navigation (move it to `onDisappear` of the reset subtree or keep it in the stem-change hook).
2. **Guard every await against the live selection.** In `SummaryTab.runPreview`, `SummaryTab.reloadSummary`, `TranscriptTab.reload`, `AudioTab.reload`, `CorrectionsTab.reload` and `MeetingDetailView.reloadPublishURLs`, compare after each await against a live token (a stem held in `@State`, or `Task.isCancelled` for `.task(id:)` work) instead of the captured `meeting.stem`, and drop the result when it no longer matches. `runPreview`'s candidate is assigned only when the token still names the stem the preview ran for; otherwise the orphaned candidate sidecar is discarded. `AudioTab`'s `playback.load` runs only when the task was not cancelled.

Part 1 alone fixes the state leak; part 2 is still needed because `.id` does not stop a detached continuation from writing into a view that lives on under the same identity when the user returns to the same stem.

## Acceptance

- Tests (view-model or extracted pure helpers; a source fence for the `.id` wiring if the SwiftUI part has no runtime read, the UX78 precedent):
  - preview started for stem A, selection moved to B before it completes: no candidate is shown for B, `candidateStem` is not A on B's pane, and A's candidate sidecar is discarded;
  - paste text typed for A is empty after selecting B;
  - a transcript reload for A that completes after selection moved to B writes no segments into B's pane, and a correction made on B afterwards carries B's indices;
  - a cancelled Audio task for A does not call `playback.load` with A's URL after B is selected;
  - a Corrections reload for A that completes after B is selected leaves no A record on B's tab, so Revert on B can only write B's own `original_summary`;
  - a fence asserting no detail-tab guard compares `meeting.stem` with a local captured from `meeting.stem`.
- UX78's existing tests and its citation-jump fence stay green.
- `cd daemon && swift build` and `swift test` green, N new tests named in the commit body; `bash scripts/ci-local.sh` green.
