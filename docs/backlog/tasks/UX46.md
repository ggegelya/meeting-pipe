# UX46: Flag-moment button on the recording HUD

Band origin: filed 2026-07-29 (owner exploratory sweep, item 16: surface features that exist but are invisible; the flag hotkey ranked high because its surface is on screen whenever the feature is usable). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Progress (2026-08-03, shipped; owner-owed eyeball)

Every scope item landed. The HUD's control row is now Stop, the mic-slash toggle, and an outline `flag` button, and the right-click menu leads with **Flag this moment**. Both new entries call `HUDBackgroundView.didClickFlagMoment` -> `RecordingHUDWindow.handleFlagMoment` -> `RecordingHUDDelegate` -> `Coordinator.recordingHUDDidRequestFlagMoment` -> `MeetingSessionController.flagMoment`, which is the hotkey's own entry, so nothing on the HUD side writes a marker, decides a timestamp, or knows the sidecar exists. `swift build` clean, **2036** `swift test` green (7 new; the 1770 in the acceptance below was a filing-time figure and was 2029 on the base this landed from), `truth_fences.py both` green, no pipeline change.

**The width, which UX35 left to whichever task landed second.** UX35 shipped one 96pt pill sized for the "Off the record" label, and predicted this task would have to widen it. It does: the control row goes 34 + 8 + 26 = 68pt to 34 + 8 + 26 + 8 + 26 = 102pt, so the *control row*, not the state label, is now the widest thing in the pill. `HUDPanelGeometry.pillWidth` is **116**, which is 102 plus the same 13pt of side margin UX35 measured for 96, rounded onto the 4pt grid the same way. The row's own arithmetic moved onto the geometry type beside it (`controlGap`, `iconControlSide`, `controlRowWidth`, `stopCenterXOffset`), so the `-17` literal in `makeContentView` is gone: the offset is derived as half the row minus half of Stop, which is -34 with two icon controls and would follow a fourth on its own. Two tests pin what a number cannot: the row fits inside the pill with a real margin either side, and the row's outer edges are mirror images about the pill's centreX (a control added without moving the offset shows up on screen as a group drifting off-centre, so the property is pinned rather than the value).

**Decisions the spec did not make:**

- **Order on the row: [Stop][off the record][flag], the new control on the end.** Appending it leaves the existing pairing intact (the mic-slash toggle keeps its "beside Stop" adjacency, which UX23's copy and the README both describe), and it keeps Stop with one neighbour rather than two, which matters more here than elsewhere because the neighbour of a mis-click is Stop. The alternative considered and rejected was flanking Stop with the two toggles, which would have re-centred Stop under the timer at the cost of putting a control on both sides of the destructive one.
- **Order in the menu: flag first, off the record second, Stop last behind the existing separator.** The menu was already ordered by consequence rather than mirroring the row, and the new item is the least consequential of the three.
- **Momentary, not a toggle.** `HUDFlagButton` renders no active state: outline `flag` per the design system's "filled is reserved for selected", tinted `fgMuted` like its sibling (the AA-clearing muted step, not `fgFaint`), no haptic (Stop's detent is for the consequential control), and no marker count. The blink is the entire acknowledgement, as scoped.
- **No new event attribute.** `flagMoment` already logs `recorder.marker_flagged`; it was left alone rather than gaining a `source` attribute to tell a button press from a hotkey press, matching how UX23 added the off-record button without instrumenting the entry point. Adding one later is a one-line change to a single writer, which is the shape the "one path" rule buys.
- **`makeContentView` is internal rather than private**, so the wiring test can build the pill's content view and fire its controls without presenting a panel or reaching a window server. It is the only visibility that changed.

## Context

FEAT8's moment flag (a hotkey stamps a timestamp marker with a quiet HUD blink; markers land in a sidecar, anchor into the transcript, and get their own summary block) is entry-invisible: the only trigger is the global hotkey (`Coordinator.swift:480-487` to `MeetingSessionController.swift:216`), and the only in-app mention is the Preferences General hotkey row's sublabel (`PreferencesView+General.swift:69-71`). The HUD, present for the entire window in which flagging is possible, offers Stop and the off-the-record toggle (`RecordingHUDWindow.swift:356`, :365, right-click menu :528-544) but no flag.

Downstream is already built and good: flag chips render inline in the transcript (`TranscriptTab.swift:46`, :696-710) and the summary carries a flagged-moments block (`markers.py:21-26`). The gap is purely that a user who has not read the hotkey list will never create one.

## Scope

- A flag button on the HUD control row beside the off-record toggle (`HUDOffRecordButton`'s sibling shape, `RecordingHUDWindow.swift:749-757` is the pattern): SF Symbol flag, `.help` tooltip, VoiceOver label, firing the same `MeetingSessionController` entry the hotkey uses (one path; the button must not grow its own marker writer).
- The existing quiet blink acknowledges the press (the hotkey already triggers it; the button reuses it).
- A "Flag this moment" item in the HUD's right-click menu beside the off-record item (:528-544), for parity.
- Width coordination with UX35 (filed the same day): UX35 converges the pill on one width for the recording and off-record states; a third control changes the arithmetic, so whichever task lands second sizes for the final control count. Recorded in both specs.

## Explicitly not in scope

Any change to marker storage, the sidecar, or the summary block (FEAT8's, shipped). A markers list UI beyond the existing transcript chips. Prompt-panel or menu-bar flag entries (the HUD is where the recording is; keep the surface singular).

## Acceptance

A test pins that the button and the menu item invoke the same session entry point as the hotkey (via `FakeSessionHost` or the controller seam), and that pressing while not recording is a no-op (matching the hotkey's guard).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770; measured 2029 on the base this landed from, 2036 after, and HYG5 is the task that stops specs quoting an absolute total). Repo dash guard green.

Owner eyeball: during a recording, click the flag; the HUD blinks; after the pipeline runs, the transcript shows the chip at that timestamp and the summary carries the flagged-moments block. VoiceOver reads the button meaningfully.

## Owner walkthrough (for the session that picks this up)

Every task gated on an owner action carries one (2026-07-30 rule). The engineering is done; these steps are the eyeball the acceptance reserved, and nothing else is owed. Steps are tagged [owner] / [session] by who acts.

1. [session] Install the build, since the HUD is a compiled surface: `./scripts/rebuild.sh` from the repo root.
2. [owner] Start a recording (any real meeting, or **Start Recording** from the menu-bar icon). Look at the floating pill top right. It is wider than you remember, and the row at its foot now has three controls instead of two: the coral Stop key, the mic-slash toggle, and a flag to its right.
3. [owner] Click the flag. The whole pill should dip once and come back, which is the acknowledgement, and nothing else should change: no badge, no counter, no chrome. Click it again a minute later, so there are two moments to find afterwards.
4. [owner] Right-click anywhere on the pill. The menu should read **Flag this moment**, **Go off the record**, then **Stop recording** under a separator. Pick the flag item; you should get the same single dip.
5. [owner] With VoiceOver on (Cmd+F5 toggles it), tab or point at the flag button and confirm it is announced as "Flag this moment" rather than as an unnamed button. Hovering it without VoiceOver should show the same words as a tooltip. Cmd+F5 again to turn VoiceOver off.
6. [owner] Stop the recording and let the pipeline finish. Open the meeting in the Library: the **Transcript** tab should carry a coral flag chip at each moment you flagged (clicking one seeks the audio there), and the summary should carry its flagged-moments block. This half is FEAT8's and has shipped for a while; it is here because it is the proof the button wrote a real marker rather than only blinking.
7. [owner] Last thing, and the one this task can actually get wrong: look at the pill as a whole. Stop should still read as the primary control with the two icons beside it, the group should look centred rather than pushed to one side, and toggling off the record and back should not resize or shift anything (that is UX35's invariant, which the new width has to keep).
8. [session] If all seven pass, UX46 moves to done and archives into `q6-final.md`. If the row looks off-centre or crowded, the numbers to revisit are `HUDPanelGeometry.pillWidth` (116) and the derived `stopCenterXOffset` (-34), both in `RecordingHUDWindow.swift`, and `HUDPanelGeometryTests` is where a new value gets pinned.
