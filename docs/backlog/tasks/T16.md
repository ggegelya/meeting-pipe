# T16: coverage.sh's daemon leg measures one arbitrary test bundle, printing 90.0% for a daemon at 51.0%

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: F151 in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) (lens build, outcome confirmed), named in its executive summary as one of the instruments that say more than the code does.

`scripts/coverage.sh`'s `run_swift` picks its inputs with two `find ... -print -quit` calls:

- `profdata="$(find .build -name 'default.profdata' -print -quit)"`;
- `bin="$(find .build -type f -path '*.xctest/Contents/MacOS/*' -not -path '*.dSYM/*' -print -quit)"`.

Then `xcrun llvm-cov report "$bin" -instr-profile "$profdata"` and the `LINE COVERAGE:` headline are computed over that one binary.

**What `find` sees on this Mac (re-checked 2026-11-13).** Three binaries match the bundle pattern:

- `.build/out/Products/Debug/MeetingPipeCoreTests.xctest/...` (2026-11-12);
- `.build/out/Products/Debug/MeetingPipeTests.xctest/...` (2026-11-12);
- `.build/arm64-apple-macosx/debug/MeetingPipePackageTests.xctest/...` (2026-10-24), left behind by the older build layout.

`swift build --show-bin-path` (Swift 6.4.2) returns `.build/out/Products/Debug`, and the only `default.profdata` is under its `codecov/`. So the current toolchain builds one bundle per test target, and the old tree still holds a combined bundle with no matching profile data.

**What the audit measured.** One run printed `LINE COVERAGE: 4349/4834 = 90.0%` over a 40-file table, which is exactly what MeetingPipeCoreTests alone yields; MeetingPipeTests yields 34024/66762 = 51.0% over 318 files, with the 277-file executable target at 47.9% (`MeetingRecorder.swift` 17.3%, `Coordinator.swift` 0.3%). A later identical `find` returned the stale binary first, for which llvm-cov reports no coverage data at all. Directory order decides which of the three you get.

**Correction at filing:** the baselines already on record are not wrong, and the defect is newer than the harness. CI6 (2026-08-18, archived in [q6-final.md](../q6-final.md)) recorded `LINE COVERAGE: 21712/58261 = 37.3%`, and T3's baseline (2026-07-20) recorded 30.4%; both were taken when SwiftPM still built the single combined `MeetingPipePackageTests` bundle, so `-print -quit` had one candidate. The script became wrong when the toolchain switched to per-target bundles, and the stale combined bundle in the old tree is what makes the pick unstable. The 51.0% figure is one bundle too; the merged figure is the one to record.

**Why it matters now.** [HYG19](./HYG19.md) waits on this: its witness rule has no instrument until `coverage.sh` reports the real figure, and [ASR7](./ASR7.md) cites F151 as the reason its own instrument carries a planted-regression self-check. Related, both done and archived: T3 (built the harness), CI6 (fixed its exit-1 headline).

## Scope

All in `scripts/coverage.sh`, `run_swift`:

1. Resolve the products directory with `swift build --show-bin-path` and look only there, so a stale tree from an older layout is never a candidate.
2. Take `default.profdata` from that directory's `codecov/`; if it is missing, SKIP as today.
3. Collect every `*.xctest/Contents/MacOS/*` binary there (excluding `.dSYM`), and pass the first positionally and the rest with `-object`, to both `llvm-cov report` and `llvm-cov export`, so the table and the headline cover the union of the bundles.
4. Print the bundle names it measured above the table, so a reader can see what the number covers.
5. Re-record the T3 baseline: add a dated row under T3's "Baseline" table in [q6-final.md](../q6-final.md) with the merged daemon figure and the pipeline figure from the same run, noting that earlier rows came from the single-bundle layout.

## Explicitly not

- Not a coverage gate or ratchet; the script stays a report and CI still does not run it (T3's decision).
- Not cleaning `.build/arm64-apple-macosx`; the script ignores it, and deleting build trees is the owner's call.
- Not the pipeline leg, which reads pytest-cov's own total and was not found wrong.

## Acceptance

- `./scripts/coverage.sh swift` prints the bundle list and one `LINE COVERAGE:` figure equal to `llvm-cov export` run by hand over both fresh bundles with `-object` and the same profdata on this Mac; the commit body shows both numbers.
- With a stale `.xctest` present outside the bin path (as on this Mac today), the printed figure is unchanged run to run.
- With the per-target bundles absent (a clean `.build`), the leg still runs `swift test --enable-code-coverage` and reports, or SKIPs with its existing message; it never exits non-zero for a missing artifact.
- `bash scripts/ci-local.sh fences` green (the script is not under CI, so no suite count moves).
- The new baseline row is in q6-final.md under T3, dated, with both figures.
