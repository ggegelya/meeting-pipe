# DOC20: README, SETUP and CONVENTIONS state guarantees the code does not keep: muted spans redacted by default, only the summarizer sees the transcript, every cross-tree surface pinned by a shared fixture

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source findings: F041, G032 and F129 in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) (its overview groups them as "Comments, docs and instruments say more than the code does"), and the field finding "The default mode keeps and transcribes what is said while muted" in the [2026-11-13 field evidence](../../audits/2026-11-13-field-evidence.md). Each claim was re-read in code at HEAD on 2026-11-13.

**DOC8's fix does not hold for the README bullet.** [DOC8](../q6-final.md) (done 2026-07-12, "mute-story truth") swept every surface that claimed live mic zeroing and recorded that "README's ADR 0016 bullet and the Workflows 'Redact muted spans' copy were already correct and left untouched". The Workflows copy was correct; the README bullet was not, and is the one this task corrects. Reopening DOC8 instead is the owner's call; it is filed here as new work because DOC8's own scope (live zeroing) was met.

**1. Muted spans are not redacted by default (F041).** [README.md](../../../README.md)'s capture-first bullet ("The mic is captured losslessly; muted side-comments are redacted afterward, not gated at capture.") goes on: "By default the mic is now recorded in full and the muted spans are redacted from the transcribed, summarized, and published artifact offline". The code default is the opposite. `CaptureMode.resolve(regulated:nda:redactMuted:)` returns `.captureFirst` unless the workflow opted in (`return redactMuted ? .captureFirstRedact : .captureFirst`); `.captureFirst` is documented as "never zero it at capture and never redact"; `Workflow.flags.redactMutedSpans` defaults to `false` and `WorkflowStore` reads `f["redact_muted_spans"]?.bool ?? false`; `MeetingRecorder.persistAfterMerge` writes a mute timeline under `.captureFirst` only for a manual off-the-record span (MIC14). ADR 0016's 2026-06-08 amendment (TECH-MIC9) made this choice on purpose after a wrong mute oracle deleted a real speaker's turn; the README was never updated.

**Field evidence.** Across the six weeks of the owner's event log, 15,853 s of owner-labelled speech fell in 68 recordings, 1,536 s (9.7%) of it while the gate read `muted_by_app`. Of that, 241.6 s fell while the poller agreed or had no reading, the cleanest count of speech said while muted; more than 30 s of it in four recordings (20260930-103043, 20261013-103027, 20261022-103101, 20261110-162917), and 20261110-162917 holds a further 67.6 s from three labels unique to that stretch. Nothing redacted any of it: the whole log carries 1 `mute_timeline_written` and 1 `mute_redacted`, both for the owner's manual off-the-record span in 20261013-170136 (955.1 s, both channels), which worked as designed. The remaining 1,294.7 s fell while the poller read unmuted, so part of it may be a wrong verdict rather than real muted speech; this task does not depend on which.

**What the app already says.** Correction at filing: the field note asks to "say in the app that capture-first keeps muted speech". Two in-app surfaces already do: Preferences ▸ Recording's **Track in-app mute** sublabel ("The mic is always recorded in full; tracking lets a workflow's 'Redact muted spans' remove those moments from the notes offline") and the workflow editor's **Redact muted spans from the notes** sublabel ("Off by default: the full mic is kept and transcribed"). The gap is [docs/GUIDE.md](../../GUIDE.md), which the app renders from the menu bar's **Guide…**: its "Off the record" recipe explains the manual cut and the NDA gate correctly but never says that muting in the meeting app is not the same thing.

**2. The summarizer is not the only thing that sees the transcript (G032).** [docs/SETUP.md](../../SETUP.md) Step 7's default bullet says of Anthropic "The transcript is sent to Anthropic; nothing else leaves your Mac." The default publish target is Notion (`OutputCfg.sinks` default `["notion"]`, and SETUP Step 6 sets it up), and `NotionCfg.include_full_transcript` defaults to `True`, so `publish_notion` appends `_transcript_toggle(transcript_md.read_text(...))` to every page: the summary and the whole transcript leave the Mac by the sink as well. The same step's Local MLX bullet ("Fully on-device, no network") and its closing sentence (the `(cloud)` / `(on-device)` tag lets "you can always tell whether a summary left your Mac") describe the summarizer only and ignore the sink the same way. README's own `notion.include_full_transcript` entry says the opposite of SETUP ("Default `true`, so every word spoken goes to Notion wherever that sink runs"), and the Preferences toggle **Include the full transcript** says it too. The audit's scenario: a user picks Local MLX to keep client calls on the Mac, keeps the Notion destination from Step 6, and every transcript is posted to Notion while the engine line reads `(on-device)`.

**3. Not every cross-tree surface is fixture-pinned (F129).** [CONVENTIONS.md](../../../CONVENTIONS.md)'s "Cross-tree golden fixtures" section opens "Every Swift-Python surface where both trees implement the same thing is pinned by one checked-in fixture that both suites read". At HEAD the table lists ten fixtures. Not in it, and pinned by no fixture both suites read and no source-reading fence: the effective-backend clamp, implemented twice (`RegulatedMode.effectiveBackend(configured:regulated:workflowNDA:)` in Swift, `mp.config.effective_backend` in Python, each with its own tests and no cross-check); and two Python-written payloads Swift strict-decodes, the restore plan (`mp.restore.RestorePlan`, decoded by `RestorePlan` in `RestoreFlow.swift`) and the MCP status (`mp mcp-serve --status --json`, decoded by `MCPStatus`), each pinned only by a JSON copy inside its Swift test. [STOR5](./STOR5.md) recorded the restore-plan choice deliberately ("pinned by a fixture *inside* `RestoreFlowTests` ... rather than by a generated CI4 golden fixture"), so the defect is the sentence, not the missing fixture.

Correction at filing: the audit marked F129 partially confirmed and its "10 of roughly 30" overstates the gap, since several other surfaces are pinned by Swift tests that read Python source and by `scripts/truth_fences.py`. The CONVENTIONS sentence also carries a qualifier ("where both trees implement the same thing") that excludes one-way payloads on a strict reading; the clamp is a two-implementation surface even under that reading. Separately, CONVENTIONS' restore section says a renamed plan key "silently empties the confirm the owner presses"; at HEAD `RestorePlan.load` is a strict `JSONDecoder` decode and `PipelineLauncher.restorePreview` fails with "restore --dry-run produced no readable plan", so a rename fails closed and visibly. That sentence is corrected here too.

## Scope

One doc-truth commit (the DOC12 and HYG6 precedent), no code or copy-string change.

1. **README capture-first bullet.** Rewrite its bold lead ("muted side-comments are redacted afterward") as well as its body, since the lead makes the same false claim. Say what the default does: the mic is recorded in full and nothing is redacted, so a muted aside reaches the transcript, the summary and every sink; a workflow's **Redact muted spans from the notes** opts into offline redaction with the uncut original kept aside; off the record (`⌃⌥O`) is always cut; regulated and NDA keep the real-time gate. Keep the ADR 0016 link.
2. **GUIDE "Off the record".** Add one sentence: muting yourself in the meeting app is not off the record; under an ordinary workflow what you say while muted is kept and transcribed unless the workflow's **Redact muted spans from the notes** is on.
3. **SETUP Steps 6 and 7.** In Step 6, say that Notion receives each meeting's summary and, by default, its full transcript, and name **Preferences ▸ Integrations ▸ Notion ▸ Include the full transcript** as the switch. In Step 7, replace "nothing else leaves your Mac" with a sentence that names the publish destination as the other place the transcript can go, qualify Local MLX's "no network" as the summarizer's, and say the `(cloud)` / `(on-device)` tag names where the summary is written, not where it is published. [PIPE39](./PIPE39.md) may stop the transcript upload; whichever lands second aligns SETUP with the code then true.
4. **CONVENTIONS.** Reword the fixture section's opening to claim only the table ("The surfaces below are pinned ..."), and add a short "Not fixture-pinned" line naming the three surfaces above with where each is pinned instead (the in-test JSON copies, each tree's own clamp tests). Correct the restore section's "silently empties the confirm" to the fail-closed behaviour.
