# T19: Seven guard, wiring and safety tests pass whatever the code does, so the defects they are named after can land with the suite green

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) F115, F112, F113, F118, F111, F190 and G046, merged at filing because they share one shape: a test whose name promises a guard, and whose body passes with the guard deleted. Every claim below was re-read in code at HEAD on 2026-11-13; three were narrower than reported and say so.

**1. The already-engaged skip is never exercised (F115).** `ExplicitStartLifecycleTests.test_engageIsSkippedWhenAnAdapterIsAlreadyLive` asserts `XCTAssertFalse(host.lifecycleCoord.isEngaged)` before and after calling `engageLifecycleIfNeeded`, and its own comment says "No pid in a unit test, so nothing engages". The guard it is named for is `MeetingSessionController.engageLifecycleIfNeeded`'s `guard !coordinator.lifecycleCoord.isEngaged`, which logs `lifecycle_engage_skipped` with `"reason": "already_engaged"`. No test in `daemon/Tests` names `already_engaged`. The guard matters: `MeetingLifecycleCoordinator.engage` opens with `disengage()`, so an unguarded explicit start would reset a live meeting's engine to `.idle`. `EngageOffMainTests` already has what the test lacks: `GatedBuild` hands back handles with a pid, `CountingAdapter` records every `start`, and `skipReasons()` reads the `lifecycle_engage_skipped` rows.

**2. The REC23 wiring fence is met by the retention path (F112).** `RecordingStemOwnershipREC23Tests.test_coordinatorNoLongerReadsTheUIMirror` checks that `Coordinator.swift` lacks `liveRecordingStem` and contains `recorder.ownedStems` and `isOwned:`. `recorder.ownedStems` occurs twice: in `reapStorage` (`MainActor.assumeIsolated { recorder.ownedStems }`, passed to `AudioRetentionSweep.sweep(... liveStems: ownedStems)`) and in `recoverOrphanedRecordings` (passed as `excludingStems:`). Dropping the orphan sweep's `excludingStems: ownedStems` leaves the substring present, so the fence stays green while REC23's defect (merging a still-starting recording's intermediates) returns.

**3. The REC16 wall-clock fence inspects one of four assignments (F113).** `CaptureHealthREC16Tests.test_theSystemOutageMarksAreStampedOnTheWallClock` splits `SystemAudioChannel.swift` on `"systemLostAt = "`, requires at least two marks, and `continue`s past any line lacking `ProcessInfo` or `Date()`. The four production assignments are two resets (`systemLostAt = 0`), `armSystemCapture`'s `systemLostAt = now`, and `handleSystemAudioLost`'s `systemLostAt = max(0, Date().timeIntervalSince1970 - ...)`. Only the last is checked. The count bar is met by the two resets alone, and `armSystemCapture`'s `now` is computed one statement earlier (`let now = Date().timeIntervalSince1970`), so changing that line back to `systemUptime` passes the fence: exactly the REC16 defect.

**4. The entry-contract gate misses the real seams (F118).** `test_entry_contract.py`'s `_is_gated_call` treats a call as sink, engine or token work only when its name is `load_secrets` or ends in `Client` or `Publisher` (`GATE_SUFFIXES`). The real construction seams are named otherwise: `summarize._select_backend`, the `providers` builders (`_anthropic_summary` calls `require_env("ANTHROPIC_API_KEY")`), `publish_router.build_publishers` and `fanout`, and `config.require_env`. And `_entry_contract_violations` checks only the scope enclosing the first `prepare` call, so a `main` that builds a client and then arms through a helper is clean. Re-run on 2026-11-13: a `main` calling `_select_backend(cfg)` before `entry.prepare`, one calling `build_publishers` and `require_env` before it, and one building `AnthropicSummaryClient` before calling a helper `_arm` that wraps `entry.prepare` each returned `[]`. Re-checked 2026-11-14: adding `_select_backend`, `build_publishers`, `fanout` and `require_env` to the predicate finds no violation in any real dispatch target, so the widening is green at HEAD; but six targets (`diarize_cleanup`, `finalize`, `merge_meetings`, `orchestrate`, `publish_from_paste`, `summarize`) reach their first `prepare` inside a helper rather than in `main`, so the helper-arm rule below must count those as armed.

**5. runMP's watchdog and token strip never run in CI (F111).** Correction at filing: the audit says the only test spawning through `PipelineLauncher.runMP` is `FailureProcessTests`, which skips in CI (`ci-local.sh daemon` prints that the daemon job syncs no pipeline venv). That is too broad: several `/bin/sh` stand-in spawns run in CI (`PipelineLauncherTests`' PIPE22 cancel-reaper tests, the PIPE36 `appleRig`, and `PipelineLogOwnerPERF13Tests`, which already reads an env var the child received). The narrower gap holds: no test sets a small `maxRuntime` and lets the watchdog fire, so the `if timedOut.isSet { completion(.failure(LaunchError.timeout(timeout))) }` branch is reached only by constructing the error by hand (`SinkDispatcherTests`, `isCancellation`), and no test asserts that `cloudSecretPolicy`'s strip reaches the child's environment. `cloudSecretPolicy` and `freshEnvironment` are unit-tested as pure functions; the line in `runMP` that joins them (`stripAnthropicKey: policy.stripAnthropic, stripNotionToken: policy.stripNotion`) is not.

**6. The atomic-write test fails before the step it describes (F190).** `AtomicSidecarWriteTests.test_a_failed_overlay_write_leaves_the_previous_overlay_intact` (doc comment: "The load-bearing one") injects failure by setting the directory to `0o500`. That also stops a remove-then-move writer at its first step (writing the `.tmp`), before it removes anything, so the test passes against the defect it describes. The correction-store twin has the same shape. Correction at filing: the shape is not unguarded, since `test_no_sidecar_writer_removes_its_destination_before_replacing_it` in the same file bans `moveItem(at: temp` in four named store files; that fence is a substring over four files, so a reinstated dance spelled with another variable name passes it. Production now writes with `data.write(to: url, options: .atomic)`, one call, so there is no seam between two steps to inject a failure into. That holds for the four sidecar writers the fence names; `ConfigStore`, `GlossaryStore` and `WorkflowStore` write a `.writing` temp and then `replaceItemAt` (or `moveItem(at: tmp` only when the destination does not exist yet), which is not the remove-then-move shape. At HEAD (2026-11-14) every `removeItem` in a `*Store.swift` or `*Sidecar.swift` (`SpeakerLabelStore`, `TranscriptCorrectionStore`, `WorkflowStore`, `PipelineFailureSidecar`, `SecretsStore`) sits in a delete path with no `moveItem` in the same function.

**7. The Clarify safety tests never drive the writer (G046).** `ClarifyTests.test_opening_and_dismissing_writes_neither_file` calls only `Clarify.plan`, `Clarify.substitute` and `Clarify.defaultScope`, which do no I/O. `test_confirming_a_line_fix_writes_only_the_correction_overlay` and `test_confirming_a_rule_writes_only_the_glossary_term` do the store write themselves (`TranscriptCorrectionStore.upsert`, `GlossaryStore.addTerm`) instead of calling `TranscriptTab.applyClarify`, which is where the one-destination rule lives. The transcript editor's save (`TranscriptTab.saveCorrection`) has no test either. Correction at filing: the audit also names `TranscriptOverlayCarryTests` and the People actions. The carry's write is driven by `MeetingLibraryServiceTests.test_retranscribe_carries_the_overlays_onto_the_new_transcript`, and the People rail's rename write is `RosterRename`, driven against a real directory by `RosterRenameTests`; `PeopleView.beginRename` is a thin wrapper. Both are left out.

Related: [ARCH22](./ARCH22.md) retires source fences by access control; [HYG14](./HYG14.md) (proof that production calls the code), [HYG18](./HYG18.md) (fences weaker than they read) and [HYG19](./HYG19.md) are the process side of the same class; [T13](./T13.md) owns shared test support; [REC16](./REC16.md) is `partial`; [REC23](./REC23.md) is done and its guard is sound, only its fence is weak; [CONC7](./CONC7.md) splits `runMP`; [T9](./T9.md) is the spawned child writing the real `pipeline.log`.

## Scope

One behavioural test per item, each replacing or beside the weak one. Where a production seam is needed, it is the smallest that lets the test reach the guard.

1. **Already engaged.** In `EngageOffMainTests` (or with its fixtures), engage through `handleDiscovery`, wait for `adapter.starts.count == 1`, then call `engageLifecycleIfNeeded(source:handles:)` with built handles and assert the adapter saw no second `start`, `isEngaged` stays true, and one `lifecycle_engage_skipped` row carries `reason: already_engaged`. Delete the vacuous test or make it this one.
2. **REC23 sweep input.** Extract the orphan sweep's input construction in `Coordinator.recoverOrphanedRecordings` (the `excludingStems:` set and the `isOwned` closure) into a small function taking the recorder's `RecordingStemOwnership` (`recorder.stemOwnership`), and test it with a claimed stem: the claimed stem is excluded and `isOwned` answers true for it. Drop the `recorder.ownedStems` substring check.
3. **REC16 clock.** Give `SystemAudioChannel` an injected wall clock (defaulting to `Date().timeIntervalSince1970`), used by `armSystemCapture` and `handleSystemAudioLost`. Test through `armSystemCapture(systemURL:isRetry: true)` after a loss at clock t and a retry at t + 30 s: the `system_capture_resumed` row's `gap_sec` is 30 and the pad frame count matches. The source fence goes. One more seam is needed: the retry plans `.resumeOpenFile` only when `systemFirstFrameUptime > 0`, and that mark is `private(set)` and set only inside the capture's private `onBuffer` handler, so the headless arm `SystemCaptureStopREC28Tests` uses always plans `.openFresh` on a retry. Add an internal way to mark the first frame (or deliver one PCM buffer through the armed capture's handler) for the test.
4. **Entry contract.** Add `_select_backend`, `build_publishers`, `fanout` and `require_env` to the gated names (and pin them in `KNOWN_GATED_CALLS`), and make `_entry_contract_violations` check the dispatch target's `main`: a call to a local function that itself reaches `prepare` counts as the arm, and a gated call above it in `main` is a violation. Add the three 2026-11-13 violating shapes as negative cases. The six helper-armed real targets named in Context must stay clean under the new rule.
5. **runMP.** Two `/bin/sh` stand-in tests: (a) the stand-in dumps its environment to a temp file for a meeting whose `<stem>.meta.json` carries `workflow_nda_mode: true` (which `cloudSecretPolicy` strips both tokens for whatever the global config says), with `ANTHROPIC_API_KEY` and `NOTION_TOKEN` in the launcher's `environment:`, and the test asserts both are absent and a non-secret base variable is present. A "token kept" case needs `runMP`'s config path to be injectable, since `cloudSecretPolicy` defaults `configURL` to `Config.defaultPath` and would otherwise read the developer's real config; that is the one seam allowed here; (b) `PipelineLauncher(maxRuntime: 1, ...)` with a stand-in that sleeps past it, asserting completion with `LaunchError.timeout` and that the injected `reapOrphanedServer` ran (the termination handler calls it when `timedOut.isSet`).
6. **Atomic write.** Reword the two failure tests' doc comments to what they prove (a failed save throws and the previous file survives), dropping "load-bearing". Strengthen the shape fence to fail on any `removeItem(at:` of the destination followed by a `moveItem` in the same function, across every file under `daemon/Sources/MeetingPipe` whose name ends in `Store.swift` or `Sidecar.swift` rather than four named files, with a negative fixture showing the rewritten fence fails on a renamed-variable dance.
7. **Clarify and editor save.** Move the write half of `TranscriptTab.applyClarify` and `saveCorrection` into an internal non-View helper (working name `TranscriptEditActions`) taking the stem, directory and glossary URL; the tab calls it. Test it against a temp directory: a line fix writes only the correction overlay, a rule writes only the glossary term and leaves `[fuzzy]`, an editor save of an empty edit reverts the override, and a store failure returns the message without touching the other file.
