# T17: Sixteen of the twenty real detection traces inject their own answer through a pseudo-event, so the corpus cannot fail on any end rule

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source findings: D081, D105, D048, D078, D085 and D090 in the [recording reliability audit](../../audits/2026-11-13-recording-reliability-audit.md) (D105 and D048 have full evidence blocks in [recording-reliability-evidence.md](../../audits/2026-11-13-recording-reliability-evidence.md)); G029, G023 and F191 in the [independent audit](../../audits/2026-11-12-independent-audit.md). Every claim below was re-read in code at HEAD `3a2da4fc` on 2026-11-14; two were narrower than reported and say so.

**1. The pseudo-event (D081, G029).** `daemon/Tests/MeetingPipeCoreTests/Fixtures/detection-corpus/` holds 20 traces the corpus README calls "real dogfood traces": `teams_native_rewalk_end_01` to `13`, `teams_native_flicker_rewalk_end_01` to `03` and `teams_native_debounce_end_01` to `04`. The 16 rewalk and flicker ones end with `{"kind": "confirm_provisional_end", "rewalk_signal": "ax_leave_rewalk"}`. `DetectionCorpusTests` handles that kind by calling `engine.confirmProvisionalEnd(evidence:)` directly, and `PromotionEngine.confirmProvisionalEnd` checks only `guard case .endingProvisional(...) = phase` before `phase = .ended(context: context)`. So whenever the trace reaches a provisional end, the confirm is the trace's own answer: the pair dwell, the lone dwell, END14's live veto, END17's revert rule and Teams' teardown oracle never decide it. The evidence string is also dead: END9 (86269d3a, 2026-08-20) removed the empty re-walk confirm, and at HEAD the host's only route to `confirmProvisionalEnd` is `consultTeardownOracle` on a `TeardownHoldPolicy` confirm. The traces still exercise the in-meeting to `ending_provisional` transition and the three flicker reverts, so "cannot fail on any end rule" means cannot fail on whether or when a provisional end confirms, which is where every END fix from END9 to END17 landed. Two synthetic seeds use the same pseudo-event (`teams_native_clean_leave_en`, `teams_native_post_call_chat_grab_en`), so 18 files carry it in all.

Correction at filing (G029): the independent audit places these traces in `LifecycleTraceReplay`. They are `engine: "promotion"` traces replayed by `DetectionCorpusTests`; the lifecycle replay's own limit is D090, item 5 below.

**2. The traces are rebuilt, not extracted (G023).** `scripts/extract_detection_trace.py` `synthesize()` reads only `lifecycle` verdict rows and constructs the signal timeline. It opens every trace with a fabricated `{"t": 0.0, "kind": start_short, "state": "live"}`, and for the tick family places the end at `last_t + LONE_DWELL + 0.5` with `confirmed_by` forced to `[LONE]`, including pre-END17 ends the log recorded with `confirmed_by: []` on the old debounce. `teams_native_debounce_end_01` shows it: window gone at 1800.01, tick at 2520.51, 720.5 s later, a number the 2026-07-13 log could not contain because the 720 s lone dwell shipped 2026-10-24. Grouped by event structure at HEAD the 20 files are 4 shapes: 12 are Leave live, Leave ended, confirm; 3 are window live, window ended, window live, Leave ended, confirm; 1 is window live, window ended, confirm; 4 are window live, window ended, tick. Each file's `description` still says "Real dogfood session" and "relative timing preserved from the event log".

**3. Extraction only sees ends the detector made (D085).** `sessionize()` opens a session on `lifecycle` `starting` and appends it to the result only on `lifecycle` `ended`. A recording stopped by hand or by the idle backstop never becomes a session, so a missed end is never inventoried, and a false end is emitted with the false end as its expected verdict. `--raw` (T8) takes any UTC window, so the gap is in choosing windows, not in the raw format.

**4. A regression shape the corpus cannot hold (D105).** Before PERF15 (200a4971, 2026-10-26), `AXLeaveButtonSignal._start` threw from `axBus.subscribe` before `startPoll` and the initial `_evaluate`; the element was kept with no poll, so Leave could never go invalid and a mic release was never corroborated. Field, work-laptop era A: `ax_leave_button_arm_failed` at 2026-10-06T14:34:37.313Z and 2026-10-08T13:40:24.882Z, each 0.2 to 1.0 s after an `ending_provisional` led by `process_audio_is_running_input_false` and a `lifecycle_provisional_end_rescued`, then no `ax_leave_button_state` and no `lifecycle` `ended`; the first ran to `auto_stop_silence` at 14:43:59.495Z (562 s), the second to a stop at 13:41:30.217Z. At HEAD `subscribeDestroyed` catches, logs `ax_leave_button_arm_failed`, and `_start` goes on to `startPoll(interval: cadence.initialInterval)` and `_evaluate(reason: "initial")`. Correction at filing: the audit's direction is a corpus regression trace, but a corpus trace feeds `PrimarySignalEvent`s to the engine and never runs `AXLeaveButtonSignal._start`, so it cannot catch this regression. The pin belongs in `AXLeaveButtonSignalTests`, which has no test with a throwing bus at HEAD (no test names `ax_leave_button_arm_failed`; only `AXMuteButtonProbeTests` covers its own arm failure). A raw trace of either window would not help either: the defect is what kept the Leave invalid row out of the log, so a replay at HEAD would see only the mic release and score the lone dwell, not the fix.

**5. The first real field Zoom false end is not in the corpus (D048, D078).** On the home Mac's stale build (c56f2869, before END9), 2026-10-13: `recording_started` (Zoom) 08:03:05.375Z, `shareable_content_window_present` false 08:03:21.967Z, `ending_provisional` .968, `lifecycle_provisional_end_confirmed` .978, `lifecycle` `ended` with `confirmed_by: [ax_leave_rewalk]` .979, while the last `process_audio_is_running_input` read true. Fixed at HEAD by END9; the stale install is DIST6's. The window is still in this Mac's `~/Library/Logs/MeetingPipe/events.jsonl` (71 rows in 08:03, checked 2026-11-14), so a session can extract it with `--raw`. It is the corpus's first chance at a real field Zoom must-not-end trace.

**6. The lifecycle replay stops at the first end and mirrors the host (D090).** `LifecycleTraceReplay.run` breaks on `state.outcome.endedAt != nil`, and its doc comment says "Nothing after an end is replayed". It is a test-side copy of what `MeetingSessionController`'s lifecycle consumer does, and `CallTeardownHoldTests` says outright that `rescueProvisionalEnd` "is not driven here" because its walk is cross-process AX. So a resume after an end (END17 item 5, and END20's 2026-11-12T15:46:06Z incident on stem `20261112-174606`) cannot be expressed as a trace.

**7. The start side has the same shape (F191).** `daemon/Tests/MeetingPipeTests/Fixtures/window_titles.json` holds 21 entries (23 titles), all `seeded: true`. `WindowRecognizerFixtureTests.test_fixture_is_backed_by_real_captures` throws `XCTSkip` until `capturedRowFloor` captured rows exist, and `scripts/ci-local.sh` `allowed_skips` lists that skip against VALOWN1. Correction at filing: the skip is not permanent, it lifts by itself when VALOWN1's owner-run capture lands; but VALOWN1 is P4, so in practice the recognizer is graded only against author-written titles. END24 (the end-side Teams matcher rejecting real titles since 2026-10-08) is what that gap let through.

**Why it matters now.** The work laptop's live event log keeps about 46 days ([field evidence](../../audits/2026-11-13-field-evidence.md), "Rotation is driven by noise: 45.9 days kept"). The audit's copy of that log spans 2026-09-29T09:45:28Z to 2026-11-13T07:44:15Z, so the 2026-10-06 and 2026-10-08 windows leave the live log in the second half of November 2026 and survive only in that copy.

## Scope

1. **A legacy characterization set.** `INDEX.json` gains a `legacy_characterization` list beside `scenarios`, holding the 20 distilled `teams_native_{rewalk,flicker_rewalk,debounce}_end_*` traces and the two synthetic seeds that use the pseudo-event. `DetectionCorpusTests` keeps replaying them (they still pin the provisional transitions), but the corpus `README.md` says they are not evidence for any end rule and states that they are 4 event structures, so their count is never quoted as coverage. A fence in `DetectionCorpusTests` fails when any trace in `scenarios` contains a `confirm_provisional_end` event.
2. **Honest provenance in the extractor.** `synthesize()`'s description template and the 20 committed `description` strings say what the file is: a characterization template rebuilt from the engine's logged verdicts, whose opening live event and lone-dwell tick time are constructed, not logged. No change to event content.
3. **Inventory by recording (D085).** `extract_detection_trace.py --inventory` segments on `recording_started` to `recording_stopped` and reports each recording's stop cause (lifecycle end, hand stop, idle backstop, other) and whether a `lifecycle` `ended` preceded the stop, so hand and backstop stops show up as candidate windows for `--raw`. `--emit-all` keeps its current behaviour for the legacy set.
4. **Truth labels and scoring for lifecycle traces.** An `engine: "lifecycle"` trace may carry `truth`: `call_ended_at` (seconds into the trace, or null when the call is live for the whole window), `truth_source` (closed vocabulary: `owner_stop`, `redetect`, `mic_release`, `owner_label`) and `max_overrun_sec`. The label is written by hand from evidence other than the lifecycle verdict, and `truth_source` names which. The replay reports `seconds_lost` (truth minus the replayed end, when the end comes first) and `overrun_sec` (replayed end minus truth), and asserts `seconds_lost == 0` and `overrun_sec <= max_overrun_sec`. `redact_detection_trace.py` `validate()` accepts exactly these keys for lifecycle traces.
5. **Replay past an end (D090, partial).** `LifecycleTraceReplay.run` no longer breaks at the first `.ended`: after an end it keeps replaying and records every end with its time, so a trace can carry a resume. Events after an end go to the same engine (whose `ingest` returns nil in `.ended`, as at HEAD, where nothing disengages on `.ended` per END20) unless the trace carries an explicit host `engage` event, which starts a fresh `PromotionEngine` and hold policy; the trace states what the host did rather than the replay assuming it. The doc comment's "Nothing after an end is replayed" goes.
6. **Seed truth-labelled traces.** (a) The 2026-10-13 Zoom window (`--raw --from 2026-10-13T08:03:00Z --to 2026-10-13T08:04:30Z --bundle us.zoom.xos`), from this Mac's log, call live throughout (`owner_label`), must not end. (b) At least four windows from the work-laptop pack picked from the new inventory, covering Teams, Zoom and Chrome, at least two genuine ends with a hand-set `max_overrun_sec` and at least two live stretches with a reverted provisional (the audit counts 29 of 31 Leave-led provisionals under a live mic reverting within 45 s). Windows from era A (before 2026-10-12) where a signal was suppressed by a since-fixed defect, such as the two D105 windows, are not eligible, because the missing row would make the replay score the old defect. (c) The 2026-11-12T15:46:06Z first-reading order stays with END20's acceptance, which already says this task owns the format if it lands first; T17 does not commit it while END20 is open, since at HEAD it would replay to the wrong end.
7. **Pin D105 at the signal.** A test in `AXLeaveButtonSignalTests` with a bus whose `subscribe` throws: `ax_leave_button_arm_failed` is logged once, the poll is armed, and killing the element afterwards emits the invalid edge.
8. **The README rule.** A reliability claim about end detection (in a task closure, an ADR or an audit) cites only traces in `scenarios` that carry `truth`.

## Explicitly not

- Deleting or deduping the 20 distilled traces. T8 decided they stay; once they are labelled, deleting buys nothing, and the README's "4 structures" line stops their count being read as coverage.
- Driving `MeetingSessionController` itself through a trace with `FakeSessionHost`, which would retire the replay's mirror of the host. It needs a clock seam across the controller's `Date()` reads (`beginTeardownHold` and `releaseTeardownHold` among them) and is its own task; item 5 is the part that unblocks resume traces now.
- `rescueProvisionalEnd`'s AX walk in CI: it is a cross-process walk against a live app, which no CI runner has.
- The F191 window-title fixture. Its fix is VALOWN1's owner-run capture; this task names it as the same class so it is not read as start-side coverage.
- Changing any end rule. A trace this task adds that fails at HEAD is a finding to file, not a trace to bend; it does not commit until its defect's task lands.
- An observed adjacency for T8: its END9, END12 and END13 windows (2026-08-03, 2026-09-02, 2026-09-04) predate the work-laptop copy's first row (2026-09-29T09:45:28Z), so with about 46 days of rotation they are probably gone from that Mac's log. T8's walkthrough should say so before the owner spends the time.
