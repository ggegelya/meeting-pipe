# UX64: the Ask pane never says the local model stood in for Apple Intelligence

Band origin: filed 2026-08-03, handed off from PIPE12 by owner decision the day PIPE12 landed. PIPE12 made the truth available end to end and its own spec scoped the render out (deferring it to UX31, which had already shipped without a register for it); the owner's call was to close PIPE12 as done and file the render here rather than grow that commit. Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

`mp ask`, `mp digest`, and `mp classify-meetings` have no Apple Intelligence path. When the configured backend is `apple_intelligence`, `engine.complete_text` silently answers on the local MLX model instead, spawning a multi-GB process per ask and tearing it down after. PIPE12 (landed 2026-08-03, `ce007ad`) made that fact explicit rather than log-only:

- `engine.py:213` stamps `replace(result, substituted_from="apple_intelligence")` on the returned `EngineResult`.
- `engine.py:62` carries `substituted_from: str | None = None`, present-and-null on the normal path so a reader can tell "no substitution" from "older build".
- `ask.py:87` and `:226` thread it into the answer JSON.
- A `pipeline` / `engine_backend_substituted` event fires before the local call, so a failed answer still records it.

The Swift side does not read any of that. `AskAnswer` (`PipelineLauncher.swift:27-41`) decodes `question, answer, citations, sources_considered, backend, model, verified, empty, error` and stops; `substituted_from` is dropped on the floor, harmlessly, because `JSONDecoder` ignores unknown keys. So the pane's provenance footer (`AskView.swift:328-332`, via `AskView.backendFooter` at `:359-361`) renders `"Answered \(SummarizationEngine.resolve(backend)!.runPhrase)"` and says the local model answered, with nothing about *why*.

The user-visible consequence is the one PIPE12's gap 3 was named for: someone picks Apple Intelligence precisely to avoid a resident multi-GB model, and every ask spawns one anyway. The log line PIPE12 added is not a surface for a non-technical owner; the Ask pane is.

## Scope

- **Decode it.** `AskAnswer` gains `substitutedFrom: String?` keyed `substituted_from`. Optional, so an answer file written by an older build still decodes.
- **A register on `SummarizationEngine`, not a string at the render site.** `daemon/CLAUDE.md` names this explicitly ("Don't spell a summarization backend's display name at its render site either"), and UX31 exists because seven independent switch tables had already drifted. The substitution phrase needs *two* engines (the one asked for, the one that ran), so it is a new function on that type rather than a fourth `var`. Shape it so the phrase reads for someone who has never heard of MLX, and so an engine this build cannot name still degrades to nil the way `backendFooter` already does.
- **Render it in the footer.** `backendFooter` grows the substitution case. Keep the existing UX31 discipline: nil rather than a fallback when either engine is unnameable, since a line the reader has to decode is worse than no line.
- Decide-and-record whether the same line belongs on the **digest** surface, which runs through the same `engine.complete_text` and therefore carries the same substitution. Likely yes and cheap; if no, the reason lands in a comment at the digest render site.

## Explicitly not in scope

Changing the substitution behaviour itself (falling back to local is correct; PIPE12's spec settled that). Adding an Apple Intelligence Q&A path. Changing `effective_backend` or the auto ladder. Any new backend. Re-opening PIPE12's temperature or adapter legs, which are done.

## Acceptance

Daemon tests: `AskAnswer` round-trips `substituted_from` present and absent (an older answer file without the key still decodes); the footer derivation is pure and table-tested (substitution present yields the two-engine phrase, absent yields today's single-engine phrase, an unnameable engine on either side yields nil); the phrase names both engines and contains no raw config id (`apple_intelligence` must not reach the screen, the same rule that made `claude_cli` a UX31 bug).

`cd daemon && swift build` and `swift test` green, with the number of tests this task adds recorded in the same commit. Repo dash guard green.

Owner eyeball: set the backend to Apple Intelligence, ask a question in the Library's Ask rail, and the footer says the local model answered *and* that Apple Intelligence has no Q&A path, without naming a config id.
