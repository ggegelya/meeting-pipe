# LOCAL14: Staged local summarization pipeline (extract, compose, verify)

Band origin: filed 2026-07-23 (owner ask from the 2026-07-23 local-quality assessment; the owner's direction verbatim: raise local quality via architecture, multi-run passes, consensus, caching; cloud parity explicitly not the target; open to architectural change). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

**LOCAL14 (P2, partial): replace the local backend's single do-everything call with a staged pipeline: grounded extraction, per-section composition, deterministic-first verification.** The filing said to do LOCAL13 (model refresh) first, because a staged pipeline on a better 8-12B compounds and clean attribution requires changing one lever at a time. **That prerequisite is still unmet** (LOCAL13 shipped its harness and thresholds; the runs, the scoring, and the verdict are owner-owed). On 2026-07-28 the owner approved building the pipeline anyway **at reduced scope: ship the three stages behind the internal toggle and keep single-pass as the default**, so the model lever and the shape lever still move one at a time when the bench runs. See [Status](#status-2026-07-28) at the end for what exists and what is owed.

Context, why the single call caps quality. `LocalSummaryClient.summarize` asks one small model, in one shot, to read the whole transcript, obey a ~60-line defensive master prompt plus a full JSON schema pasted as text, and emit title + summary + decisions + actions + questions + attendees at once (summarize_local.py:250-308, `_augment_with_schema` :633-667). Two structural consequences, both visible in the 2026-07-23 side-by-side on stem `20260723-103118`: (1) the defensive rules (no inventions, default-to-empty) are correct hallucination control that a 7B over-obeys into genericity ("Discussed deployment of hotfix and assigned tasks"); (2) JSON discipline competes with content for the model's attention, which is why the 3-layer extractor and the schema-violation replay exist at all (:379-407, :739-776). Small models are markedly better at grounded extraction (find and quote) than at open abstraction (synthesize everything); the design below moves the abstraction burden onto short, dense, already-extracted context.

**Corrected 2026-07-28, and the correction matters to anyone reading this later.** The filing carried a third motivation: that for long meetings the PIPE4 map-reduce summarizes 1,500-char windows into partial summaries and then summarizes the summaries (:88-98, :310-377), a double abstraction compounding vagueness. LOCAL13's bench prep measured that path and it **never fires on real data**: `summarize_local` windows only above 80,000 chars, and the longest transcript in the owner's whole 215-transcript corpus is 72,890. So the double abstraction is real in the code and dead in practice, and it is **not** a reason to build this. Do not restore it as one. The staged design still subsumes that path, which is a consequence worth having, not a justification.

**A second LOCAL13 measurement changed the design rather than the motivation.** The installed `mlx_lm.server` parses **no** `response_format` at all, so every stage decodes unconstrained and the layered JSON recovery is load-bearing rather than belt-and-braces. The filing's "if LOCAL13's probe shows `response_format` is honored, lean on it per stage" is therefore answered: it is not honored, and leaning on it would mean an `mlx-lm` bump (a dependency gate) or in-process loading (ARCH5's `LocalSummaryClient` split), not a request field. What per-stage schemas buy here is size, not constraint: the single-pass preamble is a measured 3,520 fixed tokens per call, larger than the transcript on a typical stand-up, so a design that multiplies calls has to shrink the per-call preamble or it loses on cost before it competes on quality. `chat_template_kwargs` **is** parsed and is the unused `enable_thinking: false` lever; it ships separately with its own test, per LOCAL13.

The staged design, refining the owner's sketch (numbered passes: general summary, key areas, decisions, then re-iterations, consensus voting, prompt caching, automatic learning). Stage 1 EXTRACT: map over transcript windows sized to the model's real budget (model-aware, not the current worst-case 1,500 chars) and pull atomic facts as structured rows: commitments, requests, dates, tickets and artifacts, self-identifications and name cues, unresolved questions, each with a verbatim quote and [mm:ss] timestamp. Extraction is the easy shape for a small model, and the quotes are FEAT10's evidence anchors for free. Stage 2 COMPOSE: one small call per section (summary bullets, decisions, actions, questions, title), each fed ONLY the extracted fact rows, never the raw transcript; a section prompt can then demand specificity (who + what + artifact per bullet) without starving output, because the facts list is short and dense. Stage 3 VERIFY: deterministic checks first (every decision and action must trace to a quote that resolves in the transcript, the FEAT10 verifier shape; owner names must appear in a supporting quote; caps enforced; dedupe), and one LLM critic call only for what determinism cannot judge (e.g. is this a commitment or an intention), with the master prompt's worked examples as its rubric. On the owner's re-iteration passes (sketch steps 4-5): fold them into Stage 3's single critic pass; open-ended self-refine at 7-14B tends to paraphrase rather than improve, so iterate only if the dogfood bench proves a second pass pays. CONSENSUS, bounded: k=3 samples at temperature ~0.6 for the two contested fields only (the decisions list, action owners), majority-keep; adopt only if it beats the critic alone on the bench, and never for the full summary (expensive, and averaging prose regresses to mush). PROMPT CACHING: keep every stage's system+schema prefix byte-stable and put volatile content last so a prefix cache can bite; measure whether the installed `mlx_lm.server` reuses KV across requests at all, and if not either accept the cost (windows are small) or move the loop in-process (ARCH5 already names the LocalSummaryClient split seam; `docs/spikes/local12_bench.py` is the latency harness). A warm server is reused across stages (LOCAL11's identity check applies). Per-stage minimal JSON schemas replace the one giant schema, and if LOCAL13's probe shows `response_format` is honored, lean on it per stage.

Interplay. FEAT10: build Stage 1 quotes+timestamps and the Stage 3 resolver AS FEAT10's local evidence leg, one design landing both, and the FEAT10 spec's "local map-reduce degrades to no evidence" caveat dissolves because this pipeline replaces that path. LANG1/LOCAL7: the language check runs on the final composed summary exactly as today; quotes stay verbatim transcript language (FEAT10's divergence exclusion applies). Long meetings: extraction IS the map, composition reduces facts rather than partial summaries, so the PIPE4 reduce path in `summarize_local` is subsumed; the cloud paste-bundle guard (`skip_above_chars` on cloud backends) is untouched. Degenerate transcripts (LOCAL2 quality checks) short-circuit to the current single-pass shape, which stays in the code as the fallback while the bake-off runs. Automatic learning on corrections stays LOCAL9's (its `mp train-adapter` + dogfood adoption verdict); a retrain cadence is premature until that verdict lands.

Gate, spike discipline. Adopt staged-vs-single-pass on the SAME model via `mp dogfood`, thresholds pre-registered before scoring: actions_capture and decisions_capture must improve by a margin the owner sets in the doc, hallucination_rate must not regress (the verifier should improve it), wall-clock per 15-minute meeting under an owner-set ceiling, RAM inside the caffeinate + free-RAM-watchdog protocol. Keep single-pass as the fallback path; the staged path becomes default only on a verdict.

Explicitly not: cloud backends keep their single tool-use call (Anthropic does not need this and the paste guard economics differ); Apple Intelligence untouched (experimental backend, LOCAL8); no new user-facing config knobs (one internal toggle may exist during the bake-off and dies at adoption, the HYG2 rule); no automatic LoRA retraining (LOCAL9); no streaming/live summarization (I8).

Acceptance. Unit tests against a scripted fake server pin: extraction output shape (quote + timestamp per fact row); composition receives fact rows only (a probe asserting the raw transcript never appears in Stage 2 messages); the verifier drops a fabricated quote, an unresolvable timestamp, and an owner with no supporting quote; the consensus majority rule (if adopted); the degenerate-transcript short-circuit. The dogfood report with pre-registered thresholds and the verdict is committed; latency and peak RSS recorded per stage. ruff + pyright + pytest green; ARCHITECTURE.md's summarize_local description and CONVENTIONS updated in the same commit that flips the default. Owner eyeball: a regenerated `20260723-103118` local summary names people, tickets, and artifacts concretely enough to be checked against the transcript via its FEAT10 chips.

## Status 2026-07-28

**Built, not adopted.** The pipeline exists and is exercised end to end by fakes; the default local path is unchanged and stays that way until the bench says otherwise.

Shipped:

- `pipeline/src/mp/summarize_staged.py`, all three stages. EXTRACT windows the transcript on a token budget converted by script (LOCAL13 measured Latin at 0.25 tok/char and Cyrillic at 0.49, so an English window is ~8,000 chars and a Ukrainian one ~4,000, both far past the old flat 1,500) and returns fact rows carrying a verbatim quote and the `[mm:ss]` of their turn. COMPOSE runs one call per section over the fact rows alone; a composed point cites rows **by index** rather than retyping a quote, which makes fabrication structurally impossible at that stage and leaves Stage 3 to catch a mis-cite. VERIFY runs `evidence.verify` itself against segments recovered from the timestamped render, drops any decision or action with no surviving anchor, nulls an owner not named in **its own** supporting quotes or cited rows, dedupes and caps, then makes one critic call for commitment-vs-intention.
- `evidence.segments_from_timestamped_markdown`, so the staged path verifies one step earlier without a second copy of the resolve rule. The `summarize` pass then re-runs idempotently over already-snapped anchors.
- 38 tests in `pipeline/tests/test_summarize_staged.py`, against a scripted fake and the in-process fake `mlx_lm.server`. Every acceptance bullet above is pinned except the consensus rule, which is not built. The scripted replies are not adversarial inventions: the thinking-mode prefix, the Markdown fence, and the dropped comma are each a failure mode LOCAL13 or the 2026-07-27 lost-meeting incident measured on this exact seam.
- The one internal toggle: `MP_STAGED_LOCAL`, an environment variable and deliberately not a config key (a config key owes `config.example.toml` and the README, both fenced by CI5, and would owe three deletions at adoption). It dies at adoption.

Two deviations, both deliberate:

- **k=3 consensus is not built.** The filing makes it explicitly bench-conditional ("adopt only if it beats the critic alone on the bench"), and there is no bench, so building it would be shipping an unmeasured lever nobody can retire.
- **The single-pass shape is untouched and still the default.** Everything routes through it exactly as before with the toggle unset, which is the test `test_the_toggle_off_keeps_the_single_pass_shape` exists to say.

Owner-owed, and this is the whole remainder:

1. Run `mp dogfood` on the same model with and without `MP_STAGED_LOCAL=1`, over a fixed stem set, under LOCAL13's caffeinate + free-RAM-watchdog protocol.
2. Write the thresholds into a doc **before** scoring, per the Gate paragraph above and LOCAL13's precedent: the two capture margins, the hallucination ceiling, the wall-clock ceiling per 15-minute meeting. Nothing here pre-registers them, and they must not be chosen after a number exists.
3. Score, name a verdict, and either flip the default or record why it stayed. A flip retires `MP_STAGED_LOCAL`, and updates ARCHITECTURE.md and CONVENTIONS.md in that same commit, both of which currently say "not the default" in as many words.
4. The eyeball: a regenerated `20260723-103118` staged summary whose FEAT10 chips check out against the transcript.

Also unmeasured and worth knowing before the bench: whether the installed server reuses a KV prefix across requests at all. The stage prompts are ordered for it (Stage 1 sends a byte-identical system turn for every window, and the five compose prompts share a leading block), but nothing here confirms it bites. If it does not, the staged path pays its preamble per call, which is exactly the cost the per-stage minimal schemas exist to keep small.
