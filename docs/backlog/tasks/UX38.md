# UX38: Ask surface redesign: invitation empty state, docked input, history

Band origin: filed 2026-07-29 (owner exploratory sweep, item 6: "build a nice animated search bar at center of the page, inviting user to ask anything, and show the results of the search in a list form below... and move the search to the top left/top right once search completed. what do you think?"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The owner's instinct is right about the core thing: Ask has a different job from every other rail scope. Facts, People, Stats, and Digests are projections you read; Ask is a conversation you start. Rendering it as another sidebar-plus-content page makes an empty pane with a lonely text field, which invites nothing.

The design opinion the owner asked for, recorded: yes to the centered invitation, with one amendment. After the first answer, the input should dock to the TOP of the pane (full-width or centered), not shrink into a top-left/right corner. A corner placement hides the primary affordance of the surface behind a small target, and the center-then-top pattern is the one the muscle memory already exists for (Spotlight, Raycast, every command palette). Top-docked keeps ask-again one click and zero hunting.

Register constraints from PRODUCT.md: quiet, deliberate, local-first; anti-flashy. "Animated" therefore means a restrained focus/transition treatment honoring `MPMotion.reduceMotion` (the prompt panel at `MeetingPromptWindow.swift:566-573` is the in-repo precedent for motion gating), not a pulsing hero. QuickFind (Cmd+K) already owns find-a-meeting; Ask's copy must frame answering ("Ask about your meetings: what did we decide about X?"), not searching, or the two surfaces blur (the QuickFind Ask handoff row, UX25, already routes questions here).

Dependencies and material: UX37 extracts the root-owned `AskModel` with a session history list this redesign renders; AI11 gives the running state something honest to show (index-rebuild progress instead of a bare spinner). Citations in answers already resolve to real meetings (`rag.verify_citations`) and the answer view already deep-links stems; keep that affordance prominent.

## Scope

- Empty state: centered input with a one-line invitation, 2-3 suggested question chips derived cheaply (recent workflow names, a recent meeting title), and the session history beneath when it exists.
- Ask flow: on submit, the input docks to the top with the quiet transition; the running state shows the AI11 progress line when the index is rebuilding, else the thinking state; Cancel per UX37.
- Results: newest-first history list of question/answer cards (question, answer, citation chips that open the meeting), rendered from `AskModel.history`.
- Decide-and-record with the owner at pickup: whether history persists across app restarts (a small JSON in the config dir, the `SavedSearchStore` single-file idiom) or stays session-only. Default to session-only until asked; durable history is one store away if wanted.
- Reduce-motion path renders the same states without the transition.

## Explicitly not in scope

Engine behavior (AI11). Model ownership and cancellation (UX37; this task builds on it and must not land first). Multi-turn conversation threading (an answer is a card, not a chat; revisit only if the owner asks). Replacing QuickFind or merging the two surfaces.

## Decided at pickup (2026-07-31)

The four calls this spec left to the implementer, recorded here so the walkthrough below is read against what actually shipped.

- **History stays session-only.** The spec's own default, taken rather than escalated. A question is asked about today's library and a restart is a reasonable place for it to end; a durable store is one `SavedSearchStore`-shaped file away if the owner asks. UX37's cap of 20 is what the list renders.
- **The pane docks on "there is anything to show", not on "an answer landed".** Layout is docked whenever a run is in flight or the history is non-empty, so the first question docks the input immediately (the move reads as a response to asking) and returning to the rail with history finds the same docked pane rather than an invitation sitting over a list.
- **The refused second ask is made legible before the click, not after it.** UX37 refuses a second ask while one runs and leaves the field untouched, which on its own is indistinguishable from a dead button. The running card carries the rule and names the way out ("One question at a time. Cancel to ask another."), and the field and the Ask button are visibly inert while the run is up. No transient toast: a state that explains itself is quieter than a message that appears and leaves.
- **The input clears when a run ends, not when it starts.** Through the run the field is the only place the running question is shown (and UX37 keeps the text on purpose so a rail switch cannot blank it); once the answer or the stop is a card, the same text left in the input is a leftover to delete before asking again, which is the opposite of what docking is for. Done in the renderer, so `AskModel`'s contract and UX37's tests are untouched.
- **Both chip kinds stack rather than wrap.** A suggestion is a whole question and a citation is a meeting title, so a flow row would break them mid-sentence at any width the list column actually gets (400 floor, 460 ideal). No wrapping layout was introduced, so the `private` `FlowLayout` in `PreferencesView+Recording.swift` stayed where it is rather than being promoted for one speculative caller.

The AI11 leg needed daemon-side plumbing that did not exist: `mp ask` was printing the heartbeat, but `PipelineLauncher.ask` never passed `runMP`'s `onProgress`, and `PipelineProgress` dropped everything past `stage` + `elapsed_s`. That is presentation plumbing rather than engine behaviour (AI11's own ship note names UX38 as the renderer for those counters), so it landed here: the counters ride `PipelineProgress`, `PipelineLauncher.askPhase` decodes the two `mp ask` stages, and `AskInFlight` gained the field UX37 left room for.

## Acceptance

Presentation-level tests over the view's state derivation: empty model renders invitation, non-empty history renders the list with the input docked, asking state renders progress when the engine reports index work. Citation chips invoke the meeting-open callback with the right stem.

`cd daemon && swift build` and `swift test` green. Repo dash guard green.

Owner eyeball: fresh Ask scope shows the centered invitation; asking docks the input up with a quiet motion (and no motion under Reduce Motion); the answer arrives as the first card with clickable citations; asking again stacks a second card; leaving and returning shows the same history (UX37's guarantee, visible here).
