# UX96: ConfigStore never re-reads a parsed config.toml, so the next Preferences save writes the launch-time document over any hand edit, including regulated_mode

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: finding F012 in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) (high, confirmed by both verifiers by reading; the audit author also re-read it at `4949c9c0`). Re-verified in code at HEAD `3a2da4fc` on 2026-11-14; it holds as reported. Not seen in the field: no field evidence names a lost hand edit, so this is code-derived.

**One parse, then the store is the author.** `ConfigStore.init(configURL:)` calls `apply(Self.read(configURL))` once, and `apply` is the only place that assigns `self.rawDocument = doc`. The only other caller of `apply` is `reloadIfUnparsed()`, which opens with `guard parseError != nil else { return }`, so once the file parsed it never runs. Its doc says so on purpose: "A no-op once the last read parsed: the store is then the file's author, and an unprompted re-read would race its own debounced save." `PreferencesWindow.show()` calls only `store.reloadIfUnparsed()`. The daemon's only `DispatchSource.makeFileSystemObjectSource` is `MeetingStore`'s, on the recordings directory; nothing watches `~/.config/meeting-pipe/config.toml`, and there is no other `ConfigStore.read` caller.

**Every modeled control rewrites the whole file from memory.** Each modeled `@Published` property's `didSet` calls `scheduleSave()`, whose 500 ms timer runs `self.writeBack()` then `persistToDisk()`. `writeBack` writes every modeled key into `rawDocument` from memory, including `ensureTable("modes")["regulated_mode"] = regulatedMode`, and `persistToDisk` renders `rawDocument` and replaces `configURL` atomically. So after any modeled Preferences change:

- a key added to the file by hand after launch (for example `obsidian.template_path` or `obsidian.daily_note_backlink`, which `PreferencesView+Integrations` says "stay in config.toml") is not in `rawDocument` and is gone from the file;
- a modeled key changed by hand after launch (for example `modes.regulated_mode = true`) is written back to its launch-time in-memory value, silently.

**The UI invites exactly this edit.** `PreferencesView+Advanced` offers an `Open in editor` button and the caption "Both are plain TOML - safe to edit by hand if you know what you're doing." The code itself records the owner hitting it once: the `summarizationModel` doc in `ConfigStore` says that before the Pipeline pane's model row, changing the model "meant quitting the app first or having its next save write the old id back". [SETUP.md](../../SETUP.md) step 8 tells the user to hand-edit `[output] sinks`.

**Between the edit and the revert, the two trees disagree.** The pipeline reads `config.toml` at each spawn (`pipeline/src/mp/config.py`), so a hand-set `regulated_mode = true` arms the Python guard immediately. The daemon keeps reading its in-memory value: `MeetingSessionController` passes `coordinator.configStore?.regulatedMode ?? false` into the recording's meta, `Coordinator+MenuActions` reads `configStore?.regulatedMode` for the menu-bar lock glyph and the Library, so the daemon records and labels meetings as not regulated until a relaunch, and then the next unrelated Preferences toggle writes `false` back and the pipeline follows.

**What does not trigger it.** UserDefaults-backed settings, secrets (Keychain) and workflow controls (their own TOML files) do not call `scheduleSave`, so they do not rewrite `config.toml`.

**Prior decision.** ARCH9 (done, see [q6-final.md](../q6-final.md)) made the single parse deliberate and `ConfigStoreTests.test_reload_is_a_no_op_on_a_store_that_parsed` pins it ("an unsaved edit must survive a Preferences reopen"). That rationale is about not losing the UI's own pending edit, which stays a requirement here; it never costed the hand edit lost on the next save. [UX94](./UX94.md) covers the unparseable file only, [UX91](./UX91.md) covers a save that fails, [UX89](./UX89.md) covers the output path field. [PIPE42](./PIPE42.md) (same band) covers the Python side of unknown or misplaced keys and a wrong-typed `regulated_mode`.

## Scope

In `daemon/Sources/MeetingPipe/ConfigStore.swift`:

1. **Track what the UI changed.** Record the set of modeled keys whose `@Published` value was assigned since the last load or save (a dirty set filled from each `didSet`, cleared after a successful persist). `writeBack` keeps writing every key on the first save of a fresh file, so a missing file is still seeded.
2. **Re-read before writing.** In the save path (`scheduleSave`'s timer body and `saveNow()`), read the file again with `Self.read(configURL)` and, if it parsed and differs from the document last loaded or written (compare a content hash, not only mtime), start from the fresh document and apply only the dirty keys onto it. Unmodeled keys and modeled keys the UI did not touch keep their on-disk values. If the re-read fails to parse, do not write (ARCH9's rule) and surface it the way [UX94](./UX94.md) does.
3. **Reload on an outside change when no save is pending.** On `PreferencesWindow.show()`, and on a `DispatchSource` file watch of `config.toml` (write, rename, delete, re-armed after an atomic replace), if no save timer is pending and the content hash differs from the last one the store wrote, `apply` the fresh document with `isInitialized` false (as `reloadIfUnparsed` does) and send `didPersist` so subscribers re-read. The store's own writes must not trigger a reload of themselves (compare against the hash it just wrote).
4. **Conflict rule.** When the same modeled key changed both on disk and in the UI since the last sync, the UI's value wins (it is the newer, deliberate action) and the store logs one `config_edit_conflict` event naming the key, never its value.

Update `reloadIfUnparsed`'s doc and `daemon/docs/gotchas.md`'s "once the file parsed the store is its author" line to the new rule.

## Explicitly not

- Not a TOML-preserving editor (comments, ordering): TOMLKit re-serialises the whole document today and still will.
- Not unknown-key warnings or the misplaced `modes.regulated_mode` table: [PIPE42](./PIPE42.md).
- Not the failed-save surface: [UX91](./UX91.md). Not the parse-error surface: [UX94](./UX94.md).
- Not workflow TOML files or `saved_searches.json` being written over after a restore (the audit's onRestored finding): a separate class.
- Not merging the three debounced-save copies: [CONC8](./CONC8.md). If CONC8 lands first, put the re-read in its shared helper.
- Removing the "safe to edit by hand" copy instead of fixing the store was rejected: SETUP.md and the Obsidian footer depend on hand edits for keys with no control.

## Acceptance

- `ConfigStoreTests`, new tests:
  - a store loaded from a file; an unmodeled key (`obsidian.template_path`) is appended to the file on disk; a modeled control (`manualHotkey`) is changed and `saveNow()` runs; the file holds both the new hotkey and the hand-added key.
  - the same with `modes.regulated_mode` flipped to `true` on disk; after a `manualHotkey` save the file still says `true`.
  - an outside change with no pending save, then the reload path (watcher callback or `show()` hook invoked directly): `store.regulatedMode` reads `true` and `didPersist` fired.
  - the store's own save does not trigger a reload of itself (no second `apply`, no extra `didPersist`).
  - the same key changed on disk and in the UI: the UI value is written and `config_edit_conflict` is emitted with the key name only.
  - a re-read that fails to parse writes nothing and leaves `parseError` set.
- `test_reload_is_a_no_op_on_a_store_that_parsed` is replaced by a test that keeps its intent: an unsaved UI edit survives a Preferences reopen when the file did not change.
- `config_edit_conflict` (ConfigStore emits no event today, so the pickup picks the category and adds its row if it is new) is documented per `CONVENTIONS.md#event-log-schema`, and `python3 scripts/truth_fences.py events` is green.
- `cd daemon && swift build` and `swift test` green, N new tests named in the commit body; `bash scripts/ci-local.sh` green.
- [docs/GUIDE.md](../../GUIDE.md) and [SETUP.md](../../SETUP.md): any sentence telling the user to quit before hand-editing `config.toml` is removed or kept true, in the same commit.
