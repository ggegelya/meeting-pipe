# LOCAL27: train-adapter builds pairs in a shape the server never sends, and its default budget drops every pair

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: finding F083 of the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) (lens antipattern, outcome confirmed, backlog "Claimed fixed, not holding" against LOCAL9 and LOCAL17). Re-verified against HEAD `3a2da4fc` on 2026-11-13 by code reading and one executed measurement in [train_adapter.py](../../../pipeline/src/mp/train_adapter.py).

**A done task's fix does not hold.** LOCAL9 (done, closed 2026-07-30, row in [q6-final.md](../q6-final.md)) shipped `39d0357c` on 2026-07-23, whose body says "the training prompt did not match what the server sends" and fixed it; `train_adapter.Pair` still says the system turn is "schema-augmented exactly as served", and `base_system_prompt`'s docstring says "The exact system turn `LocalSummaryClient` sends". At HEAD three of the three turns differ from what `LocalSummaryClient` sends:

1. **User turn.** `build_pairs` and `build_run_pairs` read the stored transcript at `transcript_path` (`<stem>.md`) and wrap it with `compose_user_message`. `summarize.summarize` sends something else: when `transcript_corrections.overlaid_structured(transcript_md)` succeeds it sends `render_markdown(structured, timestamps=True)`, and `render_markdown`'s own docstring says the `[mm:ss]` variant "is built for the model input only: the stored `<stem>.md` is always rendered without it". So the adapter learns to cite timestamps it never sees, and the speaker-rename and line-edit overlays (FEAT3, PIPE9) and FEAT8's flagged-moments block are missing too.
2. **System turn.** `base_system_prompt` is `augment_with_schema(_load_system_prompt(team_context, summary_language))`. `LocalSummaryClient._messages_for` appends `language_reinforcement(target)` after the schema whenever `expected_summary_language(summary_language, transcript)` returns a target, which for a confident English, Ukrainian or Russian transcript is every meeting. The existing pin `test_pairs_carry_the_prompt_the_local_server_actually_sends` checks the team context, the schema block and the placeholder, never the client's actual messages.
3. **Completion.** `_make_pair` emits `json.dumps(summary, ...)` of the stored `<stem>.summary.json` (or the correction's `corrected_summary`). The stored shape has plain-string `summary`, `decisions` and `questions` with anchors in a side `evidence` map; the tool schema the system turn embeds (`_evidenced_section`) requires each of those items as `{"text": ..., "evidence": [...]}` with `"required": ["text", "evidence"]`. `schemas.normalize_model_summary` is the one-way lift from the model-facing shape to the stored one; nothing inverts it. An adapter trained on these completions learns to emit the shape the schema forbids.

**The default budget drops everything.** Executed on 2026-11-13: `len(base_system_prompt())` is 15,857 chars, and `fit_to_budget`'s budget is `int(DEFAULT_MAX_SEQ_LENGTH * CHARS_PER_TOKEN)` = 4096 x 2.5 = 10,240 chars. `Pair.chars()` counts system plus user plus completion, so every pair is dropped before a transcript is counted. `main` then exits 2 either through `gate_ready` ("corpus not ready", for `--source runs`/`both`) or through the `len(pairs) < 2` check (corrections source, whose gate reads `corrections-stats` instead of the pairs), and neither message says the prompt alone is over budget; the only hint is the "dropped N of N" warning. At LOCAL23's measured rates (`resource_guard.estimate_tokens`, about 0.25 tokens per Latin char) the system turn is about 4,000 tokens, so the 2.5 chars-per-token constant overstates it, but even the true count leaves nothing of a 4,096-token budget for a transcript and a completion.

**Transcripts at default permissions.** `write_dataset` writes `{train,valid,test}.jsonl` (full transcripts plus summaries) with `Path.write_text`, and `write_split_manifest` likewise, so they land at the process umask (typically 0644) under `<adapter-path>/data`. LOCAL9's own run wrote its artifacts under `~/Documents/Meetings/adapters/` (q6-final LOCAL9 row), inside the library folder SEC12 found in iCloud's Documents scope. The repo's helper for this is `storage.atomic_write_text(path, text, mode=0o600)`.

Correction at filing: not all of this postdates LOCAL9. The missing language reinforcement was wrong on the day LOCAL9 shipped (LOCAL7 added it to the client on 2026-07-07). The `[mm:ss]` render and the `{text, evidence}` schema arrived with FEAT10 (`30da1b6e`, 2026-07-24), one day after `39d0357c`, so those two halves are drift that FEAT10 did not carry into the trainer, and LOCAL9's own run (`--max-seq-length 8192`, 42 pairs, all pre-FEAT10) predates them. When the default budget first fell below the system turn is not measured here.

**Field.** [2026-11-13 field evidence](../../audits/2026-11-13-field-evidence.md) lists F083 under "Not seen": no local backend or adapter in the window. [LOCAL17](./LOCAL17.md) (deferred, P3) is the planned retrain at 8192 on a post-FEAT10 corpus; it would hit every item above.

## Scope

1. **One transcript render.** Extract the block in `summarize.summarize` that turns `transcript_md` into the model input (the `overlaid_structured` then `render_markdown(..., timestamps=True)` branch, the overlaid-markdown fallback, and the FEAT8 flagged-moments append) into a module-level function both `summarize` and `train_adapter` call, returning the rendered text and whether a flagged-moments block was appended. The trainer resolves `<stem>.md` from the record and renders through it, and builds that pair's system prompt with `flagged_note` set from the return, so FEAT8's `FLAGGED_INSTRUCTION` is in the system turn exactly when its excerpts are in the user turn.
2. **One message builder.** Lift `LocalSummaryClient._messages_for` into a module-level function in `summarize_local` (as `augment_with_schema` and `compose_user_message` already are, for LOCAL9's reason) taking `system_prompt`, the rendered text and `target`; the client method delegates to it. `_make_pair` builds the system and user turns from it, with `target = expected_summary_language(summary_language, rendered_transcript)` per pair.
3. **Model-facing completions.** Add the inverse of `schemas.normalize_model_summary` beside it: fold the `evidence` map back into `{text, evidence}` objects for `summary`, `decisions` and `questions` (an empty `evidence` list where none was recorded, which is every pre-FEAT10 summary), keep `actions` with their inline `evidence`, and drop stored-only keys absent from `SUMMARY_TOOL["input_schema"]`. `_make_pair` serializes that.
4. **A budget that cannot silently drop everything.** Estimate pair length with `resource_guard.estimate_tokens` instead of `CHARS_PER_TOKEN`. Before building pairs, compare the fixed system turn against `--max-seq-length`; when it alone leaves no room, exit 2 with a message naming the system turn's estimated tokens and the flag to raise, rather than "corpus not ready". Re-set `DEFAULT_MAX_SEQ_LENGTH` and `DEFAULT_BATCH_SIZE` together from that measurement, under the ceiling LOCAL9 measured on the 32 GB Mac (its q6-final row: a 12288 backward drove the Mac to 4-5% free at any batch size, and the real run had to use 8192 at batch 1), with the reasoning beside the constants. If no default under that ceiling leaves room for a typical meeting, say so in the refusal and the README rather than raising the default past it.
5. **Private dataset.** `write_dataset` and `write_split_manifest` write through `storage.atomic_write_text` (mode 0600).

## Explicitly not

- Per-meeting system turns beyond what is derivable from the meeting's own files (workflow overlay extra sections, `MP_CONTEXT_OVERRIDE`, AI6's prior-meeting block): the trainer keeps the config-level system prompt plus the per-pair language target and flagged note. Rebuilding each meeting's historic prompt would need the workflow overlay as it stood when that meeting ran, which nothing records.
- Retraining or adopting an adapter: [LOCAL17](./LOCAL17.md) owns that, and its `--since` filter for the pre-FEAT10 era stays its item.
- Moving `train-adapter` behind `mp dev`: [PIPE20](./PIPE20.md). The other unchmodded writers: [PIPE30](./PIPE30.md), which lists `train_adapter`'s data files as out of its scope; this task takes only their 0600 half.
- Stale absolute paths in the sidecars the pair builders read: [LOCAL26](./LOCAL26.md). Stem derivation from `.run.json` names: [PIPE33](./PIPE33.md).
- The `datasets`/`aiohttp` advisories reached through `mlx_lm`'s tuner: [SEC31](./SEC31.md).
