# UX82: Quit exits 1 so launchd relaunches the app, a crash loop restarts every 10 s forever, the termination ceiling calls exit() off main, and the Accessibility relaunch restarts onboarding at Welcome

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([architecture review](../../audits/2026-10-24-architecture-review.md) M7 and M11, [go-live assessment](../../audits/2026-10-21-go-live-assessment.md) UX-13). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

**Quit overloads the exit status.** TECH-UX7 (2026-05-28) changed the LaunchAgent to `KeepAlive = { SuccessfulExit = false }` (`scripts/launchd.plist.template`) and made `AppDelegate.flushAndExit` end with `exit(relaunch ? EXIT_FAILURE : EXIT_SUCCESS)`, where `AppDelegate.shouldRelaunchOnQuit(override:disableAutoRestart:)` is `override ?? !disableAutoRestart` and `UISettings.disableAutoRestart` defaults to false. So the menu's plain "Quit MeetingPipe" (Cmd+Q) exits 1 and the app comes back; only "Quit (do not relaunch)" (Opt+Cmd+Q, offered by `StatusBarModel.offersQuitWithoutRelaunch` only while the agent is enabled) exits 0. That was the owner's choice for the primary user, and `docs/GUIDE.md` documents it ("**Quit MeetingPipe** is not the one that closes it for good"). The costs:

- To launchd, a requested relaunch and a crash are the same event. Nothing in the logs or in `launchctl print` distinguishes them.
- There is no crash-loop breaker. The plist's only guard is `ThrottleInterval` 10 ("Don't fork-bomb if we're crashing on launch"), so an app that crashes during start relaunches every 10 s indefinitely. Nothing in `daemon/Sources` counts launches.
- Copy depends on the relaunch: `PipelineSectionView` tells the user a setting "applies once the daemon relaunches (Quit from the menu bar)", and GUIDE's Accessibility recipe says to "quit and reopen". `SingleInstanceGuard.standDownExitStatus` "Must stay 0" for the same reason.

**The termination ceiling exits from a background thread.** `AppDelegate.armTerminationCeiling` schedules `DispatchQueue.global(qos: .userInitiated).asyncAfter(deadline: .now() + 9)` and calls `exit(...)` there. `exit` runs `atexit` handlers and C++ static destructors on that thread while the main thread may still be inside `coordinator?.shutdown()` and audio render threads are live, which can turn a wedged quit into a crash report (and, with KeepAlive, a relaunch). `_exit` ends the process without running them. Both log lines before it (`Log.writeLine`, `Log.event`) are synchronous `FileHandle` appends today, so nothing is lost by skipping the handlers.

**The Accessibility relaunch restarts onboarding.** `OnboardingStepPermissions` tells the user "After granting, quit and reopen MeetingPipe for it to take effect" (UX21: macOS caches AX trust per process at launch). `OnboardingRootView` keeps its position in `@State private var step = 0` and `OnboardingGate` only records completion, so after the relaunch the window opens at "Step 1 of 5", Welcome, and the user walks the steps again. There is no button to relaunch; the user has to find Quit.

## Scope

0. **Owner decision, before any code: should plain Quit relaunch by default?** The options are (a) keep TECH-UX7's default (Quit relaunches unless "Relaunch after quitting" is off), or (b) Quit means quit, with relaunch-after-quit an opt-in. Items 1 to 3 hold under either; only the default of `disableAutoRestart` and the GUIDE copy change.
1. **Make a requested relaunch distinguishable from a crash.** Exit 0 on every quit the user asked for without a relaunch, and exit with one dedicated status for a requested relaunch (for example `EX_TEMPFAIL`, 75), written as a named constant beside `standDownExitStatus`. Before that exit, persist a one-shot "relaunch requested" marker in `UserDefaults` so the next launch can tell it was asked for. Recorded so it is not re-litigated: `launchctl kickstart` was the audit's suggestion, but the running job cannot kickstart itself without `-k`, which kills the caller mid-teardown; the pickup confirms this with `launchctl` on the owner's machine before rejecting it for good.
2. **Crash-loop breaker.** At the top of `App.main` (after `SingleInstanceGuard.standDownIfPeerIsRunning`, before the `Coordinator` exists), record the launch time in `UserDefaults`, ignoring launches that follow the item 1 marker. If more than 5 unrequested launches fall within 60 s, start in a safe idle mode: status item and menu only, no detection, no recorder, no preloader, one notification ("MeetingPipe stopped after crashing repeatedly"), a menu row to try a normal start, and a `daemon` `crash_loop_tripped` event with the launch count. Staying alive keeps launchd from respawning; the user's Quit then exits 0.
3. **`_exit` in the termination ceiling**, keeping both log lines before it. If PERF13's logger queue lands first, the ceiling drains it synchronously before `_exit`.
4. **Resume onboarding after the Accessibility relaunch.** Add "Relaunch MeetingPipe" beside the Accessibility row's notice. It persists the current step index in `UserDefaults`, then takes the item 1 requested-relaunch path; `OnboardingRootView` starts at a persisted step and clears it. Only the Permissions step (index 1) is resumable; the later steps hold `OnboardingWorkflowChoice` in memory (WF9) and resuming into them is not attempted.
5. Docs in the same commit: `docs/GUIDE.md` (the Quit rows and paragraph, the Accessibility recipe), `docs/SETUP.md` where it tells the user to quit and reopen after a grant, and the `PipelineSectionView` copy that relies on Quit relaunching.

## Explicitly not / out of scope

- Changing `SuccessfulExit = false` or `ThrottleInterval` in the plist. The breaker lives in the app so it can show the user what happened; launchd has no window.
- UX84's onboarding wiring (presets, the test recording, Dock presence, the tutorial disagreeing with first run). Only the restart-at-Welcome half of go-live SA-7 is here; UX84 must not re-file it.
- Making Accessibility trust apply without a relaunch. macOS caches it per process (UX21); this task only makes the relaunch one click.
- `rebuild.sh` and `install.sh` restart paths, which `bootout` and `bootstrap` the agent and do not depend on the exit status (DIST5 owns installer correctness).

## Acceptance

- `AppDelegateRelaunchTests` extended: a requested relaunch maps to the dedicated status and writes the marker; a plain quit with relaunch disabled maps to 0; the stand-down status stays 0.
- A pure `CrashLoopBreaker` (launch history in, verdict out, injected clock) with at least 5 tests: 5 launches in 60 s do not trip, 6 do, launches after a relaunch marker do not count, old launches age out, the history is bounded.
- A test pins that the ceiling's exit call is `_exit` (the `terminationCeilingExits` hook stays so the test runner survives).
- `OnboardingGateTests` or a new suite: a persisted step resumes at Permissions and is cleared after use; no persisted step starts at Welcome.
- `cd daemon && swift test` green, `bash scripts/ci-local.sh` green, N new tests in the commit body.
- Owner walkthrough (confirms, does not gate): Cmd+Q behaves as decided in item 0; granting Accessibility during onboarding and pressing Relaunch returns to the Permissions step with the row reading Granted.
