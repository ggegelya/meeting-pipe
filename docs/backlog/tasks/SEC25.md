# SEC25: an unreadable or unwritten `<stem>.meta.json` drops the meeting's NDA routing in both trees, because every reader treats a file it cannot read as "no workflow" and a failed stop-time write is swallowed after the recovery manifest that held the same routing is deleted

Band origin: filed 2026-10-25 from the 2026-10-25 observability audit band ([observability audit](../../audits/2026-10-25-observability-audit.md) row O1, finders PY-1, FB-1, SW-1, SW-2, LG-10, FB-11). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

A meeting's per-workflow NDA posture lives only in `<stem>.meta.json` (`workflow_nda_mode`, plus `workflow_backend` and `workflow_sinks`). Re-read in code on 2026-10-25, every reader of that file treats "exists but cannot be read or parsed" exactly like "absent", and absent means the global config.

**Python read path.** `workflow.read_meta` returns `{}` for a missing file and also for any read or parse error: `except Exception as e: ... log.warning("Workflow meta sidecar at %s is malformed: %s", sidecar, e); return {}`. `apply_overrides` then stops at `if not meta: return cfg`, before `workflow_nda_mode`, the sidecar's `regulated_mode` or the zero-egress clamp are looked at. `entry.prepare` runs `apply_overrides` and then `arm_for_config(cfg)`, which does not arm, so `load_secrets` refills the cloud tokens from the Keychain. Every meeting-scoped command goes through `prepare` (summarize, run-all, publish, publish-notion, merge-meetings, diarize-cleanup), and the transcript, summary and WAV are separate files read only after it, so the meeting's own sidecar can fail while everything else reads.

**This read failure has executed.** `~/Library/Logs/MeetingPipe/pipeline.log`, 2026-10-16 12:46:34: two rows `Workflow meta sidecar at .../raw/20260616-201433.meta.json is malformed: [Errno 11] Resource deadlock avoided` (and the same for `20260615-102553`). Errno 11 on Darwin is EDEADLK, which a read of a dataless iCloud file returned; `~/Documents` syncs to iCloud on this Mac. Those two hits came through the AI6 sibling scan in `summarize`, where an unreadable sibling only drops out of the same-workflow match (it fails safe), but the skeptic pass found on 2026-10-25 that the same two stems had `.summary.md`, `.run.json` and `.filesystem.json` dataless while the transcript and summary were local, so a reprocess in that state would read its own sidecar the same way. The log line also names the wrong cause: an I/O error is not "malformed".

**Swift read path.** `PipelineLauncher.cloudSecretPolicy` does `if let data = try? Data(contentsOf: metaURL), let obj = try? JSONSerialization.jsonObject(...) { nda = ... }` with `var nda = false`, so on failure both tokens stay in the child environment. It also never reads the sidecar's `regulated_mode` at all (FB-11), so a meeting recorded under regulated mode and reprocessed after the global flag was turned off keeps both tokens even when the file reads fine; Python's guard is the only clamp left for it. `MeetingLibraryService.isZeroEgress` (the PIPE11 moved-into-NDA publish guard) returns `false` when the file cannot be read, and `MeetingStore`'s row reads the file through `readJSON`, so `Meeting.isZeroEgress` is false and the Library shows no Local only badge. `MeetingLibraryService.reassignWorkflow` starts from `var existing: [String: Any] = [:]` when the read fails and writes the rebuilt dictionary over the file, dropping `regulated_mode`, the source keys and `meeting_title`.

**Swift write path.** `MeetingSessionController.writeMetaSidecar` returns `Void` and ends `catch { Log.main.warning("Failed to write meta sidecar: \(error.localizedDescription)") }`: os.Logger only, whose interpolated reason is stored as `<private>`, no file-log line and no event. On the clean-stop branch the caller then runs `notifyProcessing`, `jobs.enqueue(file:summaryMode:)` and `RecordingManifest.remove(...)`, and the manifest was the only other copy of the NDA payload. Nothing restores it: orphan recovery's `restoreMetaSidecar` only runs for stems with leftover intermediates. The merge-failed branch keeps the manifest, so this is the clean branch only. The write is `.atomic`, so a failure leaves no file rather than a torn one, and the pipeline reads that as "no workflow".

**The project already states the rule this breaks.** `visibility.py`'s module docstring: a malformed sidecar reads as missing on purpose because "a policy gate must not be openable by corrupting a file", and `withheld_reason` withholds both. The routing path is the one reader that does the opposite.

Narrowed from the finders: global regulated mode is not lost on either path, because both `cloudSecretPolicy` (via `ConfigStore`, fail-closed on a parse error since ARCH9) and the pipeline read it live from `config.toml`. What is lost is the per-workflow NDA posture, a workflow's pinned on-device backend, and the sidecar's `regulated_mode` for a meeting whose global flag has since been turned off. Latent on this Mac (no workflow has `nda_mode = true`, global regulated is off); the owner's main library had 3 NDA meetings at AUTO3 filing.

## Scope

1. **Python: three outcomes, fail closed on the third.** `read_meta` keeps its signature for the informational callers (`actions`, `mcp_tools`, `glossary`, the AI6 scan, `visibility`) and a new `load_meta(path) -> MetaRead` returns `absent`, `ok(dict)` or `unreadable(errno, kind)`, where `kind` is `io` or `parse`. `apply_overrides` uses `load_meta`; on `unreadable` it returns a copy with `modes.workflow_nda_mode = True` (backend local, sinks filesystem, the guard arms through the existing `zero_egress` predicate) and logs `Workflow meta sidecar at %s could not be read (%s); running this meeting on-device` with the errno name. The "malformed" wording is reserved for the parse case. `visibility.withheld_reason` keeps reading both as `no_sidecar`.
2. **Python: one event.** `apply_overrides` emits `events.emit("pipeline", "sidecar_unreadable", stem=..., kind=..., errno=...)` once per run on `unreadable`, so the outcome reaches `pipeline_events.jsonl`, not only `pipeline.log`.
3. **Swift: one reader, same three outcomes.** A small `MeetingMetaRead` (absent, loaded, unreadable) used by `cloudSecretPolicy`, `MeetingLibraryService.isZeroEgress`, `reassignWorkflow` and the `MeetingStore` row build. If ARCH10's Codable `MeetingMeta` has landed by pickup, this is its load result rather than a second type. `cloudSecretPolicy` strips both tokens on `unreadable` and reads `regulated_mode` from the sidecar alongside `workflow_nda_mode` (FB-11). `isZeroEgress` and `Meeting.isZeroEgress` are true on `unreadable`, so every Library gate that already reads them (the detail header, the batch pane's cloud count, `MeetingMergeEligibility`'s posture check, the row badge) treats that meeting as local-only. `reassignWorkflow` refuses to write over an unreadable file and returns an error the Library shows.
4. **Swift: the write reports.** `writeMetaSidecar` throws. On the clean-stop branch a failure is logged to the daemon file log and as `Log.event(category: "recorder", action: "meta_write_failed", ...)` with the stem and the error's domain and code, and the recovery manifest is kept. When the active workflow is NDA or pins an on-device backend (`effectiveBackend` is `.local` or `.appleIntelligence`), the job is not enqueued: a `PipelineFailureSidecar` is written with a reason `FailurePresentation.isValidation` recognises ("This meeting's workflow settings could not be saved, so it was not processed. Retry once the disk has space."), and `MeetingLibraryService.retryMeeting` first rebuilds a missing `<stem>.meta.json` from a kept manifest through `OrphanRecordingRecovery.restoreMetaSidecar`. Other workflows enqueue as today, with the event recorded.

## Explicitly not

- Materializing dataless iCloud files before a read (`startDownloadingUbiquitousItem`, an EDEADLK retry loop): STOR6 owns the iCloud placement question. This task makes the read failure safe, not rarer.
- The other stores that read unreadable as empty and save over it (roster, glossary, labels, corrections): STOR9. Library-wide readers that skip unreadable sidecars (digest, ask, MCP, AI6 prior scan): PIPE35.
- Migrating every os.Logger-only site to a file log: OBS1. This task adds the two sites it needs directly.
- NDA classification at record time (title not known, bad regex, NDA turned on later): SEC21. The empty sink list meaning: WF10.
- Holding non-NDA, cloud-backend meetings on a failed write. Their sidecar carries routing (context prompt, sinks) but no privacy promise, and holding every meeting on a transient write error costs more than it protects.
