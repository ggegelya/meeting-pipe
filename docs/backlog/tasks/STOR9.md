# STOR9: eight user-data stores read a file they cannot parse or open as empty and then save that empty state over it, and summarize silently drops the speaker and text overlays it cannot read

Band origin: filed 2026-10-25 from the 2026-10-25 observability audit band ([observability audit](../../audits/2026-10-25-observability-audit.md) O5: PY-2, SW-7, SW-8, PY-7). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Verified in code on 2026-10-25 against `main` at `01e904a`. The idiom is the same in both trees: a reader catches every read and parse error and returns the empty value, and a writer reads, modifies one entry and writes the whole store back. When the read failed, the write replaces the owner's data with the empty-plus-one state. ARCH9 fixed exactly this for `config.toml` (`ConfigStore.parseError`, "never write over an unparsed file"); its spec in [q6-final.md](../q6-final.md) names `glossary.toml` as out of its scope, and nothing filed since covers the other stores.

**Writers that destroy data on a failed read:**

- **Roster (Python).** `RosterStore._people` does `except (OSError, ValueError): return []`; `enroll` then appends one person and calls `_write(people)`. Every named voice is gone after the next "Name this speaker". Skeptic correction: `forget` and `rename` return `False` on an empty list before writing, so only `enroll` destroys, and a non-dict entry raises `AttributeError` (a crash, not a wipe). The real trigger is a JSON syntax error or an `OSError` other than `ENOENT`.
- **Voiceprint (Python).** `VoiceprintStore.load` returns `(None, 0)` on the same exceptions; `meetings()` then reads 0, `orchestrate` calls `store.update(...)` because `store.meetings() < _VOICEPRINT_ENROLL_CAP` (12), and `update` writes a fresh one-sample voiceprint. This half heals over 12 stereo meetings; the roster half does not.
- **Glossary (Swift).** `GlossaryStore.init`: `let raw = (try? String(contentsOf: fileURL, encoding: .utf8)) ?? ""` and `let doc = (try? TOMLTable(string: raw)) ?? TOMLTable()`, with no log. `VocabularyEditor` calls `.onDisappear { glossary.flush() }`, and `flush` runs `saveNow`, which runs `writeBack()` and `persistToDisk()` with no dirty check. Switching Preferences group or closing the window therefore replaces a malformed `glossary.toml` with an empty `[terms]` table, edit or no edit. A second writer, `TranscriptTab`'s Add to Vocabulary (`try GlossaryStore().addTerm(...)`), replaces it with the one confirmed term. `GlossaryStore.resolvedTerms(at:)` has the same silent fallback during re-transcribe carry.
- **Speaker labels (Swift).** `SpeakerLabelStore.read` returns `.empty` on `guard let data = try? Data(contentsOf: url), let obj = try? JSONSerialization.jsonObject(...)`; `setLabel`, `removeLabel`, `removeSegment(s)` read, modify and write. `RosterRename`'s per-meeting carry reads through the same `read` and calls `SpeakerLabelStore.replace`, so a roster rename can wipe a meeting's other names too.
- **Transcript corrections (Swift).** `TranscriptCorrectionStore.read` returns `[:]` on the same guard; `upsert` and `remove` read, modify and write.
- **Saved searches and workflow corrections (Swift).** `SavedSearchStore.load` and `WorkflowCorrectionStore.load` set `searches = []` / `corrections = []` in a `catch` that logs only `Log.main.warning(...)` (os.Logger, so the reason is stored redacted and never reaches `~/Library/Logs/MeetingPipe`); the next `persist()` writes the reduced list.
- **Consent (Swift).** `ConsentStore.init` sets `self.bundles = []` when `try? JSONDecoder().decode([String].self, ...)` fails, with no log, and `save()` is `try? data.write(to: url, options: .atomic)`, so the "Always for this app" allowlist can also silently fail to persist.

**Readers that silently change a summary.** `speaker_overlay.read_overlay` returns `{"labels": {}, "segments": {}}`, `transcript_corrections.read_corrections` returns `{}`, and `markers._read_marker_offsets` / `_read_segments` return `[]` on `except (OSError, ValueError)`, none of them logging. `summarize` feeds `transcript_corrections.overlaid_structured(transcript_md)` to the model, so a re-summarize with an unreadable overlay ships attendees as raw diarizer labels and misheard terms the owner already fixed, then publishes them. `glossary.load_glossary` does log a WARNING and returns an empty glossary, which is read-only and acceptable as is.

**Reachability.** Not observed on this Mac: no store warnings in `pipeline.log`, no `roster.json`, a voiceprint at `meetings=2`, and a 32-byte `glossary.toml` last written 2026-10-16 09:38 by the pane-open path. Writes are atomic (tmp plus replace), so a torn read is unlikely; the triggers are a hand edit with a syntax error, a schema change in a later build, a sync conflict copy, and, for the per-meeting sidecars in `raw/`, an iCloud-evicted file (`EDEADLK`, observed in `pipeline.log` on 2026-10-16 12:46:34 local for two `meta.json` sidecars). `~/.config` is not iCloud-synced, so `EDEADLK` does not apply to roster, voiceprint or glossary.

## Scope

One rule, applied store by store: **missing is empty, unreadable is not.** Two kinds of unreadable are handled differently, because they are recovered differently.

1. **A typed load result in each store.** Swift: `enum StoreLoad<T> { case missing, loaded(T), unparseable(Error), unreadable(Error) }` (one small generic beside the stores, not a framework), returned by `SpeakerLabelStore.read`, `TranscriptCorrectionStore.read`, `SavedSearchStore.load`, `WorkflowCorrectionStore.load`, `ConsentStore`'s init path and `GlossaryStore`'s init. Python: `RosterStore._people` and `VoiceprintStore.load` raise a `StoreUnreadable(path, errno_or_parse)` for a present file that fails, and `ENOENT` stays empty. Display-only callers keep the empty value; only writers branch on it.
2. **`unreadable` (an I/O error other than not-found, such as `EACCES` or `EDEADLK`) refuses the write.** It is retryable, and moving a valid file that merely could not be read right now would lose it. The writer throws, the surface shows "Couldn't read <file>: <reason>; nothing was changed".
3. **`unparseable` on a machine-written JSON store quarantines, then writes.** Before the first write the store renames the file to `<name>.corrupt-<UTC yyyyMMdd-HHmmss>` beside it, so the owner's data is preserved and the edit is not a dead end. Applies to roster `enroll`, speaker labels, transcript corrections, saved searches, workflow corrections and consent. The surface that triggered it says where the old file went.
4. **`glossary.toml` follows ARCH9 exactly**, because it is hand-edited TOML: `GlossaryStore` holds the parse error, `flush`, `saveNow` and `addTerm` refuse while it is set, the Vocabulary pane shows the error with the file path, and a re-read clears it, the way `ConfigStore` does.
5. **The voiceprint update skips rather than resets.** On `StoreUnreadable`, `orchestrate`'s enroll step logs, emits, and continues the run without calling `update`.
6. **Summarize refuses an unreadable overlay.** `read_overlay`, `read_corrections` and the marker readers distinguish missing from present-but-unreadable; `summarize` fails the run with exit 1 and a named cause ("This meeting's speaker names file can't be read: <reason>") rather than publish a summary without the owner's edits. A fresh recording has no overlays, so `run-all` on a new meeting is unaffected.
7. **Every refusal and quarantine is recorded.** Python emits `pipeline` `store_unreadable` with `store`, `path_kind` (not the path), `reason` (`unparseable` or the errno name) and `action` (`refused`, `quarantined`, `skipped`); Swift emits the same action under `library` (per-meeting stores) or `coordinator` (the rest), and writes a file-log line, through OBS1's `Log.failure` if it has landed and through `Log.writeLine` if not. `mp doctor` gains one WARN line per unreadable roster, voiceprint or glossary file.

## Explicitly not / out of scope

- The meta sidecar (`<stem>.meta.json`) and `workflow.read_meta`: SEC25 owns that reader and its fail-closed rule, which is a privacy decision, not a data-loss one.
- `config.toml`: ARCH9 shipped it. Workflow TOMLs and the meeting-app registry: separate readers with their own load-error surfaces, not user-data stores written back on a click.
- File mode of the roster and voiceprint writers: SEC22 routes them through `storage.atomic_write_text`; this task changes the read side and lands cleanly before or after it.
- Materializing iCloud-evicted files: STOR6 owns dataless handling. Here an evicted read is just `unreadable` and refuses.
- Library-wide readers that skip unreadable summaries (digest, MCP, prep): PIPE35, a sibling in this band.
- A `.corrupt` restore UI. The quarantined file sits beside the original with its name in the message and the event; restoring it is a Finder move.
