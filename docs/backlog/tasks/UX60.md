# UX60: regulated mode is titled "Skip Notion publish" and never says it forces every summary onto the on-device model

Filed 2026-08-03 by the audit band. Proposed high, downgraded to medium by an independent skeptic, which narrowed it to one stale README bullet plus one under-described label. Both halves are filed.

## What is wrong

The only in-app control for `modes.regulated_mode` is labelled and explained purely as a Notion switch, while flipping it also pins `effective_backend` to `local` for every meeting.

- `daemon/Sources/MeetingPipe/Preferences/PreferencesView+Permissions.swift:44` is `SettingsToggleRow("Skip Notion publish",` with an on-state sublabel at `:46` reading "On - Notion publish is disabled for every meeting."
- `:51` is the group footer, the last chance to name the consequence: "Use for client / regulated meetings. The pipeline writes summaries to disk only - no transcript or summary is uploaded to Notion." It does not mention the backend.
- `:48`'s `$store.regulatedMode` is the only write binding for that key in the whole daemon.
- `pipeline/src/mp/config.py:303-304` is `if zero_egress(cfg) and backend != "local": return "local"`, where `zero_egress` at `:282` is `cfg.modes.regulated_mode or cfg.modes.workflow_nda_mode`.
- `daemon/Sources/MeetingPipe/PipelineLauncher.swift:1013` agrees on the Swift side and strips `ANTHROPIC_API_KEY` from the subprocess.

The per-workflow sibling one pane away gets this right: `WorkflowsView.swift` titles it "NDA mode (force local backend, filesystem only)". The global control describes the same clamp as a Notion switch.

`README.md:609` states the **opposite of the code**: "`regulated_mode` does not by itself force the local backend. Set `summarization.backend = \"local\"` explicitly for the zero-egress contract." Both halves of that bullet are false, and it additionally describes a `mp doctor` warning that was replaced by an `_info` in commit 8591d186 on 2026-05-22 (`pipeline/src/mp/doctor.py:120-124`). `README.md:567` and `:90` assert the same pre-chokepoint behaviour.

## Why it matters

The owner's config has `backend = "anthropic"`. Turning this toggle on for one client call silently repoints **every** meeting to Qwen2.5-7B on-device at lower quality, with no surface saying so. If the 4.3 GB model was never fetched the run refuses outright rather than downloading, and the only thing that catches it is the menu bar's Finish setup row, because `SetupChecklist.swift:166-169` special-cases `regulatedMode`. Anyone who checks the README first is told at `:609` that this does not happen.

## Scope

Retitle the control to what it does, regulated mode or zero egress, not "Skip Notion publish", and make its sublabel and footer state both halves: Notion is skipped, and summarization is forced onto the on-device model whatever Preferences, Pipeline says. Match the honesty of the per-workflow NDA label that already gets this right.

Surface the model-missing case inline in that group rather than only in the menu bar's Finish setup row.

Fix `README.md:609`, `:567` and `:90`, and drop the reference to a doctor warning that is now an `_info`.

## Acceptance

Suite green with new tests where the copy is pure. The control's title and footer name the backend clamp. A test pins that the Preferences string and `config.effective_backend`'s clamp cannot drift apart, in the shape `SpeakerAccuracy`'s table already uses. The three README bullets are corrected in the same commit.
