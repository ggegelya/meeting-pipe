# T20: The corpus redaction check is closed-vocabulary only for lifecycle traces, so promotion traces (33 of 41 committed) pass with arbitrary free text

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) G021. Re-read in code at HEAD on 2026-11-13.

**What the gate checks per engine.** `scripts/redact_detection_trace.py`'s `validate()` does three things. For `engine == "promotion"` it loops over `events` and rejects a `kind` outside `SIGNAL_KINDS` and `CONTROL_KINDS`; nothing else. For `engine == "lifecycle"` it calls `validate_lifecycle`, which rejects any top-level key outside `LIFECYCLE_KEYS`, closes the per-kind host keys (`HOST_KINDS`), and requires `logged_verdicts[].leading` and `confirmed_by` to match `TOKEN` (`^[a-z][a-z0-9_]*$`). For `micgate` it checks only the engine name. `scan_pii` flags only `EMAIL`, `URL` and `MENTION` matches, and `needs_redaction` only a real pid or a `TITLE_KEYS` value.

**So a promotion trace accepts:** unknown top-level keys, unknown `context` and event keys, a free-text `description`, a free-text `scenario`, and free text in `expected_verdicts[].leading` (lifecycle's `TOKEN` check is not applied to promotion verdicts). Executed on 2026-11-13 against a scratch file: a promotion trace whose `description` named a person and a company, with a top-level `notes` key, an event `label`, and a `leading` holding a person's name, gave `OK: trace is redacted and schema-valid.` and exit 0 from `--check`. Re-run 2026-11-14 on a copy of `teams_native_debounce_end_02.json` with a free-text `scenario`, a person and company in `description`, a top-level `notes` key, an unknown `context` key, an event `label` and a name in the last verdict's `leading`: same `OK` and exit 0.

**Why it matters.** `pipeline/tests/test_detection_trace_scripts.py`'s `test_every_committed_corpus_trace_passes_the_strict_check` runs the strict check over every committed trace, and is the only gate between a hand-curated trace and the public repo. The corpus has 41 traces: 33 `promotion`, 5 `lifecycle`, 3 `micgate` (counted 2026-11-13). The corpus `README.md` rule "No free text, anywhere" is enforced for none of the 33. The keys the committed promotion traces actually use are few: top-level `scenario`, `description`, `engine`, `context`, `events`, `expected_verdicts`, `expected_outcome`; `context.bundle_id`, `kind`, `pid`; events `t`, `kind`, `state`, `rewalk_signal`; verdicts `after`, `verdict`, `leading`, `confirmed_by`.

Correction at filing: lifecycle traces have a closed key set but not a closed `description`; `LIFECYCLE_KEYS` includes `description` and `validate_lifecycle` never inspects its text, so the free-text half of this applies to every engine. Every committed `description` is hand-written English prose of 125 to 916 characters (the longest is `webex_ultrasound_retention_en.json`; three `teams_native_debounce_end_*` traces sit at 435), so a pure token charset would reject all 41 and the bound has to admit prose up to at least 916. The corpus `README.md` names "a `label`" as an allowed human-readable string; correction at filing (2026-11-14): the audit's premise that `label` is unused is wrong, since the three micgate traces carry `states[].label` values, all snake_case tokens (`muted`, `hot_vad`, `silent_default`, `hardware_mute_dominates`), and the README's micgate example shows one. No promotion or lifecycle trace carries a `label`.

Related: [T8](./T8.md) (`owner-verify`) added the lifecycle schema and the strict `--check`; C6-FINISH (done, [q6-final.md](../q6-final.md)) built the promotion gate as signal kind plus email, URL and @-mention. Neither covers this.

## Scope

All in `scripts/redact_detection_trace.py`, stdlib only like the rest of the script.

1. **Close the promotion schema** in a `validate_promotion`, mirroring `validate_lifecycle`: reject top-level, `context`, event and `expected_verdicts` keys outside the sets listed in Context, and require `expected_verdicts[].leading` and `confirmed_by` to be `TOKEN`s.
2. **Make `scenario` a `TOKEN`** for every engine (every committed one already is, for example `google_meet_browser_clean_leave`).
3. **Bound `description`** for every engine: a length cap that admits the 916-character longest committed one, and reject a capitalised word that is neither the first word of a sentence nor allowed. The committed descriptions use 26 distinct capitalised non-initial words (counted 2026-11-14), and they are not only product names: product words and two platform-vendor names (Teams, Zoom, Meet, Webex, Chrome, SlimCore, PWA), acronyms (AX, HAL, VAD, RMS, GAP, PRIMARY), task IDs (END9, END17), code symbols (`CallTeardownHoldTests`, `ProcessAudio`, `ShareableContent`, `UnregisterCall`) and language names (English, German). So the rule is a short word allowlist plus patterns for all-caps tokens, task IDs and CamelCase symbols, derived from the 41 committed descriptions and kept beside `SIGNAL_KINDS` with a one-line reason. This catches a person's or company's name in prose; it is a heuristic, not a guarantee.
4. **Narrow the README's `label` wording** to what it is: a snake_case token on micgate `states[]` only, never on a promotion or lifecycle event, in the same commit. The closed promotion set rejects an event `label`.

## Explicitly not

- The micgate schema. Its keys are as open as promotion's, and `needs_redaction` exempts it because its `ax_label` is the mute button's own label. Observed, not filed here; fold it in only if the closed set falls out for free.
- Re-extracting or rewriting the committed traces beyond what the new check forces; if a committed description trips item 3, reword that description and name it in the commit body.
- Detecting names by NER or a dictionary: no new dependency.

## Acceptance

- New tests in `pipeline/tests/test_detection_trace_scripts.py`: the 2026-11-13 trace (a person's name and a company in `description`, a `notes` key, an event `label`, a name in `leading`) fails `--check` with one error per defect; an unknown `context` key fails; a non-token `scenario` fails for each engine; a lifecycle trace with a capitalised name in `description` fails; each committed product word in the allowlist passes.
- `test_every_committed_corpus_trace_passes_the_strict_check` stays green over all 41 committed traces.
- `cd pipeline && uv run --extra dev pytest -q` and `uv run --extra dev ruff check src tests` green, with the number of tests added in the commit body; `bash scripts/ci-local.sh fences` green.
