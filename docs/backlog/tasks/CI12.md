# CI12: neither the pipeline's security lint rules nor any shell-script linter runs in CI

Band origin: filed 2026-11-12 from the static-analysis (SAST) pass that followed the [2026-11-12 security review](../../audits/2026-11-12-security-review.md). The owner approved filing with "File all proposed". Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

The security review's "Checked and clean" list (no `shell=True`, no pickle, `yaml.load`, `eval` or `exec`) was established by reading the code. Nothing in CI keeps it true. On 2026-11-12 the SAST pass ran the candidate gates ephemerally against `f2d65038`, with no repo change.

**ruff `S` (flake8-bandit).** The locked ruff 0.15.12, run as `ruff check src --select S`, gives 14 hits:
- S603 x7 and S606 x1: list-argv subprocess and exec calls, for example `config._keychain_get` running `/usr/bin/security`, and `serve-local`'s `os.execvpe`;
- S607 x2: bare `lsof` and `mdfind`, which [SEC17](./SEC17.md) owns;
- S101 x3: `assert last_err is not None` after the provider retry loops;
- S110 x1: `events.emit_progress`'s deliberate best-effort `except Exception: pass`.

All 14 were triaged as not defects. With `--ignore S603,S607,S606,S101,S110,S404` the residual is 0. bandit 1.9.4 on the same tree found the same set and nothing more, so bandit adds nothing over ruff.

**shellcheck.** 0.11.0 (via `uvx --from shellcheck-py`), default severity, over `scripts/*.sh`, `scripts/lib/*.sh` and `scripts/pre-commit`: 8 hits, all `note` level and all intentional:
- SC2015 x6: the `ok`/`fail` helpers in `test-prune-worktrees.sh`;
- SC2016 x2: a literal `$PATH` in `install.sh`, and a jq program in `tail-events.sh`.

At `-S warning` these give 0 hits. The two tracked probe scripts under `daemon/scripts/` give 1 warning: SC2164, an unchecked `cd "$WORK"` in `auto1-app-intents-probe.sh`.

Why it matters: `prune-worktrees.sh` deletes directories, and `install.sh`, `rebuild.sh` and `lib/dev-cert.sh` touch the keychain and `~/Applications`. An unchecked `cd`, an unquoted path or a mistyped variable there is the class of bug that once swept a live worktree on 2026-07-24.

[TYPE2](./TYPE2.md) (open, P2) widens the same `select` list (`B A PIE SIM RUF100 I UP`) but does not include `S`, and its own rule is that a wider family is "a deliberate commit". This is that commit for `S`.

## Scope

1. **ruff `S`.** In `pipeline/pyproject.toml` `[tool.ruff.lint]`, add `"S"` to `select`, and add `ignore` entries for S603, S607, S606, S101, S110 and S404, one comment line each with the reason:
   - S603, S606: argv lists, never a shell;
   - S607: owned by SEC17;
   - S101: the retry-loop invariants;
   - S110: best-effort progress;
   - S404: importing `subprocess` is not a finding.

   No `ci-local.sh` change is needed, since the existing "Pipeline: ruff" step picks it up. If TYPE2 lands first, append to its list. If this lands first, TYPE2 appends to this one. Either order is a one-line rebase.
2. **shellcheck.** A new `ci-local.sh` step, `begin "Shell scripts: shellcheck (CI12)"`, running `shellcheck -S warning` over every tracked shell script, taken from `git ls-files` so a new script is covered without editing the list. Today that is `scripts/*.sh`, `scripts/lib/*.sh`, `scripts/pre-commit` and `daemon/scripts/*.sh`.
   - Put it in the job that runs on `ubuntu-latest` without a toolchain (beside the truth fences), where `shellcheck` is preinstalled on the hosted image.
   - When `shellcheck` is missing locally, fail early with a message naming the fix (`brew install shellcheck`, or `uvx --from shellcheck-py shellcheck`), per the root `CLAUDE.md`'s missing-prerequisite rule. Do not skip silently.
3. Fix the one warning, `cd "$WORK" || exit 1` in `daemon/scripts/auto1-app-intents-probe.sh`, so the step starts green.
4. Update the root `CLAUDE.md` verify table only if a row's command changes. Name the new step in `CONVENTIONS.md` wherever it lists what CI enforces. Ask before adding shellcheck to any install docs, since it is a contributor tool, not an owner prerequisite.

## Explicitly not / out of scope

- **semgrep:**
  - its registry rules need network on every run;
  - a 27-hit run had 0 survivors;
  - `p/bash` does not exist in the registry, and `p/swift` is 2 rules.
- **bandit:** duplicates ruff `S`.
- **pyright strict on the security modules:** 140 diagnostics, all `reportUnknown*` on JSON-shaped dicts. TYPE2 already defers strict.
- **gitleaks or any secret scanner:** the history is clean, and it is a new dependency for little signal today.
- **shellcheck at default severity:** the 8 notes are intentional, and gating on them means 8 disable comments with no defect behind them.
- **The Swift warning gate:** [CI9](./CI9.md). **Complete concurrency checking:** [CONC6](./CONC6.md).

## Amendment 2026-11-13 (audit band)

From the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md), finding F153 (security, confirmed). [SEC31](./SEC31.md) (P1) owns the lock refresh that clears today's advisories; the audit found that a recurring check, which would catch the next one, is in neither SEC31 nor this task. Re-verified at HEAD on 2026-11-14:

- `pipeline/uv.lock` holds 103 `[[package]]` entries, the project plus 102 locked packages, and still pins `certifi` at `version = "2026.4.22"`, the bundle SEC31 shows every Anthropic, Notion and OpenAI client trusts. OSV lists advisories against 13 of the 102 (SEC31 counted 121 rows across those 13 on 2026-11-12).
- `scripts/ci-local.sh`'s `pipeline` job is `uv sync --frozen --extra dev --extra mcp`, ruff, pyright and pytest. No step reads an advisory database.
- `.github/dependabot.yml` runs weekly version updates for the `uv` ecosystem, and its header says "security updates are switched on in the repo settings". That is the only mechanism that notices a new advisory, and it opens a PR rather than failing a gate. Its `ignore` rules hold `anthropic` and `httpx` below 1 and `huggingface-hub` below 2, so an advisory fixed only above one of those caps may get no PR at all.

### Added scope

5. A new step in `ci-local.sh`'s `pipeline` job, `begin "Pipeline: dependency advisories (CI12)"`, after the install, running the pipeline SEC31 used on 2026-11-12: `uv export --frozen --all-extras --no-hashes --no-emit-project` piped to `pip-audit --no-deps`. It fails on any advisory not on an allowlist file kept beside the script, one advisory id per line with the package, why it is unreachable, and the date it was accepted. The step rejects an allowlist line with no reason.
6. Network: the `pipeline` job already reaches PyPI in `uv sync --frozen`, so the step adds no new network dependency to the CI job. Locally, when the advisory database cannot be reached, the step fails with a message naming the network as the cause, per the root `CLAUDE.md` missing-prerequisite rule; if the owner prefers warn-only locally and fatal on CI, record that choice in the script.
7. pip-audit is a tool, not a runtime dependency, but it is new to the repo, and the root `CLAUDE.md` says "Don't add dependencies without asking first". Ask the owner, then either run `uvx pip-audit` at an exact pinned version or add it to the `dev` extra so `uv.lock` pins it.
8. Ordering with SEC31: land after it, or start the allowlist with the 13 packages SEC31 flagged, each with "SEC31" as the reason, and remove them when SEC31 ships (the shape CI9 uses for CONC11's warnings).
