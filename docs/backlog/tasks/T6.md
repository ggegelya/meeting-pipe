# T6: the pipeline suite stubs the orchestrator's own collaborators because run_all takes none, and production events.py asks whether pytest is imported

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([architecture review](../../audits/2026-10-24-architecture-review.md) P2, with go-live QG-8 and harness #3 as the named adjacencies). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Re-counted on 2026-10-24: `monkeypatch.setattr` appears 269 times across `pipeline/tests`, plus 44 `unittest.mock.patch("mp. ...")` calls. The most-patched targets are `digest.engine` and `ask.engine` (13 each), `ask.Config` (11) and `"mp.diarize.is_stereo_recording"` (11); the review counted 17 patches on private names (`_free_disk_gb`, `_bytes_on_disk` and similar).

The orchestrator is the clearest case. `test_orchestrate.py` replaces `mp.orchestrate.summarize` 16 times and `mp.orchestrate.publish_fanout` 14 times (for example `_run_with_publish_result`), so the tests that are meant to pin `run_all`'s wiring stub out the two things it wires. The reason is the signature: `run_all(wav, cfg=None, *, force_byo=None, backend=None)` accepts no collaborator, although both callees already take one. `summarize(transcript_md, cfg=None, *, client: SummaryClient | None = None, ...)` and `publish_router.fanout(..., publishers: list[MeetingPublisher] | None = None)` exist, and `services.py` says its protocols are there so that tests "inject in-memory fakes instead of mocking httpx / anthropic". `run_all` is the one caller that does not let them.

What that costs: `test_run_all_threads_backend_override_to_summarize` asserts `s.call_args.kwargs["backend"] == "local"` on a mock, so it pins the call rather than the outcome, and a defect between `run_all` and the real `summarize` (an argument dropped, a result key renamed) passes every orchestrator test.

Test logic in production: `events._running_under_tests()` returns `"PYTEST_CURRENT_TEST" in os.environ or "pytest" in sys.modules`, and `events.logs_dir()` redirects to a temp dir when it is true. Production behaviour therefore depends on which modules happen to be imported. `logs_dir()` already honours `MEETINGPIPE_LOGS_DIR` first, so the suite can own its isolation in `conftest.py` instead.

## Scope

1. `orchestrate.run_all` gains keyword-only `summary_client: SummaryClient | None = None` and `publishers: list[MeetingPublisher] | None = None`, forwarded to `summarize(client=...)` and `publish_fanout(publishers=...)`. `None` keeps today's resolution exactly, and `orchestrate.main` never passes either. If PIPE19 (one provider table) lands first, the seam takes a provider from that table instead of a bare client; otherwise PIPE19 replaces this seam when it lands.
2. `tests/conftest.py` gains a `FakeSummaryClient` (returns a fixed `MeetingSummary`, records `system_prompt` and `transcript`) and a `RecordingPublisher` (records each `upsert`, returns a configured result or raises a configured error), plus an autouse fixture that sets `MEETINGPIPE_LOGS_DIR` to the test's `tmp_path`.
3. Delete `_running_under_tests` and its branch in `events.logs_dir`. The conftest variable replaces it for pytest; the Swift suite's Python children already receive the variable (`FailureProcessTests` passes `"MEETINGPIPE_LOGS_DIR": dir.path`).
4. Migrate every `patch("mp.orchestrate.summarize")` and `patch("mp.orchestrate.publish_fanout")` site in `test_orchestrate.py` to the two fakes. Event assertions read the tmp logs dir rather than patching `mp.orchestrate.events.emit`. Other test files migrate when they are next touched, not here.

## Explicitly not / out of scope

- A sweep of all 269 patches. Most patch a genuine boundary (subprocess, the clock, physical RAM) and are fine.
- A ratchet on the monkeypatch count. A numeric rule is the Goodhart shape HYG10 is removing elsewhere; the migration in item 4 is the measurable part.
- Changing `summarize` or `fanout` signatures, the provider table (PIPE19), or the Anthropic client factory (PIPE24).
- The live contract test for the default cloud call (T10, go-live QG-8).
- The other writers that bypass `logs_dir()` (`orchestrate._configure_logging`, `local_server.marker_path`): that is T9. The two interact: once this task removes the `sys.modules` redirect, T9's fixes and the conftest variable are the whole isolation story, so a test that calls `monkeypatch.delenv("MEETINGPIPE_LOGS_DIR")` and then emits would write to the real log. Item 4's tests must not do that, and T9's real-log check catches it if one does.

## Acceptance

- New tests drive `run_all` end to end with the two fakes: a normal run writes `<stem>.summary.json` and the publisher saw that path; an all-sinks-failed `RecordingPublisher` yields `publish_failed: True` and a `run_failed` row with `stage: "publish"` in the tmp `pipeline_events.jsonl`; a raising `FakeSummaryClient` yields `run_failed` at the summarize stage.
- `grep -c 'patch("mp.orchestrate.summarize"\|patch("mp.orchestrate.publish_fanout"' pipeline/tests/test_orchestrate.py` is 0.
- `pipeline/src/mp/events.py` contains no `sys.modules` check. `test_events.py`'s pytest-redirect test is replaced by one asserting the conftest fixture set the variable, and one asserting `logs_dir()` with the variable unset resolves the production path (without writing to it).
- `cd pipeline && uv run --extra dev ruff check src tests`, `uv run --extra dev --extra mcp pyright` and `uv run --extra dev pytest -q` green, with the number of new tests in the commit body; `bash scripts/ci-local.sh pipeline` green.

## Amendment 2026-11-13 (audit band)

Added from the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) low F198 (listed as unverified there), re-verified at HEAD on 2026-11-13.

**The isolation test cannot fail on its own.** `test_events.test_emit_under_pytest_writes_outside_production` calls `events.emit("test", "tick", stem="x")` and then asserts `events._events_path().parent != PRODUCTION_LOGS`. That re-asks the path helper rather than observing where `emit` wrote, so it fails only if `test_logs_dir_under_pytest_never_touches_production` above it already fails, and a writer that opened a hard-coded `~/Library/Logs/MeetingPipe` path itself would pass it. This is the shape T9 found in `orchestrate._configure_logging`.

**Added scope.** When item 3 replaces the `sys.modules` sniff with the conftest `MEETINGPIPE_LOGS_DIR`, the replacement test emits a row with a unique marker and asserts that marker is in `tmp_path / "pipeline_events.jsonl"`, and (read-only) that the production `pipeline_events.jsonl`, if present, has the same size and mtime before and after. (F198)

**Added acceptance.** The new test fails when `emit` is patched to write to a second, hard-coded directory (tried and reverted, said in the commit body).
