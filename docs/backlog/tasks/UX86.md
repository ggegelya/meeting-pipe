The words a user reads include implementation vocabulary the app's own glossary already translates:

- **"sink"**: `SummaryTab` ("publish it through your sinks", "push it to your sinks"), `MeetingRow` help ("at least one sink failed"), three `MeetingDetailView+Header` alerts, `BatchActionsPane`'s republish hint, `WorkflowsView`'s LAN sublabel.
- **Engine and file internals**: "FluidAudio" and "Parakeet TDT" in the Pipeline caption and language sublabel, "mlx_lm.server" and "HuggingFace MLX repo id" in the local-model rows, "TCC" in the Permissions caption, an **Open meta.json** button in `MeetingDetailView+Header`, "Used by mp doctor" in Advanced, "Record (BYO)" in the detection prompt's menu.
- **Recorder copy (PD-15)**: `MeetingRecorder.RecorderError.errorDescription` surfaces as the start-failure toast: "Audio engine failed to start: installTap raised on the input node twice; the audio engine was replaced", "Could not create output WAV: ...", "Recorder already in progress". REC15 fixed the race behind the first one, not its wording.

**The doctor is a terminal in a window.** `PreferencesView.doctorSheet` renders `doctor.output` as one monospaced `Text` in a `ScrollView`, with Re-run and Close. It is the troubleshooting surface SETUP.md and GUIDE.md send a non-programmer to ("Run doctor…"), and it reads like `mp doctor` because it is `mp doctor`'s stdout plus `DoctorCommand`'s lines.

GUIDE.md's "The words this app uses" already pairs the terms: "Backend, or engine", "Sink, or destination", "Roster, or your saved voices", "BYO" as "Bring your own summary". The app's strings never adopted the plain half.

## Scope

1. **One vocabulary, chosen first.** Before any string changes, the owner confirms the plain term per word. Proposed from the glossary and the go-live list: backend to engine (or summary engine), sink to destination, daemon to MeetingPipe (or "the app"), TCC dropped ("macOS permissions"), BYO to "Record without a summary", meta.json to "Show meeting files in Finder". Workflow, roster and regulated mode renames are listed for the owner but are not assumed, because they rename sidebar sections and Preferences panes and touch UX87.
2. **Replace in user-facing strings only.** Config keys, `WorkflowBackend` / `WorkflowSink` case names, event names, log lines and `CONVENTIONS.md` stay as they are. "Applies on the next daemon launch" becomes "after MeetingPipe restarts". Engine product names (FluidAudio, Parakeet, mlx_lm, HuggingFace) leave captions; the local-model id field keeps its value but its sublabel explains what it is in plain words.
3. **Recorder toasts in the user's terms.** `RecorderError.errorDescription` says what happened and what to try ("The microphone could not be started. Try again, or pick another input in System Settings ▸ Sound."); the technical reason moves to the log line and the failure details, which `FailureNotice`'s Details sheet already carries.
4. **The doctor sheet shows results, not stdout.** Parse the doctor output into rows (pass, warning, failure, with the fix line) and render them as a list with status pills; keep the raw text behind a "Show details" disclosure and the copy button, so nothing diagnostic is lost. If `mp doctor` has no stable line format to parse, add a `--json` mode that both renderers read (the `mp restore --dry-run --json` precedent in CONVENTIONS.md), and say which was chosen in the commit body.
5. **GUIDE.md, SETUP.md and README in the same commit** wherever they quote a renamed control, and the glossary entries flip so the plain word leads.

## Explicitly not / out of scope

- Rearranging Preferences panes or moving rows: UX87. This task changes words in place.
- Workflow routing's bundle-id and regex fields: UX88.
- The language-pin copy ("a fixed code skips detection"), which is false as well as technical: UX85.
- The stop message that blames the disk at the WAV ceiling: REC19.
- Renaming code identifiers or config keys to match. A user-facing rename that drags a contract change is the wrong trade.
- A lint that bans the words from string literals. Worth considering once the vocabulary settles; a fence written before the owner picks the words would encode the wrong ones.
