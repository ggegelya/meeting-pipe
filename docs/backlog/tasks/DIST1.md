# DIST1: Bundle a runtime for a drag-n-drop installer

Band origin: carried from Q4; base spec in q4-final.md, progress notes here. Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

**DIST1 (P2, partial): bundle a runtime for a drag-n-drop installer.** Base spec in [`q4-final.md`](../q4-final.md) (search the id). **Progress (2026-07-12): daemon plumbing + build tool + runbook shipped; the notarized bundle build + clean-Mac test are owner-owed.** Design + runbook: [`docs/spikes/dist1-bundle-runtime.md`](../../spikes/dist1-bundle-runtime.md). The problem is that a clean Mac has no Python 3.11+ and the install needs Homebrew + uv + ffmpeg (and locked-down regulated Macs often cannot install Homebrew at all, the exact zero-egress target). Approach: embed a relocatable python-build-standalone (`install_only`, no baked rpaths) + the pipeline wheels + a static ffmpeg under `Contents/Resources/pipeline-runtime/`. **Shipped + tested:** `PipelineLauncher.findMP` now prefers the embedded runtime and runs it as `python3 -m mp` (NOT the `bin/mp` console script, whose pip-baked absolute shebang breaks when the .app is relocated to /Applications, the crux relocation gotcha), extracted into a pure injected `resolveDirectMP` with 4 `PipelineLauncherFindMPTests` pinning the priority (embedded > venv > uv > PATH); `MeetingRecorder.findFFmpeg` falls back to `pipeline-runtime/bin/ffmpeg` after PATH, covering the recorder merge and `MuteRedactor`. The build tool `scripts/bundle-runtime.sh` fetches the runtime, `pip install`s the pipeline into it, verifies `python3 -m mp --version`, installs a static ffmpeg (owner pins an LGPL/GPL-compliant `FFMPEG_URL`), and signs every embedded mach-O inside-out (a notarization prerequisite). 1224 daemon green. **Reconciliation:** DEP1 (GO on native AVFoundation merge/transcode) does not remove ffmpeg because `MuteRedactor` is a third spawn site out of DEP1's scope, so a static ffmpeg is still bundled (the `findFFmpeg` fallback makes dropping it later a no-op); I7 (drop Python) is the strategic fork DIST2 recommended deferring, and bundling now buys a shippable clean-Mac install without betting on the port. Owner-owed remainder (needs Developer ID creds + a second clean Mac, neither here): run `scripts/bundle-runtime.sh` with a real `CODESIGN_IDENTITY` + `FFMPEG_URL`, notarize (`notarytool submit --wait`) + staple, package a .dmg, and drag-install-test on a clean Mac confirming (via `events.jsonl`) the pipeline ran entirely from the bundle. D8 is the durable CI home for the notarize step once a second user exists.

## Amended 2026-10-24 (audit band)

Added from the [go-live assessment](../../audits/2026-10-21-go-live-assessment.md) DI-4 and DI-5, verified against `scripts/bundle-runtime.sh` and the daemon on 2026-10-24. Neither was listed in this spec. They do not change the owner-owed legs above; they are defects the session leg must fix before step 2 of the walkthrough can produce a bundle worth notarizing.

**Already fixed, so not part of this amendment.** DI-4's headline, that the tool installs dependencies without the lock and would ship anthropic 2.x, was fixed by CI8: `bundle-runtime.sh` now runs `uv export --frozen --no-dev --extra mcp --no-emit-project`, installs that with `pip install --require-hashes`, and installs the pipeline itself with `--no-deps`.

**DI-4: the tool still cannot produce a shippable bundle as written.**

1. **The default Python URL does not exist.** `PBS_TAG` defaults to `20250612` and `PYTHON_VERSION` to `3.11.9`. That release has no 3.11.9 asset: on 2026-10-24 the default `PBS_URL` returned HTTP 404 and the same tag's `cpython-3.11.13+20250612-aarch64-apple-darwin-install_only.tar.gz` returned 200. A run with defaults dies at `curl -fL` before doing anything. Pin a pair that exists, and have the tool check `uv.lock`'s `requires-python` (`>=3.11, <3.13`) against the version it fetches.
2. **Hardened runtime with no entitlements.** Every leaf and the app are signed `--options runtime`, and no entitlements file exists anywhere in the repo. Under the hardened runtime, microphone capture needs `com.apple.security.device.audio-input` (Apple's resource-access entitlement), so a bundle signed this way should lose its mic; not measured here, and the clean-Mac test in step 4 is where it would show. Add an entitlements plist with audio input and pass it to the app's `codesign`. Whether the embedded Python and the MLX extension modules also need `com.apple.security.cs.disable-library-validation` or `allow-unsigned-executable-memory` is unknown until notarized; record what step 3 finds.
3. **Leaf signing failures are swallowed.** The inside-out loop runs `codesign ... "$f" 2>/dev/null || true`, so an unsigned leaf surfaces only as a notarization rejection after upload. Fail the build on a leaf that does not sign, and finish with `codesign --verify --deep --strict` on the app.
4. **It re-signs the owner's live install with an ad-hoc identity.** The tool defaults `--app` to `~/Applications/MeetingPipe.app` and `CODESIGN_IDENTITY` to `-`, and modifies that bundle in place. Run with defaults, it replaces install.sh's stable "MeetingPipe Dev" signature (`sign_app_with_resources`) with an ad-hoc one, which install.sh's own comments say makes the Screen Recording grant cdhash-strict again. Build into a copy (a staging path, the `test-app-relocation.sh` pattern) and refuse an ad-hoc identity unless a flag says this is a local trial.
5. **`pip install --upgrade pip` fetches an unpinned pip** from the network into the bundle before the hash-checked install. Pin it, or skip the upgrade.
6. **The app it starts from is a dev build.** It assumes an app made by install.sh, whose `Info.plist` is install.sh's heredoc (version 0.1.0 build 1, `LSMinimumSystemVersion 13.0`). DOC16 and DIST6 change that heredoc; this tool should take the plist from the same source rather than inherit whatever the last install wrote.

**DI-5: a drag-installed app has nothing that does install.sh's other two jobs.**

- **No login agent.** The only writer of `~/Library/LaunchAgents/com.meetingpipe.daemon.plist` is install.sh's step 6. `LaunchAtLoginService` reads and toggles that agent but never creates it, and on `.notInstalled` the Preferences footer says "No launch agent is installed, so nothing starts MeetingPipe at login. Run scripts/install.sh." A user with only the app gets that sentence. The bundle needs an app-owned way to install the agent: either Preferences ▸ General writes the plist from a template carried in the bundle (pointing at the running bundle's path), or, with a Developer ID, `SMAppService`, which UX42's comment in `LaunchAtLoginService` already names as the D8-era option. Either way the UX42 rule holds: one writer, and a disabled toggle is never re-armed.
- **No model prefetch.** install.sh runs `MeetingPipe prefetch-models` (FluidAudio, about 630 MB). Without it the first recording downloads the models at stop time (the lazy path install.sh's comment names), so the first meeting's transcript waits on a download of about 630 MB. The bundle needs an in-app download with progress before the first recording, the shape UX21 already built for the local summarizer (`LocalModelPreflight`, the menu bar's progress row), started from onboarding (UX84's test step is the natural place to require it).

**Not in this amendment.** ffmpeg in the bundle: DEP2 removes the need, and with it `FFMPEG_URL` and its licensing step. Version stamping: DIST6. The installer's own relaunch and uninstall defects: DIST5. Hardened runtime for the from-source install: SEC17.

**Acceptance added by this amendment.** A run of `scripts/bundle-runtime.sh` with defaults either succeeds on a staging copy or refuses with a named reason, and never touches `~/Applications/MeetingPipe.app`; a leaf that fails to sign fails the build; the signed app carries the audio-input entitlement (`codesign -d --entitlements - <app>`); a drag-installed app with no LaunchAgent can turn Launch at login on from Preferences, and a first launch offers the speech-model download before the first recording.
