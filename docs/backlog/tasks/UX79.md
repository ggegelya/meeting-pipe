# UX79: the menu reads "MeetingPipe: Idle" and offers an inert Start Recording for the whole of a stop

Band origin: filed 2026-08-18. ARCH6 corrected T3's archive claim on the same day and recorded this as unfixed rather than quietly fixing it, because the fix changes what the menu says and shows mid-stop and ARCH6's own acceptance forbade user-visible change. Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## What the archive claimed, and what is actually there

T3's body in [`q6-final.md`](../q6-final.md) said that deriving the menu header from the real state "makes the author's own case live". ARCH6 corrected that sentence in place on 2026-08-18 and it now reads: "`setStopping` still passes `.idle` to `rebuildMenu`, so the header still reads `MeetingPipe: Idle` through a flush and `headerLabel`'s `.stopping` branch is still reached only from tests ... It is a live, unfixed, one-to-several-second truthfulness defect in the always-visible surface, not a shipped fix."

That correction is right and the code says so in three places, each of which documents the split as deliberate:

- `StatusBarController.setStopping(file:source:summaryMode:)` sets `titleState = .stopping(...)`, applies the icon and title, then calls `rebuildMenu(state: .idle)` under the comment "Deliberately `.idle`, not `titleState`: the menu built during a flush is the idle one (its header and its Start row), which is what has always shipped."
- `StatusBarController.titleState`'s own doc: "Deliberately NOT `lastMenuState` ... Collapsing the two would change what the menu says mid-stop, so they stay apart and the difference is stated here rather than left to be rediscovered."
- `StatusBarController.menuInputs(state:finishSetupTitle:)`: "`state` is a parameter rather than a read of `lastMenuState` because `setStopping` passes `.idle` here on purpose while the title says 'Stopping…'."

So the menu-bar **title** reads "Stopping…" (`StatusBarModel.title`'s `.stopping` case) while the **menu header** one click away reads "MeetingPipe: Idle" (`headerLabel`'s `.idle` case, because `.idle` is what it was handed). `headerLabel`'s `.stopping` branch returns `"MeetingPipe: Stopping…\(suffix)"` and is reached only by `StatusBarModelTests`.

## The half nobody recorded: the row it offers does nothing

Measured for this filing on 2026-08-18 against `b122e00`. The archive names the Start row as a *cost* of fixing this ("the `.idle` menu also carries the Start row"). Traced through, it is an argument for the fix rather than against it.

`StatusBarModel.rows(_:)` switches on the state it is handed. On `.idle` it appends `.startRecording`; on `.recording` it appends `.stopRecording`; everything else takes `default: break`, and the comment beside it already states the intended answer: "`.stopping` is a genuine no-op mid-flush." Being handed `.idle`, it appends Start Recording.

That row's action is `Coordinator.menuStart()`, which is `session.toggleManual()`. `MeetingSessionController.toggleManual()`'s `.stopping` case is:

```swift
case .stopping:
    // Mid-flush; a new start would race the await.
    break
```

**So the Start Recording row the menu offers throughout a stop is inert.** Clicking it does nothing, says nothing, and logs nothing. The model already knows `.stopping` should carry no transport row; the controller withholds the state that would apply that knowledge.

## The window is not always a second or two

The `.stopping` window runs from `setStopping` inside `MeetingSessionController.stopRecording(file:source:summaryMode:)` to `statusUI.setIdle()` after `await recorder.stop()` and the merge, so its length is the length of the post-processing, which scales with the recording rather than being constant.

It has been very long once. REC13's watchdog sits in that exact window and its comment records why: "REC13(4): 52 minutes in `.stopping` produced no event and no notification on 2026-08-14, so the only symptom was a Library row that never settled." REC13 bounded every engine call inside `stop()` and armed `StopStallWatchdog`, so a repeat should be rare, but the honest reading is that the header lied and offered a dead control for 52 minutes on a real recording, not for a second or two.

That is the difference between this being cosmetic and being worth a row: on the normal path it is a brief lie in an always-visible surface, and on the abnormal path it is the only surface a user consults, saying the opposite of what is true.

## The question this task exists to answer

Should the menu header and its row set follow the stopping state, and what does the user see if they do? ARCH6 could not answer it inside a green-to-green task, so it is asked here rather than assumed.

Three routes, none pre-selected, with what each does to the visible menu:

**Route A, pass `titleState` to `rebuildMenu`.** Header reads "MeetingPipe: Stopping…", `rows(_:)` takes its `default: break`, and the menu has **no transport row at all** during the flush. The inert Start disappears, which is the correct behaviour and is what `rows(_:)`'s comment already says it wants. The open question is whether a menu with no transport row reads as finished or as broken, which is a judgement about a surface a session cannot screenshot.

**Route B, split the header from the rows.** The header follows `titleState` while the rows keep `.idle`. Smallest visible delta and the header stops lying, but it leaves the inert Start row exactly where it is, so it fixes the sentence and not the control. Only worth taking if route A's empty transport section is judged worse than a dead row.

**Route C, a `.stopping` row.** Header reads "Stopping…" and the transport slot carries a disabled row saying so, so the section is neither dead nor empty. Most work, and it is the one route that needs new copy, which means reading `docs/GUIDE.md` first per the root `CLAUDE.md` same-commit contract.

**Whatever is chosen, `headerLabel`'s `.stopping` branch stops being test-only or is deleted.** Leaving a branch that only tests reach is CI6's exact finding class, so "leave it alone" is not a free outcome: it costs either the branch or a written reason for keeping unreachable code.

## Scope

The seam is one line, `rebuildMenu(state: .idle)` inside `StatusBarController.setStopping`, plus whatever the chosen route needs in `StatusBarModel.rows(_:)` and `headerLabel(_:)`.

Land the decision, pin it with tests, and correct T3's body in `q6-final.md` so the archive stops describing a live defect that is no longer live. That last item is small and load-bearing: ARCH6 already rewrote that sentence once, and leaving it saying "unfixed" after the fix recreates the doc-truth defect DOC12 and HYG6 spent a batch clearing.

## Explicitly not / out of scope

**The menu-bar title.** `StatusBarModel.title`'s `.stopping` case is correct today and stays. This task makes the header agree with the title, not the other way round.

**`toggleManual`'s `.stopping` no-op.** It is right: a start mid-flush would race the await, and the comment says so. The defect is offering a control for it, not the guard behind it.

**The stop path, the flush duration, and the stall watchdog.** REC13 shipped all three on 2026-08-17. Nothing here tries to make the window shorter, and a fix that only helps because the flush is fast is the wrong fix.

**The HUD.** `coordinator.hud.dismiss()` runs at the top of `stopRecording`, so the HUD is already gone by the time this window opens. It has no stopping state to get wrong.

**`lastMenuState` and `titleState` collapsing into one field.** Tempting once the header follows the title, and it is a refactor with its own blast radius across every `rebuildMenu` caller. If route A makes the two identical in every path, say so in the ship note and let the owner decide whether the collapse is a separate row.

**Observed but not filed:** the flush window's real duration distribution is not in this spec because it is measurable and nobody has measured it. `state_change recording -> stopping` and the following transition to idle both appear in `events*.jsonl`, so a pickup that wants the number can have it. Remember event `ts` is UTC while stems are local.

## Acceptance

- During a stop, the menu header and the menu-bar title agree. A `StatusBarModel` test drives the chosen route's inputs and asserts the header string, and it fails against `main`, where the header for a stopping session is "MeetingPipe: Idle".
- No inert control is offered mid-flush. A test asserts `rows(_:)` for a stopping session contains no row whose action would hit `toggleManual`'s `.stopping` no-op. If route C is taken, the row is present and disabled, and the test asserts that instead.
- A controller-level test asserts `setStopping` hands `rebuildMenu` the state the chosen route requires, so the fix cannot be undone by a later caller passing `.idle` again. This is the regression that actually recurs: the current `.idle` was passed deliberately three times over.
- `headerLabel`'s `.stopping` branch is either reached in production or deleted. If it is kept and unreachable, the reason is written beside it.
- T3's body in `q6-final.md` is updated to say what shipped and when, replacing ARCH6's "live, unfixed" correction rather than sitting beside it.
