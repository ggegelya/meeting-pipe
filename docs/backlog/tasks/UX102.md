# UX102: Controls PRODUCT.md names miss its accessibility floor: the recording pulses, HUD pulse and panel fades ignore Reduce Motion, the prompt's workflow chip and the two-channel waveform have no accessible name or keyboard path, and the HUD meter keeps a live level after Mic lost

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: five low findings in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md): G042 and G041 (verified low, demoted from medium), F173, F174 and G059 (low, not verified by the audit). All five re-verified in code at HEAD `3a2da4fc` on 2026-11-14; corrections are noted inline. The [field evidence pack](../../audits/2026-11-13-field-evidence.md) has no log surface for any of them, so this is code-derived.

**The floor.** [PRODUCT.md](../../../PRODUCT.md)'s accessibility section says "The recording-dot opacity loop, the panel fade in/out, the Library row pulse, and the workflow tint transitions degrade to crossfades or instant transitions when reduced motion is on." Several surfaces already honour it: `MeetingPromptWindow` sets `ctx.duration = MPMotion.reduceMotion ? 0 : MPMotion.durBase`, `HUDFlagAcknowledgement.decide(count:reduceMotion:)` drops the flag animation, and `MPButtonStyle`, `MechanicalToggle`, `AskView` and `GuideView` read `accessibilityReduceMotion`. The ones below do not.

**G041, the Library pulses.** `LibraryToolbar.swift`'s private `PulseDot` and `LibraryChrome.swift`'s `MPSteadyPulseDot` (the row pill's dot) are free-running `TimelineView(.animation(minimumInterval: Self.frameInterval))` loops whose opacity is `0.5 + 0.5 * cos(phase * 2 * .pi)` and `0.675 + 0.325 * cos(...)` respectively; neither reads `accessibilityReduceMotion` or `MPMotion.reduceMotion`. `MPRingSpinner`, the processing pill's ring, is the same shape with `.rotationEffect(.degrees(360 * phase))`; PRODUCT.md does not name it, but it is the same continuous motion on the same row. [PERF26](./PERF26.md) (done 2026-11-12) capped their frame rates and left the motion itself alone.

**F173, the HUD.** `RecordingHUDWindow.present` calls `pulseDot?.startPulsing()`, which adds `RecordingHUDWindow.pulseAnimation()` (a `CABasicAnimation` on `opacity`, `anim.repeatCount = .infinity`) unconditionally. The panel fades in with `ctx.duration = MPMotion.durBase` and `dismiss(animated:)` fades out with `MPMotion.durFast + 0.03`, neither checking `MPMotion.reduceMotion`. Only the flag acknowledgement in this file reads the setting.

Correction at filing (F173): the audit's framing implies the prompt window already honours Reduce Motion for its fades. It does so only for its "Last time" button fade (`ctx.duration = MPMotion.reduceMotion ? 0 : MPMotion.durBase`) and its prep-card disclosure (`if MPMotion.reduceMotion { panel.setFrame(...) }`); `MeetingPromptWindow.show`'s own panel fade-in (`ctx.duration = MPMotion.durBase`) and `dismiss(animated:)`'s fade-out (`MPMotion.durFast + 0.03`) have the same gap as the HUD. PRODUCT.md's "panel fade in/out" covers both panels, so scope item 2 covers both.

**G042, the prompt's workflow chip.** `WorkflowChipView` is an `NSButton` with `title = ""` and `isBordered = false`; the workflow name is drawn by a private `titleLabel` (`NSTextField(labelWithString:)`) set in `workflowName`'s `didSet`, and the class sets no `setAccessibilityLabel`, `toolTip` or accessibility value. Its one call site, `MeetingPromptWindow`'s panel build plus `applyWorkflow(_:to:)`, sets only `workflowName`, `emoji` and `workflowColor`. The prompt's other controls carry tool tips ("Record this meeting", "More options", "Dismiss"), so VoiceOver reaches a nameless button exactly where the owner picks which workflow a meeting records under.

**G059, the waveform.** `AudioTab`'s `StaticWaveform` paints both channels and their "Mic" and "System" labels into a `Canvas`, and `WaveformBody` seeks only through `.gesture(DragGesture(minimumDistance: 0).onChanged { ... seekFromLocation(...) })`. There is no accessibility element, label, value or adjustable action on the stack, and no key handler; the tab's only keyboard control is Space for play and pause (`.keyboardShortcut(.space, modifiers: [])`). A VoiceOver or keyboard user can play from the start but cannot hear where the playhead is or move it.

**F174, the HUD meter after Mic lost.** `setMicCaptureLost(_:)` does `if on { levelMeter?.level = 0 }`, with the comment that "The recorder's level is frozen at its last value once the tap is abandoned". The 10 Hz ticker started by `startMeterTickerIfNeeded()` keeps running and writes `RecordingHUDWindow.normalizedLevel(db: provider())` every 100 ms, and `provider()` is `audioRecorder.currentMicLevelDb()`, the frozen `levelDb`. So within one tick the meter is lit again at the last level, beside a label saying the mic is gone. Nothing stops or gates the ticker on `micCaptureLost`.

Correction at filing (F174, off the record): the audit pairs `setOffTheRecord` with Mic lost, but with a live tap `MeetingRecorder.meterLevelDb(micDb:mode:verdict:offRecord:)` returns `-120` when `offRecord` is set, so the next ticks write zero anyway. The overwrite is real there only when the tap has stalled and `levelDb` is frozen, which is the case the setter's own comment names. The fix below covers both because it gates the ticker on the HUD's state rather than on the provider.

**F174, the elapsed clock.** The readout is built with `elapsed.textColor = MPColors.fg`. `setConfirmingEnd(_:)` sets `elapsedLabel?.textColor = on ? MPColors.fgSubtle : MPColors.fgMuted`, so when an END17 hold reverts to in-meeting (any live signal returning), the clock never returns to `fg` and reads muted for the rest of the recording. Verified as described.

**Related.** [UX27](./UX27.md) (P4) owns Tab and Space operability of the floating panels, which this task does not attempt; an accessible name on the chip is useful to VoiceOver whether or not the panel takes key focus. [ARCH16](./ARCH16.md) (P3) would rebuild both panels in SwiftUI. [UX73](./UX73.md) owns the flag acknowledgement's motion. [HYG17](./HYG17.md) touches `WorkflowChipView`'s colour helper.

## Scope

1. **Reduce Motion, Library.** Give `PulseDot`, `MPSteadyPulseDot` and `MPRingSpinner` a reduced-motion branch that draws a static indicator (the dot at full opacity with its aura at a fixed alpha; a still, partial ring) and no `TimelineView` at all, so the reduced path also stops the redraws. Read `@Environment(\.accessibilityReduceMotion)` as the rest of the SwiftUI chrome does, and put the envelope behind a small pure function (for example a `PulseEnvelope.opacity(at:reduceMotion:)`) so a test can pin it without rendering.
2. **Reduce Motion, HUD and prompt panels.** `RecordingHUDWindow.present` skips `startPulsing()` when `MPMotion.reduceMotion` is true and leaves the dot at full opacity. The present and dismiss fades of both `RecordingHUDWindow` and `MeetingPromptWindow` use a zero duration under the same check, copying the prompt's "Last time" fade line (`MPMotion.reduceMotion ? 0 : MPMotion.durBase`). Extract the decision as one static both panels call (the `HUDFlagAcknowledgement.decide(count:reduceMotion:)` precedent) so a test drives it.
3. **The chip's name.** In `WorkflowChipView`, set `setAccessibilityLabel` from `workflowName` in its `didSet` (so the " · NDA" suffix `applyWorkflow` adds is spoken too), a `setAccessibilityHelp` such as "Change workflow", and the same string as `toolTip`, matching the prompt's other controls.
4. **The waveform.** Give `WaveformBody` one accessibility element: label "Recording waveform, mic and system audio", value the playhead as `WaveformTimecode.format(currentTime)` of the duration, and `accessibilityAdjustableAction` stepping the playhead by a fixed interval (5 s proposed). Add left and right arrow key handling while the waveform has focus, through `playback.seek(to:)` and clamped to `0...durationSec`. The value must come from `PlayheadOverlay`'s observation, not by making `StaticWaveform` observe playback, which would undo the TECH-A13 redraw budget.
5. **The meter.** While `micCaptureLost` is true, or while off the record, the 10 Hz tick writes zero rather than `provider()` (or the ticker stops and `syncMeterToOcclusion`/`startMeterTickerIfNeeded` refuses to restart it in that state). `setOffTheRecord(false)` resumes live levels as today; `dismiss` already resets `micCaptureLost`.
6. **The clock.** `setConfirmingEnd(false)` restores `MPColors.fg`, the colour the readout is built with.

## Acceptance

- Tests (pure seams where a view cannot be driven headless):
  - the pulse envelope under reduce motion is a constant for every phase, and under normal motion still spans its current range (`PulseDot`, `MPSteadyPulseDot`), and the ring's rotation is constant under reduce motion;
  - the panel decision: reduce motion means no HUD pulse animation and zero fade durations for both the HUD and the prompt panel, normal motion keeps today's values;
  - `WorkflowChipView`: after `workflowName = "X · NDA"`, `accessibilityLabel()` is that string and `accessibilityHelp()` is set (extend `RenderedViewSmokeTests.test_workflowChip_builds_with_and_without_color` or add beside it);
  - the HUD meter: with a level provider returning a loud constant, the per-tick decision, extracted as a static beside `shouldMeterTick(occlusionVisible:hasProvider:)` (`RecordingHUDTests` drives statics, there is no injectable scheduler), writes zero for a loud provider while mic capture is lost and while off the record, and the provider's level otherwise; after `setOffTheRecord(false)` live levels resume;
  - the clock: `setConfirmingEnd(true)` then `setConfirmingEnd(false)` leaves the readout `MPColors.fg`;
  - the waveform: the adjustable action's increment and decrement move `currentTime` by the step and clamp at both ends (on a pure helper if the view cannot be hosted).
- Existing `RecordingHUDTests`, `AudioPlaybackControllerTests` and the PERF26 frame-cap tests stay green.
- `cd daemon && swift build` and `swift test` green with the new tests named in the commit body; `bash scripts/ci-local.sh` green (the design-token fences cover any new colour use).
- [docs/GUIDE.md](../../GUIDE.md): if a recipe describes seeking in the Audio tab, it gains the arrow-key seek in the same commit.
- Owner check after landing, by eye since the daemon UI is not screenshotable: with System Settings, Accessibility, Display, Reduce Motion on, the Library toolbar dot, a row's recording dot and the HUD dot are steady, and VoiceOver reads the prompt's chip by workflow name.
