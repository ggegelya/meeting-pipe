# UX87: Preferences is organized by subsystem, so the user's own name sits under Pipeline beside model ids and a chunking threshold

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([go-live assessment](../../audits/2026-10-21-go-live-assessment.md) UX-10). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Verified in code on 2026-10-24. `PreferencesItem` has eight panes (General, Recording, Prompt, Pipeline, Storage, Integrations, Permissions, Advanced), and its own doc comment names the IA as "per the Claude-Design handoff, refined in DSN1": one pane per subsystem. Counting `SettingsRow`, `SettingsStackRow` and `SettingsToggleRow` call sites gives about 80 rows before the four permission rows, close to the go-live assessment's 85. The heaviest panes are Pipeline (22 rows in 8 groups), Integrations (20 in 7) and Storage (17 in 6).

What a person comes to Preferences for is not where it is:

- **The user's own name.** `SettingsGroup("Your name")` (the `summarizationUserLabel` field plus the voiceprint **Reset**) lives in `PreferencesView+Pipeline`, between the Summarization group (engine picker, Anthropic model id, local model id, endpoint URL, active model, preload toggle) and the People roster. UX83 makes this the setting that decides whether the user's own voice is labelled at all.
- **People and speaker labels** are split: the roster is under Pipeline ▸ People, the separation knobs under Pipeline ▸ Speaker labels.
- **Privacy** is spread over three panes: regulated mode under Permissions, cloud-sync detection and **Move library…** under Storage, the MCP reachability rows under Integrations.
- **Destinations** (Notion, Obsidian, folder, LAN share, UX45) share the Integrations pane with API keys and MCP.
- **Engineering knobs sit at the same level as personal choices**: the chunking threshold under Pipeline ▸ Long meetings, "HuggingFace MLX repo id", "Local mlx_lm.server target", and the endpoint URL appear beside the engine picker.

The detection prompt's settings are their own pane (Prompt) while the detection timings they interact with are under Recording ▸ Detection.

## Scope

1. **Mockup first.** Update `design/ui_kits/macos_app/PreferencesWindow.jsx` to the proposed layout and get the owner's approval on it before Swift changes, the DSN17 precedent. The mockup's known-lag notes in the kit README are cleared for the panes it redraws.
2. **Group by what the user is doing.** Proposed, for the owner to amend: **General** (your name and voice profile, appearance, startup, sound, hotkeys), **Recording** (the prompt, stop conditions, microphone, detection, auto-record), **Summaries** (engine, prompt, languages, long meetings, digest), **People** (saved voices, speaker separation), **Destinations** (Notion, Obsidian, folder, network share), **Privacy** (permissions, regulated mode, cloud sync, MCP access), **Storage** (library, backups, retention, caches), **Advanced** (configuration, diagnostics, automation). API keys sit with the engine or destination that needs them.
3. **Engineering knobs behind a per-group disclosure.** Model ids, endpoint URL, preload, chunking threshold and similar rows move into an "Advanced" disclosure inside their group, collapsed by default, so the default view shows choices and the knobs stay one click away. No knob is removed.
4. **Move, do not rewrite.** Rows move between pane files as views; bindings, `ConfigStore` keys and behaviour are unchanged. `PreferencesItem` cases change, so every deep link into a pane (the `SetupChecklist.Fix` targets, the permission and Integrations deep links, the Library gear) is re-pointed in the same commit.
5. **Tour and docs in the same commit.** The Tutorial rings `vocabulary`, `speakerLabels` and `regulatedMode` inside Preferences; moving those rows updates `TutorialAnchor` and its fences per `daemon/CLAUDE.md`'s tour rule. README's Preferences reference, SETUP.md and GUIDE.md recipes that say "Preferences ▸ Pipeline" or "▸ Integrations" are rewritten to the new paths (DOC10, DOC11 contract).

## Explicitly not / out of scope

- Changing the words on rows: UX86. If UX86 lands first, use its vocabulary in the pane names; if not, pane names here are the plain ones above and UX86 adjusts row copy only.
- Replacing the Recording ▸ Output directory text field: UX89.
- Removing settings or whole features: FEAT18 decides keep, Experimental or delete per surface. This task moves what exists; a row FEAT18 removes is simply not moved.
- Asking for the name in onboarding: UX83.
- A search field in Preferences. Worth it only if the regrouped panes still fail the owner's eyeball.
