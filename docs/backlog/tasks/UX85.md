# UX85: pinning a transcription language only filters tokens by script, while Preferences, README and config.example.toml say it "skips detection" and that Auto-detect "chooses per meeting"

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([go-live assessment](../../audits/2026-10-21-go-live-assessment.md) FQ-11). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Verified on 2026-10-24 against the pinned FluidAudio 0.14.8 checkout:

- **What the pin does.** `FluidAudioRunner.transcribe` passes `language: Self.resolveLanguage(hint:)` to `AsrManager.transcribe`. Upstream's doc comment on that parameter: "Optional language hint for script-aware token filtering (v3 only). When set, top-K tokens that don't match the language's script are skipped in favor of matching candidates." `Documentation/ASR/TokenLanguageFilter.md` adds that the filter keeps "the highest-logit top-K candidate whose alphabet matches", with only two scripts, Latin and Cyrillic, and falls back to the unfiltered argmax when no candidate in the top-K matches.
- **What "Auto-detect" does.** Nothing. `resolveLanguage` returns nil for "auto", which disables the filter; Parakeet v3 has no language-detection step to skip. Its comment, "so the SDK detects language itself", is wrong the same way.
- **Consequences the copy hides.**
  - Within a script a pin does nothing distinguishing: `en`, `de`, `es`, `fr`, `it`, `pt` and `pl` all map to the Latin filter, so pinning German tells the model nothing English does not.
  - For a code-switched meeting a Cyrillic pin is a coercion. `uk` or `ru` explicitly rejects ASCII letters, so an English product or person name spoken in a Ukrainian meeting is replaced by any Cyrillic candidate in the top-K. The owner's meetings are English and Ukrainian, often in the same call. Likely but not measured here; [ASR4](./ASR4.md)'s code-switched subset can measure it.
- **The copy.** `PreferencesView+Pipeline.swift`, the Languages ▸ Transcription row: "On-device ASR (FluidAudio Parakeet TDT). Auto-detect chooses per meeting; a fixed code skips detection." `README.md`'s `transcription.language` bullet: "`\"auto\"` (default) detects per meeting; an ISO 639-1 code ... pins it and skips detection, which is the safer setting if your meetings are always in one language." `config.example.toml`: "lets the SDK detect the language per meeting; an ISO 639-1 code pins it and skips detection". The picker's first option is labelled "Auto-detect".

The summary side is not affected: summary language "Match transcript" reads the transcript's script (`pipeline/src/mp/summary_language.py`), not the sidecar's `language` field.

## Scope

1. **Say what it does.** Rewrite the Preferences sublabel, the README bullet, and the `config.example.toml` comment to describe a script preference: blank (default) lets the model write either script; a code makes it prefer that language's alphabet; for a Cyrillic language, English words in the same meeting can come out in Cyrillic. Plain words in the Preferences copy (no "FluidAudio Parakeet TDT", the [UX86](./UX86.md) class).
2. **Name the picker honestly.** The "Auto-detect" option becomes something like "Any (no preference)", and the per-language rows say they set the alphabet. Collapse nothing in the stored values: `auto` and the existing codes keep their meaning in `config.toml`.
3. **Fix the two code comments** that claim detection: `FluidAudioRunner.resolveLanguage` and the `TranscriptionRunner` protocol's `languageHint` doc.

## Explicitly not

- Adding language detection, or a per-meeting language. Neither exists in Parakeet v3 and this is a copy task.
- Removing the pin. It is useful when a meeting is wholly in one script and the model leaks the other one (upstream issue #512's shape).
- Reorganising the Preferences pane ([UX87](./UX87.md)) or vocabulary boosting's interaction with the pin ([ASR5](./ASR5.md) a priori item 3).
