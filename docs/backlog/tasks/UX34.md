# UX34: Fixed-size detection prompt: cap the Last time prep card, scroll inside

Band origin: filed 2026-07-29 (owner exploratory sweep, item 2: "clicking on it expands significantly the recorder prompt... the size of the prompt window should be fixed size"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The detection prompt panel is 600x64 (`MeetingPromptWindow.swift:60-62`), positioned top-centre with an 80pt top inset (:63, :384-392). The CAL2 "Last time" disclosure grows it: `toggleLastTime` (:535-575) computes `newHeight = Self.panelHeight + (isExpanded ? PrepCardView.height(for: card) : 0)` at :562 and animates `setFrame` keeping the top edge fixed (:563-565). There is no maximum, no clamp, and no scrolling anywhere in the panel: `PrepCardView` is a bare `NSView` of absolutely-positioned single-line labels (`PrepCardView.swift:89-202`, `maximumNumberOfLines = 1` at :212), pinned to an exact height constraint at :547.

The only bound is on content count, not height: `PrepCard.maxPoints = 3`, `maxActions = 3` (`PrepCard.swift:37-38`). A full card works out to ~196pt from `PrepCardView.layout`'s row metrics (:16-32, :47-74), so the panel jumps 64 to ~260pt, the 4x expansion the owner reported. At 260pt the panel bottom lands ~340pt from the screen top, over a meaningful slice of the meeting window it is supposed to sit above.

Two adjacent facts worth carrying into the fix. First, the card is built lazily once per prompt and then hidden/shown (:539, :560), so a scroll view added at the build site survives the toggle. Second, `prep_card_opened` is logged only inside the first-build branch (:550-555), so the event means "prompts where the card was opened at least once", not opens; fine as is, but worth a one-line comment so nobody reads it as an open counter.

## Scope

Cap the disclosure and scroll inside it:

- Add a `maxCardHeight` constant (pick visually; something near 120pt keeps the expanded panel under ~190pt total) and clamp the growth at :562 to `min(PrepCardView.height(for: card), maxCardHeight)`.
- Wrap `PrepCardView` in an `NSScrollView` at the build site (:539-548): documentView = the card, the card keeps its exact computed height as the document height, the scroll view gets the clamped constraint. Vertical elastic only, no visible scroller until needed.
- Lift the height decision into a small pure function (input: card, constants; output: panel height and whether it scrolls) so the clamp is unit-testable without AppKit, per the repo's decide-pattern.
- Add the one-line comment on `prep_card_opened`'s first-build semantics.

The collapsed state, the top-edge anchoring, and the reduce-motion branch (:566-573) stay exactly as they are.

## Explicitly not in scope

Redesigning the prep card's content or its 3+3 caps (CAL2's call, and CAL3 owns the series-keying question that decides whether the card's content is even the right one). Making the panel resizable by the user. Touching the prompt pill's own 600x64 geometry.

## Acceptance

Unit tests on the pure height decision: an empty card (zero height, button hidden per the existing collapse-to-zero behavior), a partial card below the cap (no scroll), a full 3+3 card (clamped, scrolls).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770). Repo dash guard green.

Owner eyeball: on a workflow with a full prep card, click Last time; the panel grows to the capped height only, the card scrolls to reveal the rest, collapse returns to 64pt, and the panel never covers the top third of the meeting window.
