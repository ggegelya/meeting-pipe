# STOR6: new installs put the library in iCloud-synced `~/Documents`, the welcome screen promises nothing leaves the Mac, and a library left in iCloud is read with no dataless or download handling

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([architecture review](../../audits/2026-10-24-architecture-review.md) M9, [go-live assessment](../../audits/2026-10-21-go-live-assessment.md) UX-5, PD-10, DI-11 and "Fix before anyone else installs it" item 9). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

**What SEC12 already did, and what it left.** SEC12 shipped on 2026-07-10 (`81dc71f`, "detect a cloud-synced library, warn, and offer a guarded move"; `0111c0b` bounded the ancestor walk). It added `CloudSyncDetector` (Swift) and `mp.cloudsync` (Python), a `mp doctor` WARN that is a FAIL marker under regulated mode or an NDA workflow (doctor still exits 0, owner's call), a Preferences ▸ Storage pill fed by `StorageStatsStore`, and `LibraryMover`, a guarded move that refuses while a recording or a job is live and refuses a synced destination. Its row in [q6-final.md](../q6-final.md) says "Visual eyeball owner-owed". SEC12 deliberately warns; it did not change the default, and nobody has moved the owner's library.

**The default still lands inside iCloud's reach.** Verified on 2026-10-24: `ConfigDefaults.outputDirPath = "~/Documents/Meetings/raw"`, `mp.config` `output_dir: Path = Field(default=_expand("~/Documents/Meetings/raw"))`, and `config.example.toml` `output_dir = "~/Documents/Meetings/raw"`, which `scripts/install.sh` copies to `~/.config/meeting-pipe/config.toml` on a fresh install. The filesystem sink defaults to `~/Documents/Meetings/published` in both `ConfigStore` and `config.py`. `Endpoints.Paths.recordingsRelative = "Documents/Meetings/raw"` is a fourth copy with no caller. On the owner's Mac `~/Documents` carries `com.apple.icloud.desktop`, and `ls -lO ~/Documents/Meetings/raw` shows six files already evicted by iCloud (`compressed,dataless`): the `.summary.md`, `.run.json` and `.filesystem.json` of `20260615-102553` and `20260616-201433`. A Documents-folder library also triggers the Documents TCC prompt on first write, which no setup doc mentions (DI-11).

**The welcome screen contradicts the defaults.** `OnboardingStepWelcome` shows "Meeting notes that never leave your Mac" and "Audio capture and transcription stay local; nothing is uploaded unless you configure a publish target." The default `[summarization] backend` is `"anthropic"` (`config.example.toml`, `ConfigStore`), so every transcript goes to Anthropic, and with iCloud Desktop & Documents on, the audio goes to Apple. README's "Your library may be uploading to iCloud" section opens "meeting-pipe keeps summarization on your Mac", which is false for the same default. The app already has the honest sentence: `PrivacyReach` builds the Permissions pane's callout from `RegulatedMode.effectiveBackend` and the configured sinks, "built from the same two predicates the pipeline enforces, rather than restated next to them".

**A library kept in iCloud is read as if it were local.** `grep -rn "ubiquitousItem\|NSFileCoordinator\|dataless\|startDownloadingUbiquitous"` over `daemon/`, `pipeline/` and `scripts/` returns nothing. Opening a dataless file makes the read block until the file provider has fetched it, so playback (`AudioPlaybackController`), transcription (`FluidAudioRunner.readMonoFloat32`), the Library scan, and `mp backup`'s `tarfile` walk can each stall on the network or fail offline, with no surface naming iCloud as the cause.

## Scope

1. **New-install default outside every synced root.** Change the library default to `~/Meetings/raw` and the filesystem sink default to `~/Meetings/published` in `ConfigDefaults`, `mp.config`, and `config.example.toml` together, and delete `Endpoints.Paths.recordingsRelative`. `~/Meetings` sits outside iCloud Desktop & Documents and outside the TCC-protected Documents folder, and stays visible in Finder (unlike `~/Library`). The pickup confirms the folder name with the owner before writing it; the location class (home root, not Documents, not Library) is the decision this task makes.
2. **Never move an existing library by changing a default.** An install whose `config.toml` already names `output_dir` keeps it (that is every current install, since `install.sh` seeds the key). For a config without the key whose old default directory exists and is non-empty, the first launch writes the old path into `config.toml` explicitly and logs `library_default_pinned`, so the library cannot appear to vanish. Existing iCloud libraries are moved only through `LibraryMover`, which already exists; the Storage pill keeps offering it.
3. **Honest welcome copy.** Replace the two `OnboardingStepWelcome` strings with ones derived from `PrivacyReach` for the configured backend and sinks (say plainly that the default engine sends transcripts to Anthropic), and name the library folder and whether it is synced, using `CloudSyncDetector`. Fix README's "keeps summarization on your Mac" sentence and the library paths in README, `docs/SETUP.md` and `docs/GUIDE.md` in the same commit.
4. **If the library stays in iCloud, check before heavy reads.** Before playback, transcription or re-transcription of a recording, read `URLResourceValues.ubiquitousItemDownloadingStatus`; when it is not `.current`, call `FileManager.startDownloadingUbiquitousItem(at:)`, show "Downloading from iCloud" on the row instead of blocking, and emit `icloud_download_wait`. In `mp backup`, report dataless files (`st_flags & SF_DATALESS`) in the summary line instead of silently materialising gigabytes. The Library scan's small sidecar reads stay as they are.

## Explicitly not

- Refusing to record into a synced root, or clamping file sinks under zero-egress. That is the privacy gate, SEC18 (architecture review S2); this task changes defaults and copy, SEC18 decides what a synced library is allowed to do.
- File coordination (`NSFileCoordinator`) for every write. The review notes atomic writes look like delete plus create to iCloud; with the default moved out, coordinating writes into a synced root is not worth its cost unless SEC18 keeps synced libraries allowed.
- UX89 (the Recording ▸ Output directory free-text field that can make the library appear to vanish). Item 2 here guards the default change only; UX89 owns the field.
- UX84's wider onboarding wiring (the default preset's Anthropic key is never asked). Item 3 changes the welcome step's two strings only.
