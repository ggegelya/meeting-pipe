# UX107: Finish setup and mp doctor are two reachability models that disagree in both directions

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source findings: G033 (quality, confirmed) and F180 (quality, low) in the [independent audit](../../audits/2026-11-12-independent-audit.md). Re-verified in code at HEAD `3a2da4fc` on 2026-11-13. No field instance is recorded; this is a latent defect on the setup path [DOC10](../q6-final.md)'s carve-out keeps in scope.

**The promise.** `SetupChecklist`'s doc comment says required-ness "mirrors doctor's reachability", `docs/GUIDE.md` says of the Finish setup row "When it is gone, you are set up", and `docs/SETUP.md` says that after configuring, Run doctor "should come up clean".

**The checklist misses real gaps.** `SetupChecklist.Item` has four cases: `permissions`, `anthropicKey`, `notion(needsToken:needsDatabase:)`, `localModel`. `cloudReachable` counts only `$0 == "anthropic" || $0 == "auto"`, so a workflow or global backend of `openai` with no key, or `claude_cli` with no `claude` binary, yields no item: the row disappears and every summary fails. `Coordinator.setupChecklistInputs` passes `notionDatabaseIdPresent: configStore.map { !$0.notionDatabaseId.isEmpty }`, the global id only, while a workflow's `.notion(databaseId:)` sink carries its own id (`Workflow.notionDatabaseID`, "empty string falls back to the global"). So a workflow with its own database and an empty global id shows a false "Choose a Notion database", and a workflow whose id is empty while the global one is also empty is caught only by accident of the global read.

**Doctor fails things nobody needs.** `doctor.check_secrets` declares `required = ("ANTHROPIC_API_KEY", "NOTION_TOKEN")` and prints `[FAIL]` for either missing whatever the backend and sinks; `main` then runs `check_anthropic(presence[...])` and `check_notion(presence[...], cfg)` outside regulated mode, each printing a second `[FAIL]` ("ANTHROPIC_API_KEY missing", "NOTION_TOKEN missing"). On Local MLX with a folder sink and regulated mode off, that is four FAIL lines under an empty checklist. `check_openai` and `check_claude_cli` already condition on `cfg.summarization.backend`, but only the global one, so a per-workflow `openai` or `claude_cli` pin is invisible to doctor too.

**F180, folded in.** `check_anthropic` posts to `ANTHROPIC_DOCTOR_PROBE_MODEL` (`"claude-haiku-4-5-20251001"` in `endpoints.py`) and on 200 prints an OK line ending "model access confirmed" without touching `summarization.model`, so a retired or mistyped configured model passes doctor ([PIPE28](./PIPE28.md) owns the model-id failure itself and already names this; this task only stops doctor claiming access it did not check). Correction at filing: F180 says doctor "validates no sink"; `check_notion` does validate the Notion token and the global database id. What it does not validate is a per-workflow Notion database id or any non-Notion sink (folder or Obsidian destination exists and is writable).

Related: [ARCH14](./ARCH14.md) (the backend as a String; records the missing OpenAI row as observed, not filed), [UX84](./UX84.md) (first-run steps do not feed each other), [UX86](./UX86.md) (doctor's raw output in a sheet), [UX92](./UX92.md) (a Finish setup item for a denied Notifications permission), [PIPE28](./PIPE28.md); UX22 and DOC10 are archived in [q6-final.md](../q6-final.md).

## Scope

1. **One reachability table, pinned as a cross-tree fixture.** A golden fixture (generated by `scripts/gen_contract_fixtures.py`, listed in `CONVENTIONS.md`'s cross-tree fixture table) that maps each backend id (`anthropic`, `auto`, `openai`, `claude_cli`, `local`, `apple_intelligence`) to the secret or binary it needs, and each sink type to its requirement (`notion`: token plus a database id, per workflow, falling back to global). Regulated mode empties the cloud rows. Python reads it in doctor; Swift asserts `SetupChecklist`'s rules against it in a test.
2. **Checklist.** Add `Item.openaiKey` and `Item.claudeBinary` (its fix opens the setup doc section that installs Claude Code; the presence check is a binary lookup the caller does off main, the same way `localModelMissing` is read). Make Notion's database check per workflow: `Inputs` carries, per workflow with a Notion sink, whether its effective database id (own, or the global fallback) is non-empty.
3. **Doctor.** `check_secrets` derives required secrets from the backends and sinks in use across workflows (read from the workflows directory the way `check_local_stack` already does) and prints `[ OK ]` or an `[INFO] not needed by any workflow` line otherwise; `check_anthropic` and `check_notion` skip their live probe with an INFO line when nothing uses them. `check_openai` and `check_claude_cli` consider per-workflow backends, not only the global one. `check_anthropic`'s OK line names the probe model and stops saying "model access confirmed" for the configured model.
4. **Sinks.** Doctor checks each per-workflow Notion database id it can reach, and that each folder or Obsidian destination exists and is writable, without writing a meeting.

## Explicitly not

- Making doctor exit non-zero on FAIL: it stays a diagnostic.
- The configured-model failure path at summarize time: [PIPE28](./PIPE28.md).
- Rewording doctor's output for non-programmers: [UX86](./UX86.md).

## Acceptance

- A table test on each side over the same combinations, at least: global anthropic with Notion; Local MLX with a folder sink; global openai with no key; a `claude_cli` workflow with no binary; a workflow with its own Notion database and an empty global id; regulated mode with a Notion sink. For each, the checklist's items and doctor's FAIL lines name the same gaps, and a fully configured case gives an empty checklist and zero FAIL lines.
- `SetupChecklistTests` gains the openai, claude binary and per-workflow Notion cases; `test_doctor.py` gains the Local MLX plus folder case with zero FAIL lines and the per-workflow `openai` case with one.
- `docs/GUIDE.md` (Finish setup) and `docs/SETUP.md` (Run doctor) updated in the same commit if the items or lines they name change.
- `cd daemon && swift test`, `cd pipeline && uv run --extra dev pytest -q`, ruff and pyright green, with the number of new tests in the commit body; `bash scripts/ci-local.sh` green.
