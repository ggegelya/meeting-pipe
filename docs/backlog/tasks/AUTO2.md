# AUTO2: Published-note transcript deeplinks (meetingpipe:// open at a timestamp)

Band origin: filed 2026-07-22 (owner feature ask, approved in the 2026-07-22 review session; P3 promote-on-demand by design: the in-app jump ships in FEAT10, this is the out-of-app half). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

**AUTO2 (P3, new): make the published [mm:ss] timestamps clickable from Obsidian / filesystem / LAN notes.** FEAT10 puts plain ` [12:34]` suffixes in published Markdown; this task turns them into `meetingpipe://open?stem=<stem>&t=<seconds>` links that open the Library at that meeting's Transcript tab at that moment. The scheme is shipped and hardware-verified (AUTO1, 2026-07-20, an `automation` `command` event with verb `open_library`): `AutomationCommand.parse` is the pure tested parser (Automation/AutomationCommand.swift:46) whose `library`/`open` verb already takes a scope, the router (`Coordinator+Automation.handleAutomation`) is the single gate, and `CFBundleURLTypes` is already registered by install.sh, so only new verb parsing lands in code. AskView already navigates from a citation to its stem (AskView.swift:12) and FEAT10 adds the pending-seek seam into TranscriptTab; this task is the URL spelling of those two existing moves.

Scope: parser support for `meetingpipe://open?stem=<percent-encoded stem>&t=<float seconds>` (t optional; a garbage t degrades to open-without-seek; bare `open`/`library` behavior unchanged), with cases in the AutomationCommand tests. Router: resolve the stem to a Library row (the AskView navigation precedent), select the Transcript tab, hand over the pending seek; an unknown stem (stale note, renamed recording) opens the Library quietly with no alert. Publishers: `render_summary_md` gains an optional deeplink mode (a stem parameter) rendering each timestamp as a `[12:34](meetingpipe://open?stem=...&t=754)` link, enabled for the Markdown-file sinks (publish_obsidian.py, publish_fs.py, publish_lan.py) and the stored `<stem>.summary.md`; Notion keeps plain-text timestamps (custom URL schemes are not reliably clickable in Notion rich text). The Swift mirror `AppleIntelligenceSummarizer.renderMarkdown` matches and the CI3 golden `summary-md-golden.json` gains a linked case.

Explicitly not: no Notion deeplinks (revisit only on evidence the scheme renders clickable there); no new UI for stale stems beyond the quiet no-match open; no install.sh changes (the scheme is already registered; a new verb is parse-side only). Depends on FEAT10 (the timestamps in notes and the pending-seek seam); promote to P2 once FEAT10 ships if the owner wants the out-of-app half next.

**Progress (2026-07-24): built; only the owner's click is left.** Promoted to P2 by the owner the day FEAT10 shipped, which is exactly the clause above. Both trees green (1691 Swift, 1032 Python; ruff, pyright, truth fences clean).

Parse and route: `AutomationCommand` gained `openMeeting(stem:seek:)` on the existing `open` / `library` branch, so a bare `open` and every `?scope=` still parse as before, `library?stem=` works too (the two are synonyms everywhere else and a silently-ignored stem on one of them is the kind of asymmetry nobody would guess), and a `t` that is missing, unparseable, negative, NaN, or infinite degrades to open-without-seek rather than to no navigation. The router does **not** resolve the stem: a citation click usually wakes a Library that has never scanned, and `MeetingStore` scans asynchronously from the window's `onAppear`, so "no such meeting" and "not scanned yet" look identical at that instant and collapsing them would send every valid link to the quiet no-match open. Instead `Coordinator+Automation` sets `LibraryWindowModel.pendingTranscriptJump` and shows the window; the pure `Automation/TranscriptDeeplink.resolve` answers `openMeeting` / `libraryOnly` / `wait` against the loaded list, `LibraryRootView` re-asks it on every store revision until it is decidable, and `MeetingDetailView` consumes the request (guarded on the stem, so a request meant for another meeting cannot seek in this one) into FEAT10's `pendingSeek` seam.

Render: `render_summary_md` gained an optional `deeplink_stem`, passed by the filesystem sink, the LAN sink, `summarize`'s stored `<stem>.summary.md`, and `publish-from-paste` (a no-op there today, since a pasted summary carries no anchors, but the two writers of that one file now spell it the same way). Notion is untouched and pinned untouched. Three spellings are contract rather than taste, all documented in CONVENTIONS: `t=` keeps millisecond precision with trailing zeros stripped, because `TranscriptSegmentLookup` picks the last segment starting at or before `t` and truncating an anchor snapped to a 754.32 s segment start would land the jump on the row *before* the cited one; the stem is percent-encoded down to the RFC 3986 unreserved set (Swift has to spell that set out in ASCII, since `CharacterSet.alphanumerics` would leave Cyrillic raw while Python encodes it); and the link syntax replaces the outer brackets rather than nesting inside them, because a leading `[[` is an Obsidian wikilink. The CI3 golden gained a `deeplink_stem` case (a stem with a space and Cyrillic, fractional anchors) and the Swift reader fails if that case ever disappears.

One thing the spec assumed was not true, and it is the important one: **the Obsidian sink never went through `render_summary_md`**. It renders its own user-templatable note, so FEAT10's plain ` [mm:ss]` suffixes had never appeared in an Obsidian note at all. Since Obsidian is the sink this task exists for (and the acceptance says a republished note carries the links), it now renders the shared `evidence_suffix` per section, which adds anchors *and* links to that sink in one step. A summary with no anchors still renders byte-identically, pinned by a test.

**Owner-owed:** the leg the acceptance reserves, click a `[mm:ss]` in a real Obsidian note on this Mac and land on the cited transcript row. Not exercisable here (Launch Services URL delivery is not drivable in this harness and the menu-bar app is not screenshotable). It needs one `./scripts/rebuild.sh`, since the new verb is code, not Info.plist, plus a republish of a meeting that actually has anchors, since existing notes carry the old plain suffixes until they are rewritten.

Acceptance: parse tests pin the happy path, percent-encoded stems, missing and malformed t, and no regression on the shipped verbs (the MeetingPipeAppIntentsTests vocabulary fence stays green). A router-level test pins known-stem to Transcript-tab-with-seek-pending and unknown-stem to Library-without-seek. A republished Obsidian note carries the links and the Notion output is unchanged, both fixture-pinned; CI3 golden regenerated; both suites and truth fences green. Owner-owed: click a link in a real Obsidian note on this Mac and land on the cited transcript row.
