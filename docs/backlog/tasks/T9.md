# T9: swift test appends thousands of lines to the real pipeline.log, because the Python child it spawns opens a hard-coded log path instead of MEETINGPIPE_LOGS_DIR

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([go-live assessment](../../audits/2026-10-21-go-live-assessment.md) QG-5). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The go-live run on 2026-10-21 saw both suites append about 8,000 synthetic lines to the real `~/Library/Logs/MeetingPipe/pipeline.log` and pytest leave a stale `mlx-server.json` there. Re-checked on 2026-10-24, after CI8 and DIST4 landed: 31,984 of the 32,181 lines in the dev Mac's `pipeline.log` read `synthetic frame`, the file was last written at 17:42 that day, and nothing in either change touched the cause.

**The finding is narrower than "both suites".** The two event-log writers really are isolated: Swift's `Log.resolveLogsDir` honours `MEETINGPIPE_LOGS_DIR` and the XCTest environment, and `PipelineLauncher` appends a child's stdout to `Log.logsDir/pipeline.log`, which is the redirected dir under test. The leak is two Python writers that never ask `events.logs_dir()`:

1. **`orchestrate._configure_logging`** builds `Path(os.path.expanduser("~/Library/Logs/MeetingPipe"))` itself and opens `pipeline.log` there. `FailureProcessTests` launches `daemon/Tests/MeetingPipeTests/Fixtures/failure-process.py` with `"MEETINGPIPE_LOGS_DIR": dir.path`; its `run-all` branch goes through `orchestrate.main`, which calls `_configure_logging()`, and the fixture's error carries `"synthetic frame\n" * 2000`. The child is not under pytest and the variable is ignored for the text log, so each `swift test` run with a pipeline venv adds about 2,000 lines to the user's log.
2. **`local_server.marker_path(home=None)`** resolves `Path.home() / "Library" / "Logs" / "MeetingPipe" / "mlx-server.json"`. `LocalSummaryClient._spawn()` calls `local_server.write_marker(...)` with no home, and `test_summarize_local.py`'s `_fake_spawn` drives `_spawn()` with a fake pid 4242, so pytest writes a marker into the real logs dir. `server_log_path()` beside it already routes through `events.logs_dir()`. `LocalServerReaper` checks the process's command line before signalling, so a stale marker is noise in `mp doctor`, not a kill risk.

Read-only users of the real path (`logs_cmd.LOGS_DIR`, `analyze_detection.DEFAULT_EVENTS_PATH`, `doctor._RECORDER_LOG`) do not write and are listed only so the fix is not over-scoped.

The docs say this class is closed. `CONVENTIONS.md`'s event-log section says both writers are isolated and "the trap is historical, not ongoing". That is true of `events.jsonl` and `pipeline_events.jsonl` and false of `pipeline.log` and `mlx-server.json`.

## Scope

1. `orchestrate._configure_logging` takes its directory from `events.logs_dir()`.
2. `local_server.marker_path` resolves `events.logs_dir() / MARKER_NAME` when `home` is `None`, keeping the `home` parameter its tests use.
3. A fence so the next bypass is caught by a test rather than by a log: a pytest that scans `pipeline/src/mp` for writes under the logs path (the `"Library/Logs"` literal and `"Logs" / "MeetingPipe"` path joins) and allows only `events.logs_dir` plus the named read-only sites, each with a reason.
4. `FailureProcessTests` also asserts that the child's `pipeline.log` landed in its temp `dir`, pinning the cross-process half end to end.
5. Correct the `CONVENTIONS.md` paragraph in the same commit: name `pipeline.log` and the marker, and say they were fixed here.

## Explicitly not / out of scope

- Cleaning the lines already written. Nothing rewrites a user's log; the owner can delete the `synthetic frame` block by hand. `mp.events.is_test_residue` filters JSONL rows only, and `pipeline.log` is free text.
- Removing the `sys.modules` pytest redirect from `events.py` and moving isolation into `conftest.py`: that is T6. Either order works; after both, isolation is the environment variable alone.
- The Swift logger's thread safety: PERF13's logger item.
- Making the daemon's job lane run `FailureProcessTests` in CI (it skips there without a venv): T7's skip gate decides that.

## Acceptance

- New pytest cases: with `MEETINGPIPE_LOGS_DIR` set to `tmp_path`, `_configure_logging()` (run in a subprocess, since it no-ops when the root logger already has handlers) creates `tmp_path/pipeline.log`; `marker_path()` equals `tmp_path/"mlx-server.json"`; the source fence in item 3 passes, and fails on a planted `expanduser("~/Library/Logs/MeetingPipe")` write (tried and reverted).
- `FailureProcessTests` asserts `dir/pipeline.log` exists after the run (it still skips without a venv).
- Session check, stated in the commit body: on the dev Mac, `grep -c "synthetic frame" ~/Library/Logs/MeetingPipe/pipeline.log` and the `mlx-server.json` mtime are unchanged across a full `swift test` and `pytest` run.
