# T14: pipeline CI is red on main because three workflow-overlay tests hard-code EDEADLK, while Linux's errno.errorcode names errno 35 EDEADLOCK

Band origin: filed 2026-11-12 from the dependency, platform and AI-model upgrade review (owner approved "File all proposed"); seen in passing while reading CI state. Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

The "Pipeline (pytest)" job of CI run 43189769485 (2026-11-12, head 0c327305) failed with exactly three tests, all in `pipeline/tests/test_workflow_overlay.py`:
- `test_an_unreadable_sidecar_emits_one_event_per_run`: `assert rows == [("pipeline", {..., "kind": "io", "errno": "EDEADLK"})]`;
- `test_the_io_log_line_says_could_not_be_read_not_malformed`: `assert "EDEADLK" in text`, against a log line that read `could not be read (EDEADLOCK: [Errno 35] Resource deadlock avoided)`;
- `test_read_meta_still_reads_an_unreadable_sidecar_as_empty`: `('unreadable', 'io', 'EDEADLOCK') == ('unreadable', 'io', 'EDEADLK')`.

**The production code is right.** `workflow.read_meta` names the error with `errno_mod.errorcode.get(e.errno, str(e.errno))`. On Linux, `EDEADLK` and `EDEADLOCK` are both 35, and `errno.errorcode[35]` is `"EDEADLOCK"`. On macOS, `EDEADLK` is 11 with no alias, so the tests pass locally.

The tests have expected the literal since they were added on 2026-10-26 (commit 4ef9da24, WF10).

**Why nobody noticed:** CI on main has been failure or cancelled on every run listed back to 2026-08-16. HYG12 owns that visibility gap.

## Scope

In those three tests, compare against `errno.errorcode[errno.EDEADLK]` instead of the literal `"EDEADLK"`.

Leave the production naming alone. The Swift reader `MeetingMetaRead` treats the sidecar read on its own and does not parse this name.
