# CI10: Swift has no linter or formatter, and every build warns about an undeclared CLAUDE.md inside the Core target

Band origin: filed 2026-10-25 from the 2026-10-25 code-quality audit band ([code-quality audit](../../audits/2026-10-25-code-quality-audit.md) SW13). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Re-checked on 2026-10-25 against `01e904a`, Swift 6.3.3, `swift-format` 6.3.0.

**The warning.** Every `swift build` of the daemon, clean or incremental, prints `warning: 'daemon': found 1 file(s) which are unhandled; explicitly declare them as resources or exclude from the target`. A clean scratch build names the file: `daemon/Sources/MeetingPipeCore/CLAUDE.md`, the island rules file the root `CLAUDE.md` tells agents to keep under that name. [`daemon/Package.swift`](../../../daemon/Package.swift)'s `MeetingPipeCore` target declares `resources: [.process("MicGate/Resources")]` and no `exclude:`, so SwiftPM sees a file it has no rule for. It is the only unhandled file: `Tests/MeetingPipeCoreTests/Fixtures/detection-corpus/README.md` sits under a processed resource directory. The line carries no source path, so [CI9](./CI9.md)'s planned gate (fail on a `warning:` whose path is under `daemon/Sources`) would not catch it either; it is permanent noise that trains a reader to skip the first lines of build output, which is where CI9's two real Swift 6 diagnostics also print.

**No linter or formatter.** There is no `.swiftlint.yml` or `.swift-format` anywhere in the repo, `ci-local.sh`'s `daemon` job builds and tests only, and the only lint artefact is a stale `// swiftlint:disable:next force_try` above the `try!` in `MeetingLibraryServiceTests.decodeAnswer`, naming a tool that is not installed or configured here. `swift-format` ships inside Xcode (`xcrun --find swift-format` resolves in `XcodeDefault.xctoolchain`), so a lint step needs no new dependency.

**Baseline, measured at filing** (`swift-format lint --recursive --parallel daemon/Sources`, 4.8 s wall). With swift-format's defaults (2-space indent, 100 columns) it reports 65,059 findings, 59,285 of them `Indentation`, because the repo indents with 4 spaces: the defaults are not a candidate. With 4-space indentation, line length unbounded and every rule switched on, it reports 6,762. Formatting rules dominate (`Indentation` 1,822, `AddLines` 1,186, `Spacing` 759, `NoEmptyLinesOpeningClosingBraces` 180, `TrailingComma` 74, `RemoveLine` 26), then documentation rules (`BeginDocumentationCommentWithOneLineSummary` 2,044, `AllPublicDeclarationsHaveDocumentation` 285, `ValidateDocumentationComments` 25). The remaining rules, the only ones that could catch code rather than layout: `DoNotUseSemicolons` 182, `UseEarlyExits` 23, `NeverForceUnwrap` 22, `OneVariableDeclarationPerLine` 17, `OneCasePerLine` 14, `NoAccessLevelOnExtensionDeclaration` 12, `OrderedImports` 11, `OmitExplicitReturns` 10, `NeverUseImplicitlyUnwrappedOptionals` 10, `UseWhereClausesInForLoops` 7, `UseSynthesizedInitializer` 4, `UseLetInEveryBoundCaseVariable` 4, `NoLeadingUnderscores` 4, `ReplaceForEachWithForLoop` 2, and one each of `OnlyOneTrailingClosureArgument`, `NoBlockComments`, `GroupNumericLiterals`, `AlwaysUseLowerCamelCase`. `NeverUseForceTry` finds 0. The audit read the force unwraps (about 25) and the 8 IUO members by hand and found every one safe.

## Scope

1. **The warning, now.** Add `exclude: ["CLAUDE.md"]` to the `MeetingPipeCore` target. A clean `swift build` prints no `unhandled` line. If CI9 has landed, its warning gate also fails on SwiftPM's `found N file(s) which are unhandled` line (one more pattern, the file has no path to filter on); if it has not, say so in CI9's spec so its gate picks the pattern up.
2. **The linter, as a measure-then-decide.** The owner decides; the session measures and proposes. Pre-registered bar, written before anyone reads the hits: a rule is adopted only if, on `daemon/Sources`, it has at least one hit that a hand read classifies as a real defect or as a breach of a rule `CONVENTIONS.md` or a `CLAUDE.md` already writes down. Hits that are only taste do not count. Formatting and documentation rules are excluded from the candidate set, because `swift-format lint` checks whole files and the first touch of any file would surface its layout debt. The session records, per candidate rule, the count and a one-line verdict with one example, in this spec's progress note, then asks.
3. **If the owner adopts a set:** a checked-in `daemon/.swift-format` enabling exactly those rules, the existing hits fixed in the same commit so the baseline is zero, and a `Daemon: swift-format lint` step in `ci-local.sh daemon` over `daemon/Sources` (whole tree, since it starts at zero; no changed-files diffing). `CONVENTIONS.md` names the step. **If none passes the bar, or the owner declines:** no config, and one line in `CONVENTIONS.md` recording that Swift is deliberately unlinted and why.
4. Either way, delete the stale `swiftlint` comment.
