# UX44: Vocabulary editor: sample row, de-jargon, fuzzy toggle, workflow cross-link

Band origin: filed 2026-07-29 (owner exploratory sweep, item 15: "I just realize it exists, but not sure what is the purpose", one day after FEAT11 shipped the editor; the owner wants the app usable non-technically). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The FEAT11 Vocabulary editor (Preferences, Pipeline pane, `VocabularyEditor.swift` over `GlossaryStore`) is structurally sound: scope picker, term rows, debounced TOML round-trip that preserves hand-edits and the `[fuzzy]` table, a footer that even names Re-transcribe as the way to fix an old meeting (:74-88, unusually good). What it lacks is a first-contact story, which is exactly what the owner hit:

- **"ASR" is used unexpanded, twice**: the footer's opening ("Fixes a term ASR keeps mangling", :81) and the empty state ("the spellings ASR keeps getting wrong", :105). The empty state also says "ticket prefixes", more jargon.
- **The footer is one six-line paragraph carrying five rules** (what it does, matching semantics, when it applies, how to fix an old meeting, scope layering). Accurate; unreadable as onboarding.
- **No example anywhere in-app.** "Add term" appends a fully blank row (:52); the worked pairs ("cube kernetes" to "Kubernetes", "post gres" to "PostgreSQL") exist only in `glossary.example.toml:20-24`, which no UI surfaces. The user must invent both sides of their first row from placeholder text alone.
- **`[fuzzy]` has no UI.** The near-miss second pass (rewrites any single token within `max_distance` Levenshtein edits of a canonical term; `glossary.py:91-93`, :107-128, defaults `enabled=false, max_distance=1` at :198-208) is documented only in the example file's comments. `GlossaryStore` deliberately preserves it blind (daemon/CLAUDE.md names it a live pipeline knob with no UI), and enabling it requires hand-editing `~/.config/meeting-pipe/glossary.toml`.
- **One entry point.** The editor is constructed only in the Pipeline pane (`PreferencesView+Pipeline.swift:14`). The workflow editor sheet never links its own per-workflow terms (zero references in `WorkflowsView.swift` / `WorkflowInspector.swift`); reaching them means leaving the workflow, opening Preferences, and re-selecting the workflow in the scope picker.

For the final report's plain-language framing (recorded here so the spec carries it): the Vocabulary fixes words the transcriber keeps getting wrong; you teach it "when you hear X, write Y"; new meetings pick it up automatically, old ones need Re-transcribe.

## Scope

- **Copy pass**: replace "ASR" with "the transcriber" (or "transcription") in footer and empty state; drop "ticket prefixes" for a concrete example; split the footer into a one-line lede above the rows ("Teach the transcriber the words it keeps getting wrong.") and a shorter footer holding the when-it-applies + Re-transcribe sentence, moving the matching-semantics detail to a `.help` tooltip on the rows.
- **Sample row for the empty state**: one greyed, non-persisted example row rendered where real rows go ("cube kernetes" to "Kubernetes", from the example file), disappearing on the first real row. It is display-only; nothing writes until the user adds a term (FEAT11's keep-it-a-pre-fill honesty rule).
- **Fuzzy toggle**: "Also catch near-misses (one letter off)" wired to `[fuzzy].enabled`. `GlossaryStore` extends its modeled surface to that one boolean while continuing to round-trip everything else blind (`max_distance` stays config-only; its default of 1 is the sane setting). The store's write path already rewrites only the tables it models; extending it to `[fuzzy]` must preserve unknown keys within that table (`max_distance`, anything future). The CI4 `glossary-golden.json` fixture pins the resolution merge, which this toggle does not change; confirm at pickup whether the fixture generator covers the fuzzy block and regenerate if the writer's shape does (the pipeline/CLAUDE.md rule).
- **Workflow cross-link**: a quiet "Vocabulary..." link in the workflow editor sheet (near the context prompt, which FEAT11 already treats as sibling context) that opens Preferences at the Pipeline pane with the Vocabulary scope preselected to that workflow. The deep-link seam is `PreferencesSelectionState` plus a scope hand-off; the SetupChecklist rows already deep-link into panes, so a routing precedent exists.

## Explicitly not in scope

The transcript-correction pre-fill ("Add to vocabulary" from an edited segment): FEAT12, filed the same day, owns it, including FEAT11's recorded complexity reasons. A fuzzy `max_distance` control. Import/export of term lists. Any change to `mp.glossary` matching semantics or the merge (pinned by the golden fixture).
