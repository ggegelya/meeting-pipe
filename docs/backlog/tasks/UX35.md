# UX35: HUD width parity between recording and off-the-record states

Band origin: filed 2026-07-29 (owner exploratory sweep, item 3: "Off the record mode looks too wide, while when it is disabled it is too narrow... make it same size"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The recording HUD has three hard-coded widths: `panelWidth = 76` for normal recording (`RecordingHUDWindow.swift:51`, with the sizing arithmetic in the comment at :48-50: dot 8 + gap 5 + "Recording" ~50 = 63pt plus margin), `offRecordPanelWidth = 150` for off-the-record (:59), and `degradedPanelWidth = 232` for the system-audio-degraded card (:56).

`setOffTheRecord(_:)` (:238-250) swaps the label text ("Recording" to "Off the record", :239), retints, flips the mic-slash glyph, and resizes the window per state at :248 via `resizePanelAnchoringTopRight`. Nothing measures the text: 150 is a literal, and "Off the record" at the 10pt label size needs ~76pt of text, so the off-record pill carries ~60pt of dead width while the normal pill is snug at 76.

Convergence is layout-safe: every element in `makeContentView` is either centred on the pill's centerX (glyph :379, dot row :387, meter :394, stop key :409) or pinned to both edges (elapsed :390-391, workflow label :399-400). Nothing anchors to an absolute x. The one width-sensitive element, the truncating workflow name (`HUDWorkflowLabel`, :617-624), only gains room.

## Scope

One shared width for the normal and off-the-record states, sized for the longer "Off the record" content (roughly 100-110pt; pick by eyeball against the real label), applied as a single constant. Delete the per-state resize between those two states at :248 (the degraded card's 232pt resize stays). The label swap, tint, glyph, and meter behavior are untouched.

Coordinate with UX46 (filed the same day), which adds a flag-moment button to the same pill: the shared width must fit the control row with three controls, so if both tasks are picked up, size once for the final control count rather than twice.

## Explicitly not in scope

The degraded-mode card width. Rewording the "Off the record" label to something shorter (it is MIC14's discoverability surface and the wording is load-bearing; the off-record feature also splits on workflow NDA mode, so the label must stay unambiguous). Any HUD redesign beyond the width.

## Acceptance

The two states share one width constant; no `resizePanelAnchoringTopRight` call fires on the off-record toggle (pin by unit test if the resize decision is lifted into a testable seam, else by code inspection at review plus the owner eyeball).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770). Repo dash guard green.

Owner eyeball: start a recording, toggle off the record and back; the pill does not change size in either direction, the label fits in both states, and the workflow name still truncates gracefully.

## Progress (shipped 2026-07-29, owner-owed on the eyeball)

Implemented in `daemon/Sources/MeetingPipe/RecordingHUDWindow.swift`. 1786 daemon tests green, 5 of them new, no pipeline change.

**The width is measured, not eyeballed, and the spec's estimate was high.** The spec asked for "roughly 100-110pt; pick by eyeball against the real label", which a headless session cannot do, so the number came off the layout instead. The pill's widest content is the dot row (`dot 8 + NSStackView spacing 5 + the state label`), and reproducing that row's constraints and asking for its `fittingSize` gives **64.0pt for "Recording" and 83.0pt for "Off the record"** at 10pt medium. The label alone measures 50.5 and 70.0pt intrinsic, so the spec's "~76pt of text" and the ToC row's "~89pt of content" were both about 6pt high. `pillWidth = 96` is 83 plus the same 12pt of side margin the old 76 gave the 64pt "Recording" row, rounded onto the 4pt grid. That lands just under the spec's 100-110 band, on a smaller true content width; the owner eyeball is the check on whether the resulting margin reads right.

**The resize decision was lifted into a seam, per the acceptance's preferred branch.** New `HUDPanelGeometry` in the same file, in the house pure-logic style (`daemon/CLAUDE.md`: explicit inputs, nothing read off AppKit inside), holding the four geometry constants and one `size(offRecord:degraded:) -> CGSize`. `offRecord` is a deliberate input that changes nothing, and `HUDPanelGeometryTests` asserts exactly that, so a reintroduced per-state width fails a test rather than needing to be caught at review. `setOffTheRecord` no longer calls `resizePanelAnchoringTopRight` at all; the degraded card is the only resize the HUD performs, and its 232pt width is untouched.

**A latent bug closed on the way.** `clearSystemAudioDegraded` resized to the recording-only 76 unconditionally, with no off-record branch, while `setOffTheRecord` skipped its resize whenever the banner was up. So going off the record, then having system audio degrade, then a successful retry, left the pill at 76 with "Off the record" (83pt of content) in it, clipped by the rounded mask. Both degraded call sites now route through `HUDPanelGeometry.size`, which returns the shared pill for either off-record value.

**Decisions not in the spec.** (1) Status is `owner-owed`, not `done`: the backlog's own rule is that eyeball work stays in the active backlog, and the eyeball is load-bearing here because the width came off a measurement rather than the eye the spec asked for. (2) `design/ui_kits/macos_app/RecordingHUD.jsx` had drifted to `width: 60` (the pre-DSN25 value) while calling itself a faithful recreation; its width is now 96 and its header names the shared-width rule. Its other drift is named there but not fixed: it models neither the off-the-record state nor the mic-slash toggle, and its `minHeight` is still 162 against the shipped 192. Those predate UX35 and are worth their own hygiene task.

**Not done, and deliberately.** UX46's flag button is not built. The shared width is sized for the current two-control row, and both `HUDPanelGeometry.pillWidth` and the `stop.centerXAnchor` offset carry comments naming UX46 as the place to resize.
