# T15: The WAV-deleting FLAC compress path has no test for its verification, ffmpeg or missing-output failure branches

Band origin: filed 2026-11-13 (audit band 2026-11-13, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Source: F114 in the [2026-11-12 independent audit](../../audits/2026-11-12-independent-audit.md) (lens data, outcome confirmed).

`AudioRetentionSweep` runs `AudioTranscoder.compressToFLAC(wav:)` for every meeting whose workflow's retention policy is `compress`. Re-read at HEAD on 2026-11-13, the function encodes to `<stem>.flac.writing`, moves it to `<stem>.flac`, reopens it with `AVAudioFile` and compares durations, and only then runs `try fm.removeItem(at: wav)`. Its own doc comment calls that ordering "the whole point": "Every failure path leaves the original WAV untouched, because the audio is irreplaceable". There are four such failure paths, and each one also has to clean up:

- `TranscodeError.ffmpegFailed(status)` on a non-zero exit, after `try? fm.removeItem(at: temp)`;
- `TranscodeError.outputMissing` when ffmpeg exits 0 and wrote nothing;
- a decode error rethrown from `duration(of: flac)` when the output does not open, after removing the FLAC;
- `TranscodeError.verificationFailed(wavSeconds:flacSeconds:)` when `abs(transcodedSeconds - sourceSeconds) <= durationToleranceSec` (0.05 s) fails, after removing the FLAC.

`daemon/Tests/MeetingPipeTests/AudioTranscoderTests.swift` has four tests: three happy-path ones (`test_compress_produces_a_smaller_flac_and_removes_the_wav`, the waveform re-derivation, the playback open) and `test_a_missing_source_leaves_no_flac_behind`. None of the four branches above appears in any test. The sweep's caller only counts `outcome.failed` and writes a `WARN: could not compress` line, so nothing outside the transcoder catches a regression either.

**The scenario the audit names.** A refactor drops the duration guard or widens `durationToleranceSec`. All four tests still pass, since they only ever feed a full-length encode. The next compress sweep keeps a truncated FLAC and removes the original WAV, which is the one irrecoverable outcome in the retention feature.

**The injection seam already exists.** `compressToFLAC` resolves its binary through `RecordingPostProcessor.findFFmpeg()`, which honours `MEETINGPIPE_FFMPEG` first (`ExecutableResolver.resolve(name: "ffmpeg", envOverride: "MEETINGPIPE_FFMPEG", ...)`). `RecordingPostProcessorTests` already uses it: its private `fakeFFmpeg(in:writing:)` writes a shell script that copies a given file to the last argument and exits 0, and the 2026-07-15 truncation test drives the merge with a 1 s WAV through it. `OrphanRecordingRecoveryTests` and `OrphanRecoveryREC24Tests` each carry their own private copy of the same helper, so there are three today.

**Correction at filing:** the audit names three untested branches (`verificationFailed`, `ffmpegFailed`, `outputMissing`); re-read at HEAD on 2026-11-13 there is a fourth that deletes the output and rethrows, the decode error from `duration(of: flac)`, and a fifth, a failed `moveItem(at: temp, to: flac)`, which is hard to provoke from a fake ffmpeg and is left to the four below.

Related: [DEP2](./DEP2.md) (new) replaces the ffmpeg encode with AVFoundation but keeps the duration verify; [CONC5](./CONC5.md) (new) adds only a timeout case to this suite; STOR1 (done, archived in [q6-final.md](../q6-final.md)) shipped the transcoder and claimed no failure-branch coverage.

## Scope

Tests only; no production change.

1. Lift the fake-ffmpeg script into a shared test helper (one file under `daemon/Tests/MeetingPipeTests/`, used by `RecordingPostProcessorTests`, `OrphanRecordingRecoveryTests`, `OrphanRecoveryREC24Tests` and the new tests), extended with an exit status and a "write nothing" mode, so the three copies become one instead of four.
2. Add the four failure-branch tests to `AudioTranscoderTests` (or a sibling class, since `setUpWithError` skips the whole class when no real ffmpeg is installed and these tests need none). Each sets `MEETINGPIPE_FFMPEG` to the fake for its own duration and unsets it in a `defer`.
3. Each test asserts the outcome, not the mechanism: the thrown error, the WAV still present with its original byte size, and neither `<stem>.flac` nor `<stem>.flac.writing` left in the directory.

**Keeping them valid across DEP2.** The assertions are about what survives on disk, so they stay true for any encoder. When DEP2 removes ffmpeg from this path, the fake no longer reaches the encode; DEP2 then has to carry these four scenarios over to whatever seam its native encoder exposes, and must not delete them as ffmpeg tests. Say so in a comment at the top of the new tests.

## Explicitly not

- Not DEP2's native port, and not CONC5's timeout case (a hung ffmpeg); both are filed.
- Not a change to `durationToleranceSec` or the verify itself; the code is right, it is unpinned.
- Not the sweep's reporting (`outcome.failed` with a log line and no event): observed, not filed here.
- Not the `try? fm.removeItem(at: flac)` before the move, which deletes an existing `<stem>.flac` sibling when a WAV and a FLAC coexist; observed, out of this task.

## Acceptance

- New tests in `AudioTranscoderTests` (or a sibling class), each with a fake ffmpeg via `MEETINGPIPE_FFMPEG`:
  - fake exits 1: throws `.ffmpegFailed(1)`, WAV intact, no `.flac`, no `.flac.writing`;
  - fake exits 0 and writes nothing: throws `.outputMissing`, WAV intact, no `.flac`;
  - fake writes a short but decodable file (a 1 s audio file for a 3 s WAV): throws `.verificationFailed` with both durations, WAV intact, no `.flac`;
  - fake writes bytes that do not decode: throws, WAV intact, no `.flac`, no `.flac.writing`.
- Each new test is shown to fail with its guard removed (for the verification case, with the `guard abs(...)` deleted), noted in the commit body.
- `RecordingPostProcessorTests`, `OrphanRecordingRecoveryTests` and `OrphanRecoveryREC24Tests` stay green on the shared helper, and no private `fakeFFmpeg` copy remains.
- `cd daemon && swift test` green with 4 new tests; `bash scripts/ci-local.sh daemon` green, and the new tests do not add a skip to `allowed_skips`.
