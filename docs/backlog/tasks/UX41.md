# UX41: Names changed since this summary: quiet cue + one-click re-summarize

Band origin: filed 2026-07-29 (owner exploratory sweep, item 11: after renames "summary might need re-generation... or instead maybe we can infer summary with new names without specific extra re-generation call. I am not 100% sure what is the best option"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The split is real and confirmed on both sides. Generation applies the speaker overlay and bakes the resolved names into the summary text: `summarize()` composes the overlaid transcript (`summarize.py:453-461`, via `transcript_corrections.overlaid_structured` and `speaker_overlay.apply_overlay`) and renders `**Name**:` lines the model reads, so bullets, attendees, and action owners carry whatever names existed at that moment. Display never re-resolves: `MeetingSummary` is a flat decodable with no overlay step, and no summary surface references `SpeakerLabelStore` (grep zero). The repo already states it in as many words: "summaries and transcripts keep whatever they were written with" (`RosterRename.swift:14-16`). Meanwhile the transcript, cast strip, and People rail all resolve at display time and update immediately after a rename.

So after the owner names voices (the exact 2026-07-27 session: seven voices named post-meeting), the transcript says Anisha while the summary still says THEM-3, and nothing says why.

Decision, taken as delegated between the owner's two options:

- **Not silent substitution.** Rewriting names inside generated prose is unreliable (inflected languages, the owner's library is half Ukrainian where names decline by case; possessives; partial matches) and it would falsify provenance: the summary claims to be what the model wrote. Rejected.
- **Not auto-regeneration.** It costs an engine call (cloud money or local minutes) per rename batch, and PIPE11 just made regeneration deliberate and queued. The owner owns the click. Rejected.
- **Yes: a quiet, truthful cue with the fix one click away.** The register precedent is the "Summary edited locally" caption (`MeetingDetailView+Header.swift:94-106`) and the FEAT11 nudge rule ("a nudge, not a feature: no new storage, nothing auto-filled").

The derivation has one trap, found while tracing: a naive `mtime(speaker_labels.json) > mtime(summary.json)` check is falsified by the in-place summary rewrites that do NOT regenerate (the action done/reopen toggle through `MeetingLibraryService.setActionResolved` and the correction editor's `persistEdit`, both re-serialize `summary.json`). The truthful timestamp is `<stem>.run.json`'s `ts`, written at summarize time (`corrections.py:78-87`) and kept truthful by PIPE11 even for standalone re-summarizes (`summarize.py:876-905`). `MeetingStore` already parses `run.json` for backend/model/publish_state (:514, :535) and already prefetches content-modification dates in its scan (:318), so the derivation costs no new I/O class.

## Scope

- Derive `namesChangedSinceSummary` in `MeetingStore`'s post-scan overlay step (the `hasCorrections` shape at :362-367): true when the speaker-labels overlay's mtime is later than `run.json`'s `ts`; false when either file is absent (no summary yet, or never renamed; conservative, no cue). Roster-wide renames route through the same overlay files (`RosterRename` writes per-meeting overlays), so they are covered by construction.
- Render the cue in the detail header's caption slot beside "Summary edited locally": "Speaker names changed after this summary." with an inline "Re-summarize" affordance that opens the existing `ReSummarizeMenu` (UX29's NDA honesty comes free; the cue must not offer a cloud path the clamp forbids).
- Surface parity per the UX28 rule (a chip that exists in one place only is the named failure mode): decide-and-record between header-only (quiet, recommended: the list row stays calm, renames are deliberate acts whose consequence you check in the detail) or header + a row dot. Recommendation recorded: header-only; revisit if the owner reports missing it.
- The cue clears itself by construction: a re-summarize rewrites `run.json.ts` (PIPE11), flipping the comparison.

## Explicitly not in scope

Any rewriting of summary text (rejected above, recorded so the pickup session does not re-litigate). Auto-regeneration or batch "re-summarize all renamed" (the batch pane already covers multi-select re-summarize). Transcript-correction staleness (text edits already re-summarize through their own flow; only names have this silent split). `mp ask` index staleness (the fingerprint already covers overlay files; verified at `embed_index.py:349`).

## Acceptance

Pure derivation tests: rename-after-summarize yields true; action done-toggle rewrite of `summary.json` after a rename still yields true (the trap case, pinned); re-summarize (newer `run.json.ts`) clears it; absent `run.json` or absent overlay yields false.

A header test pins the caption + affordance render when the flag is set, and that the affordance opens the re-summarize path gated by `ReSummarizeMenu` (an NDA meeting's cue leads to the local-only offering).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770). Repo dash guard green. No pipeline change expected; if `run.json` parsing gains the `ts` field in Swift, no fixture is involved (run.json is not a CI4-pinned surface; confirm at pickup).
