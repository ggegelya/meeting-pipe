# UX39: Cmd+Tab truthfulness: activation ordering, close handoff, count drift

Band origin: filed 2026-07-29 (owner exploratory sweep, item 9: "when I open library, it is always displayed at the end of command+tab menu... commandtab cannot switch to it immediately if I was commandtabbed from it"). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

The whole policy machine is 27 lines (`WindowActivationManager.swift`): `didShowWindow` increments a count and, on the first window, calls `NSApp.setActivationPolicy(.regular)` immediately followed by `NSApp.activate(ignoringOtherApps: true)` (:12-18); `didCloseWindow` decrements and drops to `.accessory` at zero (:21-26).

Three defects:

1. **The MRU-tail placement.** `setActivationPolicy(.regular)` is processed asynchronously by the system; an `activate` issued in the same run-loop turn applies against the pre-transition state, so the newly-regular app is appended to the app switcher's MRU list instead of being promoted to front. That is exactly "at the end of Cmd+Tab, and one Cmd+Tab cannot switch back". The call-site ordering compounds it: `LibraryWindow.show()` runs `makeKeyAndOrderFront`, then `activate`, then `didShowWindow` (which flips the policy and activates again) (`LibraryWindow.swift:48-51`, re-open path :15-22), so the window is fronted and activated while the app is still `.accessory`. Same shape in `PreferencesWindow.swift:63-66` and `DiagnosticsWindow.swift`.
2. **No close handoff.** `didCloseWindow` drops to `.accessory` with no re-activation of anything (:24), so closing the Library leaves focus nowhere in particular and the switcher's state stale.
3. **The count drifts on minimize.** `show()` guards on `!w.isVisible`, but `NSWindow.isVisible` is false for a miniaturized window, so minimize-then-reopen runs `didShowWindow` again; `windowWillClose` fires once, so `visibleCount` never returns to zero and the app is stuck `.regular` (Dock icon, Cmd+Tab slot) with no windows. Same hazard at `PreferencesWindow.swift:26-32` and `DiagnosticsWindow.swift:13-16`.

Adjacent: `NSApp.activate(ignoringOtherApps:)` is deprecated on the macOS 14 floor; twelve call sites across seven windows. The three handshake-skipping windows (Onboarding, Correction, QuickFind) are deliberate (panels/one-shots) and stay.

## Scope

- Reorder the open path: flip the policy to `.regular` FIRST, then defer `makeKeyAndOrderFront` + activation to the next run-loop turn (`DispatchQueue.main.async`) so the Dock transition has landed before the app claims frontmost. Encapsulate in `WindowActivationManager` (a `showWindow(_ window:)` that owns the whole dance) so the three handshake windows cannot re-diverge.
- Close handoff: when the count reaches zero, drop to `.accessory` and yield activation so focus lands on the next app rather than nowhere (the modern `NSApp.yieldActivation(to:)` family where available, else activate the next `NSWorkspace` frontmost candidate; record the chosen mechanism, it is the one genuinely fiddly part).
- Idempotent counting: track shown windows by identity (`Set<ObjectIdentifier>` or the window itself as the key) instead of a bare int, so a re-show of a live-but-miniaturized window deminiaturizes without double-counting; `show()` also learns to `deminiaturize` instead of re-running the open dance.
- Migrate the activation calls to the non-deprecated `NSApp.activate()` API in the same pass.

## Explicitly not in scope

The handshake-skipping panels (QuickFind, Onboarding, Correction) staying Dock-less is intentional. Dock-menu or Dock-icon features while `.regular`. Any change to which windows participate.

## Acceptance

`WindowActivationManager` becomes testable by identity: unit tests pin show/show-again-same-window (count 1), show-two-close-one (still `.regular`), close-all (drops), and the minimized re-show case (no double count). Policy flip and activation ordering are pinned by the manager owning the sequence (call-order recorded via an injected seam in tests).

`cd daemon && swift build` and `swift test` green (baseline at filing: 1770). Repo dash guard green.

Owner eyeball, the actual repro: open the Library, Cmd+Tab away, hold Cmd+Tab: MeetingPipe sits SECOND in the list (front of MRU behind the current app) and one Cmd+Tab returns to it. Minimize the Library, reopen it from the menu bar five times, close it once: the Dock icon disappears.
