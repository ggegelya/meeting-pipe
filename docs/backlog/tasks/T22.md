# T22: A plain swift test creates the corrections and waveform folders in the owner's real home, writes a peaks file into the real cache, and reads the real corrections corpus on every MeetingStore scan

Band origin: filed 2026-11-26 from the T9 amendment session (commit `d67e444a`), which saw `Library/Application Support/MeetingPipe/corrections` and `Library/Caches/MeetingPipe/waveforms` appear, as empty folders, in the throwaway home `ci-local.sh` now runs `swift test` under. Reproduced at filing (2026-11-26) with `env HOME=<tmp> CFFIXED_USER_HOME=<tmp> swift test --filter ...`: `MeetingPipeTests.MeetingStoreTests` (77 tests) left `Library/Application Support/MeetingPipe/corrections` and `MeetingPipeTests.AudioTranscoderTests` left `Library/Caches/MeetingPipe/waveforms`, both empty, while a filter matching no test left neither. Owner approved filing on 2026-11-25/26. Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

**Why ci-local does not show it.** Since T9's amendment `scripts/ci-local.sh` runs `swift test` with `HOME` and `CFFIXED_USER_HOME` on an empty sentinel and fails if `<sentinel>/Library/Logs/MeetingPipe` gains a file (`logs_sentinel_check` in `scripts/lib/logs-guard.sh`). That guard looks at the logs folder only, and at files only. A plain `cd daemon && swift test`, which root `CLAUDE.md`'s verify table and every pickup session run, resolves the real home.

**The two creators, read at HEAD `0f141418` on 2026-11-26.**

- `CorrectionStore.directory()` builds `home.appendingPathComponent(Endpoints.Paths.correctionsRelative, ...)` from `FileManager.default.homeDirectoryForCurrentUser` and calls `createDirectory(withIntermediateDirectories: true)`. `MeetingStore.performScan` calls it on every scan through `editedStemsOverlay()` (`guard let dir = try? CorrectionStore.directory()`), then `CorrectionStore.editedStems(directoryOverride: dir)` reads every record in it. So every test that runs a real `MeetingStore` scan (`MeetingStoreTests.scanOnce`, among others) creates the real folder and reads the owner's real corrections corpus; a real record for a stem a fixture also uses would put the "Summary edited locally" marker on the fixture's row. `CorrectionStore.readData(stem:)` without an override does the same. `CorrectionStoreTests` itself is clean: every `write` passes `directoryOverride: dir`.
- `WaveformPeaksLoader.cacheDirectory()` builds `Endpoints.Paths.cachesDir.appendingPathComponent("waveforms")` and creates it, on every `cachePath(for:)` / `cachePath(stem:)`. Direct test callers: `AudioPlaybackControllerTests.test_a_cancelled_peaks_compute_throws_and_caches_nothing` and `AudioTranscoderTests`, whose FLAC test calls `WaveformPeaksLoader.load(audioURL:)` twice on `20260101-120000.wav` and `.flac`, so it writes `20260101-120000.peaks` into the real cache and removes it only on its last line (not in a `defer`, so a throw between leaves it). Indirect: the retention sweep's drop, the delete cascade (`MeetingLibraryService`) and `StorageStatsStore` all reach `cacheDirectory()`.

**What was observed.** On 2026-11-26 the real `~/Library/Caches/MeetingPipe/waveforms` held only two real meetings' peaks (2026-10-16) and `~/Library/Application Support/MeetingPipe/corrections` was empty, so no test residue remains today; the folders themselves also exist because the installed app creates them, which is why the leak only shows under a sentinel home.

**The precedent.** `Log.resolveLogsDir` redirects to a temp directory when `Log.isRunningUnderTests`, and `LibraryDefaultPin.defaultHasEntries` answers false under XCTest "the way `Log` redirects its directory there". The app-private folders have no such redirect. `Endpoints.Paths` already resolves every folder from one `home`, and `EndpointsPathsTests` pins the relative literals separately from the home they resolve against.

## Scope

1. Under XCTest, resolve `Endpoints.Paths.appSupportDir` and `Endpoints.Paths.cachesDir` to a per-process temp directory (the `Log` precedent, keyed on `Log.isRunningUnderTests`), and make `CorrectionStore.directory()` derive from `appSupportDir` instead of spelling `home.appendingPathComponent(correctionsRelative)` itself. That covers both creators and every other `appSupportDir` / `cachesDir` reader (`AutoRetryStore.init`, `MuteRedactor.originalsDirectory`, `SearchIndexer.defaultIndexURL`, `MeetingDurationCache.defaultURL`, `LegacyConsentMigration`, `NotionDatabaseList`) at once. The alternative, an injected directory per site, is more seams for the same result; the pickup may still pick it if the redirect breaks a test that needs the real resolution.
2. `EndpointsPathsTests.test_the_folder_accessors_resolve_from_home` and `test_the_migrated_defaults_keep_their_paths` assert against the home the accessors resolve from; adjust them to assert the relative layout under whatever root the accessor returns, keeping the literal pins in `test_every_relative_path_keeps_its_literal` unchanged.
3. Widen the T9 sentinel check in `scripts/lib/logs-guard.sh` to fail on any entry, folder or file, under `<sentinel>/Library/Application Support/MeetingPipe` and `<sentinel>/Library/Caches/MeetingPipe` after each guarded suite, and pin it in `scripts/test-logs-guard.sh` both ways (a planted `mkdir` there turns it red; a clean run stays green).
4. Move `AudioTranscoderTests`' peaks cleanup into a `defer`, if the redirect does not make it moot.

## Explicitly not

- `Endpoints.Paths.configDir` (`~/.config/meeting-pipe`): config, secrets, roster and voiceprint readers under test are a separate question with its own risk (a redirect there changes what `ConfigStore()` loads); if the widened guard finds writes there too, file it rather than fold it in.
- The pipeline suite: T9 already pins `MEETINGPIPE_LOGS_DIR`, and pytest runs under the same sentinel; extending the widened check to the pytest run is in scope of item 3 only if it costs nothing.
- Deleting anything in the owner's real folders: the observed real folders hold only real data.

## Acceptance

- `bash scripts/ci-local.sh daemon` green with the widened check, which fails on the pre-fix code by naming `Library/Application Support/MeetingPipe/corrections` and `Library/Caches/MeetingPipe/waveforms` (shown red before the fix).
- `scripts/test-logs-guard.sh` gains the two cases in scope item 3 and stays green; it runs in the truth-fences job.
- A test that a `MeetingStore` scan under XCTest resolves the corrections directory outside `FileManager.default.homeDirectoryForCurrentUser`.
- `cd daemon && swift build` and `swift test` green, with the number of new tests in the commit body; `bash scripts/ci-local.sh` green.
