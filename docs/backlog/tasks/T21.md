# T21: Every FakeSessionHost is kept alive for the whole test run, which hides that controllers outlive their tests

Band origin: filed 2026-11-21 (second fix review, see [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md)). Status and priority live in this file's header; [INDEX.md](../INDEX.md) lists every task.

## Context

Found by the [second fix review](../../audits/2026-11-21-second-fix-review.md) (tests and observability report, M10), confirmed by reading the code at `8426758b`.

Commit `56d7a9df` (`fix(ci): keep every FakeSessionHost alive for the whole test run`) appends every fake to a static array in its initialiser (`Self.keepAlive.append(self)` in `daemon/Tests/MeetingPipeTests/FakeSessionHost.swift`). The reason is real: `MeetingSessionController` holds its host `unowned`, and a timer, a `Task` or an Accessibility build it started can fire after the test body ends, which trapped on a freed host.

The fix removes the trap and keeps the cause. Those timers and tasks now keep running against a stale fake until the test process exits. They can write rows into a later test's logs directory, tick shared singletons (`UILatency.shared`, `PermissionsCenter.shared`) and use CPU, and a later flake would show up as a wrong row in an unrelated test instead of a crash that names the culprit.

## Scope

1. Give `MeetingSessionController` (or the test support around it) a teardown that cancels what it started: its timers, its pending tasks and any in-flight Accessibility work.
2. Call it from the tests that build a controller, through one shared helper so a new test cannot forget it.
3. Remove the keep-alive array once the suite is green without it. If a remaining late callback is found, fix that callback's ownership instead of keeping the array.

## Explicitly not

- Changing the `unowned` host reference in production code, unless step 3 shows a production path with the same lifetime bug; that would be its own task.
- T13's shared driver fake and the unbounded wait loops, which are amended on [T13](./T13.md).

## Acceptance

- The keep-alive array is gone and `swift test` is green in three consecutive full runs.
- A test builds a controller, starts the work that used to outlive it (a dwell timer and a pending task), tears it down, frees the host, and observes no callback afterwards.
- A test that asserts an empty event log after a previous controller test passes when run in the same process.
- `swift test` green, 2 new tests.
