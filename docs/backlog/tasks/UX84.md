# UX84: the first-run steps do not feed each other, so a preset ignores the Notion step, the default engine's key is never asked in-app, and the test recording's outcome is never shown

Band origin: filed 2026-10-24 from the 2026-10-24 audit band ([go-live assessment](../../audits/2026-10-21-go-live-assessment.md) fix 6 / UX-3, DI-13, SA-7 onboarding half, UX-17). Status and priority live in this task's ToC row in [meetingpipe-q6-backlog.md](../meetingpipe-q6-backlog.md).

## Context

Verified in code on 2026-10-24. `OnboardingRootView` runs five steps in a `switch step` (Welcome, Permissions, Workflow, Publish target, Test), and no step reads what an earlier one decided.

**1. A preset never uses the Notion step that follows it.** `OnboardingStepWorkflow.presetWorkflow` builds every real preset with `sinks: [.filesystem]` and `isDefault: true`; Personal and Internal team pin `backend: .anthropic`, Client work pins `.local` with NDA on. The next screen, `OnboardingStepPublishTarget`, writes the Notion token to `SecretsStore` and the database to `ConfigStore.notionDatabaseId`, and nothing ever adds `.notion` to the workflow the previous step created. A user who picks Personal, pastes a token, picks a database and gets a green **Verify connection** publishes to a local folder only.

**2. "I'll set up later" leaves a Notion-only default.** `WorkflowMigrator.runIfNeeded` runs in `Coordinator` init, before onboarding, and seeds "General" with `sinks: [.notion(databaseId: legacyNotionDB)]`, which on a fresh install is an empty id. The "later" card deletes only what the step itself created, so General stays the default. With no token, `publish_router._build_one` returns an `UnavailablePublisher` for Notion, a Notion-only run exits 3 through `all_sinks_failed`, and every meeting lands in Needs you.

**3. The default engine's key is never asked in the app.** The shipped `config.example.toml` sets `backend = "anthropic"` and `sinks = ["notion"]` (DI-13: two external accounts, the Anthropic one prepaid), and the Personal and Internal team presets pin Anthropic. No onboarding step has an Anthropic key field. `install.sh` does prompt for `ANTHROPIC_API_KEY` on a TTY, so the from-source path asks once in Terminal, but the prompt is skippable and a drag-installed app (DIST1) has no Terminal step at all. Skipped, `summarize.py` fails on `require_env("ANTHROPIC_API_KEY")`. The menu bar's **Finish setup** row (`SetupChecklist`, UX22) lists the missing key afterwards, which is a repair, not a first run.

**4. The test step cannot show its own result.** `OnboardingStepTest` toggles a recording and counts down; its copy says "the transcript and summary appear in your Library". It has no view of the job it started, so a failure from item 2 or 3 is visible only later in the Library, and **Finish** closes the window (`onComplete` then `close()`).

**5. The window is hard to get back to.** `OnboardingWindowController.show` builds the window with `styleMask = [.titled, .fullSizeContentView]` (no close or minimize button) and deliberately skips the `WindowActivationManager` handshake ("first run happens once, before there is anything to Cmd+Tab between"). In an `LSUIElement` app that means no Dock icon and no Cmd+Tab entry, while the Permissions step sends the user to System Settings for two grants. Coming back is a hunt.

**6. The docs describe a different first run (UX-17).** SETUP.md Step 4 says the Welcome window "walks you through the four permissions", and never mentions the workflow or destination steps; Step 6 tells the user to set Notion in "the Welcome window's Where summaries go step" without saying a preset's destination ignores it; Step 7 says the Anthropic key goes in Preferences. `install.sh`'s closing text lists the four steps in the same terms.

## Scope

1. **One resolution of the first-run choices.** A pure `OnboardingOutcome.resolve(preset:notionReady:engine:)` (Core-style `decide()` idiom) returns the default workflow's sinks and backend. Notion is added to a non-NDA preset when the token and database are both set; an NDA preset never gets it. Applied whenever the user leaves the Publish target step and on Finish or Skip, through the existing `choice.createdID` upsert so WF9's no-duplicate rule holds.
2. **The migrator seed stops being Notion-only on a fresh install.** `WorkflowMigrator.runIfNeeded` seeds `.notion` only when a legacy `notion.database_id` exists, and `.filesystem` otherwise, so "I'll set up later" lands meetings on disk rather than in Needs you. Existing stores are untouched (the migrator already skips a non-empty store).
3. **An engine step, or an engine row on the workflow step.** It offers what the preset will use and asks for what that needs: an Anthropic key field bound to `SecretsStore.anthropicAPIKey` when the resolved engine is Anthropic, the existing UX21 local-model download note when it is on-device, and Claude CLI only when the binary resolves. Which engine is preselected is the owner's decision, recorded in the commit body (the go-live assessment proposes on-device first; FQ-12 says the local summarizer is below its own ship gate).
4. **The test step watches its job.** It reads the stem it started from the Library model the app already has and shows transcribing, summarizing, done, or the failure through the existing `FailureNotice` / `FailurePresentation`, with a fix link where one exists. **Finish** after a test opens the Library on that meeting.
5. **The window can be found and closed.** Add `.closable` (close behaves as Skip, so the gate cannot be stranded half-done) and take the `WindowActivationManager` handshake so the window has a Dock icon and a Cmd+Tab entry while it is open. The UX39 comment in `show()` is replaced with the reason.
6. **Docs in the same commit** (DOC10 and DOC11 contract): SETUP.md Steps 4, 6, 7 and 9 describe the five steps as they now behave, GUIDE.md if any recipe names these controls, and `install.sh`'s closing text.
