## How to pick up a task (delegation)

Mechanics are codified in `/tech-task <ID>` (read the task here, read the orientation docs, implement, verify, one commit on `main`, do not push). Soft context that command does not carry:

- Task ids carry no `TECH-` prefix (e.g. `/tech-task STOR1`). Historical code comments, ADRs, and commits keep the old `TECH-` form as provenance.
- **Full specs live one per task in [`tasks/<ID>.md`](./tasks/)**; items carried from Q4 unchanged keep theirs in [`q4-final.md`](./q4-final.md) (search the id), so each spec has a single owner.
- User locale: 99% English / Ukrainian. Do not default examples to German. Verify any new `uk` labels in `MuteLabels.toml` with the user.
- The user is vibe-coding: high-level explanations, does not read code. Lean on the ARCHITECTURE.md diagrams. Blind sub-pixel visual churn is out of bounds; visual changes need eyes, and the daemon is a menu-bar app that is not screenshotable here, so a rendered eyeball is owner-owed.
- No em-dashes in any output (CI fails on a U+2014 in any added line repo-wide, and on any U+2014 present at all under `daemon/Sources` / `daemon/Resources`; `scripts/pre-commit` blocks both at commit time when installed). Use hyphens, commas, or rewrite. Commit with the repo's git identity. Do not push without permission.
- Binding constraint (CLAUDE.md): the primary user is the author; selling is tertiary; technical excellence in core functionality comes first. The BRAND launch band stays deferred. The 2026-07 redesign band (DSN20-29 + WF6 + UX15) shipped in Q5; the only redesign residual is the owner-run `/design-sync` push, an outward sync tracked as an owner action, not a task.
- The AI/DV standing rule: every `AI*`/`DV*` capability and any new engine call must route through the local engine path so the `egress_guard` clamps it under regulated/NDA, honour `effective_backend()` (forced local under regulated/NDA), and add no new always-on egress.
- Owner walkthroughs (2026-07-30, owner request): every task gated on an owner action (an `owner-owed` status, a probe run, a decision, an eyeball) carries an `## Owner walkthrough` section at the end of its spec, steps tagged [owner] / [session] by who acts. When picking such a task up, follow that section step by step with the owner instead of re-deriving the procedure, and give new filings of that shape the same section.
- Acceptance bars never pin an absolute suite total (2026-08-04, HYG5): a figure like `baseline at filing: 1770` is true against exactly one base and stops being true the moment anything else lands, which during a parallel batch is immediately and repeatedly. The bar is the suite being green plus the number of tests the task adds (`swift test` green, 8 new tests), because both halves stay checkable against any base. Measure the baseline on your own branch rather than trusting a filed one, and record what you measured in the ship note, not back in the bar.
- The de-CLI standing rule (2026-07-10): the CLI is a debugging escape hatch, not a product surface. A task that ships a user-facing capability includes its UI affordance in the same task; a CLI-only ship is `partial`, not done. Exempt by class (owner-dev diagnostics): dogfood, analyze-detection, corrections-stats, train-adapter, spike harnesses. Rationale: the Q4 validation audit carried 13 tasks for the CLI-only-no-UI pattern, it recurred in Q5 (AI4), and unwritten goals lose to written personas in an AI-steered repo.

## Marking a task done

When a task ships done-done, move it to the running quarter archive [`q6-final.md`](./q6-final.md) in the same commit: its ToC row (Status `done`, a one-line ship note in the Comment) moves there, and the spec text from `tasks/<ID>.md` moves there prefixed `[DONE]` with that file deleted, so the active backlog stays lean, `tasks/` stays active-only, and the archive keeps the whole trail in one file (process change 2026-07-10; specs split to per-task files 2026-07-17). A partial ship stays here as `partial` with the remainder named in the Comment; owner-owed runtime or eyeball work stays here as `owner-owed`. `/tech-task` codifies the move.
