# Observability, error handling and logging audit, 2026-10-25

Scope (owner-commissioned): swallowed errors (`try?` on writes, `except Exception` and `pass`), silent fallbacks, event-log coverage of failures, user-facing error surfaces, and what cannot be diagnosed from the logs today. Base: `main` at `01e904a`. Nothing here is filed until the owner approves the list.

## Summary

**Verdict: the logging that exists is well built, but too many failures never reach it, and the most common failure-handling idiom in both trees is "an unreadable file is an empty file".**

What holds up: the event log has a documented schema and a CI fence on its categories; both JSONL writers are test-isolated and rotate the same way; every log file is 0600; the exit-3 publish contract, per-sink `sink_failed` events, recording-path capture health events, merge failures and model prefetch are all recorded properly; there is no reachable `fatalError` or `try!`, and no empty `catch {}`. About 230 of the daemon's 331 `try?` and about 150 of the pipeline's 176 `except` sites were classified benign (temp deletes, display-only reads, caches).

What does not:

1. **Unreadable means empty, then gets saved over.** At least 13 stores across both trees read a file they cannot parse or open as empty, and several then overwrite it on the next edit: roster, voiceprint, glossary, speaker labels, transcript corrections, saved searches, workflow corrections, consent. The same idiom on the meeting sidecar is a privacy fail-open: an unreadable or unwritten `<stem>.meta.json` drops a meeting's NDA routing in both trees.
2. **Failures outside the pipeline go to os.Logger, which redacts them.** 51 of 60 daemon warning and error sites have no file-log sibling, and os.Logger stores their interpolated reason as `<private>`. A failed config save, Keychain save, failure-sidecar write, workflow load or schedule install leaves nothing in `~/Library/Logs/MeetingPipe`.
3. **Degraded outcomes look like success.** An `auto` engine that dropped to local because the key was revoked, a language repair that failed, a speaker-cleanup reply that never parsed, a diarizer that threw, a long meeting skipped for a paste bundle, and a partial publish are each recorded as an ordinary success, or only as a WARNING line in a log file.
4. **Some questions cannot be answered from the logs at all:** which build ran; why the daemon restarted; why a recording stopped (user Stop or a confirmed end); which backend a run used and why; which mic captured the second half; whether a permission was revoked; whether the user was ever notified. No run id crosses the daemon/mp boundary, and `pipeline.log` uses zone-less local time while the JSONL uses UTC.
5. **User-facing surfaces miss whole classes.** A publish failure never reaches the menu's durable "failed" row, and a partial publish notifies "Meeting published". Scheduled backups and digests fail into log files nothing reads. Most non-pipeline failures are titled "Processing could not finish" whatever failed.

## Method

Five parallel read-only finders (Swift swallowed errors; Python swallowed errors; silent fallbacks and cross-tree contracts; logging infrastructure and diagnosability against the owner's real logs on this Mac; user-facing error surfaces), each told to classify rather than count. 69 raw findings. Every high went to an independent skeptic told to refute it in code and in the logs, plus seven medium spot-checks: 16 verified, **0 refuted, 8 downgraded** (six highs to medium, two mediums to low), and four were found partly covered by existing tasks (SEC23, UX82 and DIST6, PERF13, DET10). Three highs survived: the meta-sidecar fail-open (PY-1), the empty sink list that publishes to Notion (FB-2), and publish failures missing from the menu (UI-2). Duplicates across angles were merged into the task shapes below.

## What this audit could not see

The owner's main library and logs on the work laptop (all NDA, multi-sink, auto-fallback and scheduled-job reachability rests on code reading); write-failure branches (disk full, EACCES), which cannot be exercised read-only; TCC-gated paths (a denied `~/Documents`, revoked permissions, notification authorization, Focus suppression); rendered notifications, HUD and menu (the menu-bar app cannot be screenshotted); crash-then-recover sequences; info-level os_log and anything before 2026-10-18 (not persisted). The installed app on this Mac is a 2026-09-11 build, so runtime evidence predates UX80 and every 2026-10-24 landing. The pipeline suite ran green apart from one SIGINT test that hangs when the runner starts with SIGINT ignored (an artifact of the background launch; it passes alone).
